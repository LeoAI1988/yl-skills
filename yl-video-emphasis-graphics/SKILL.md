# 视频重点标注图解

已有视频可以直接进入。读取实际显示区域、时长、时间基、镜头和讲解对象，有可用字幕或文稿时复用。无口播素材按画面事件定位，如光标点击、物体变化、操作结果。与其他技能组合时，由调用方提供剪辑后的时间轴、保留的标题和字幕区域，本技能负责图解选点、设计、渲染与验收。单独调用同样可以交付叠好图解的新视频。只做方案或记录反馈时按要求交付对应范围。

## 从观众需要看懂的关系出发

通读或观看整段，在最终时间轴上标出容易错过的变化。每处写清楚“此时说了什么或发生了什么、让观众看懂哪层关系、用什么图形来表达”。两档价格用并列数值，倍数增长用分步乘式，操作演示用目标位置和结果标注，跨角色协作用节点与箭头。按原话或画面出现顺序揭示信息，保留数字、单位和所指对象。需要比较时让上一项留在画面，给观众看清差别的时间。

启用后按全部成片时间排点，通常每 **7～10 秒**出现一项新的实质图解。第一项距片头最多 10 秒，相邻两项和末项到片尾的间隔均不超过 10 秒。语义需要可以更密。短于 7 秒的作品也可在最有意义的画面放一处。持续显示的一张图可以分步增加新条件、数值或因果边，每次新增实质信息可以单独计点。字幕换页、重复亮起、纯装饰动画以及片头标题均不计入。轻重变化靠短标注与完整关系图交替完成，过长间隔优先拆解已有关系。用户限定了局部区间时，在选定区域的局部时间轴检查，然后映回全片；用户明确指定不同节奏时采用该值。个人配置 `video.emphasis_style_file` 可提供 `cadenceSeconds` 及字体、进退场、羽化黑底参数。

## 依画幅重排同一组信息

| 画幅 | 对数值、流程与对象的安排 |
| --- | --- |
| 横屏 | 先在人物视线侧或较大空白侧划出可用区。三档数值可横向并列，流程箭头沿阅读方向增长。板书、鼠标、手势正在指的对象预留空间，标题出现期间错开时段或侧别。 |
| 竖屏 | 先量顶部标题、脸部与下方字幕、底部及侧边平台控件。两档对比可上下对齐，多步因果可纵向展开或分步换页。保留单位和上一步参照，短标签在手机尺寸仍可辨认。 |

同一内容转横竖两版时沿用语义锚点，分别重排节点、换行、箭头、字号与羽化范围。将各画幅的实际像素坐标写入各自的 spec，视线或对象移动时抽看整个时段。两侧都拥挤可换到无遮挡镜头、使用局部放大或让图解短时独占展示画面。已选[字幕标题版式](../yl-video-text-layout/SKILL.md)时交换占用框与时段；独立使用则从现有画面量取。

先画出起点、终点和观众眼睛要走的路线。因果在高而窄的空白区上下拉开，在宽而矮的空白区左右展开。为箭杆和箭头单独留一段可见距离，字块放在线路之外。逢替换，固定接收端，让旧对象退出、新对象入位；逢汇聚，先留下各个来源，再把支线接到共同终点。相邻段的动作由关系决定。同一对象跨句延续时沿用位置，使观众认得出它。参考片有多种表达时，要取样其运动中段，按[动效选择与小屏验收](references/emphasis-motion.md#从参考动作选图形)编排整条。

## 生成和合成

采用重点图解形式时，全片口播字幕同步采用黑底白字样式。将字幕生成在时间轴上，每句使用独立的紧贴字宽的黑色直角底条，白色常规字重，居中排在画面底部安全区。按原稿已有语言出字幕；已有双语时中文在上、较小的译文在下，两行分别衬底。已有普通口播字幕层时先替换该层；只有烧录字幕的素材先查同版无字底片，避免叠出双字幕。无口播时无需生成字幕。

读取个人图解预设的 `textColor`、`backdrop` 和 `caption`。把统一字色传给规格顶层的 `diagramTextColor`，使图解内的小标题、编号、关键词和结论都用同一字色。独立视频标题另取标题配色。将同一份 `backdrop` 传给图解规格。圆形羽化底板读取 `circleAlpha`，缺省沿用 `alpha`。两者都表示黑底中心不透明度。要求背景更透时降低圆底不透明度，保持文字、线条和字幕底条原有对比。用同一张实景帧并排比较旧值与新值，观察中心纹理、文字可读性和圆缘过渡，再在最亮背景复核。字幕换句时底条与文字同步切换。自定义渲染脚本也须执行同一套规则。

1. 在原帧上为每组预留图形区域。横屏、竖屏、方形分别测量，避开人物、原字幕、板书、光标、演示结果与阅读区域。有字幕已烤入的视频直接把字幕作为避让区。选用当前画面合适的布局，可接收其他版式技能给出的可用区域。
2. 按 [参考动效与规格](references/emphasis-motion.md) 编排文字、线、节点和独立羽化遮罩。在 spec 的 `anchors` 列表逐项填写 `componentIndex` 及 `meaning`。下标从 0 开始，选本步首先出现并承载新信息的组件，时间直接取该组件的 `startFrame`。例如两档价格的第二档开始揭示时，以第二档的数值组件为锚点。单条口号配黑底不足以说明对比或因果。审核原句、图解内容与显示时机，再检查间隔。
3. [透明图层渲染器](scripts/render-emphasis-overlays.py) 依赖 Python 3 与 Pillow。`--spec emphasis.json --check-cadence` 报告首段、相邻锚点、末段和超限区间。有箭头的作品设置实际播放宽度，执行 `--spec emphasis.json --check-motion` 查看每根箭杆、笔画与箭头头部在小屏上的像素数。再用 `--spec emphasis.json --out-dir render` 生成带时间轴的 RGBA 状态图、manifest 和 FFconcat。可选的 `--base-manifest` 用于已有文字层。新工程的 `cadenceSeconds` 取本次目标区间，例如 `[7, 10]`。调序、裁切或改速后重新定位。
4. 独立交付时，将透明轨按原始显示画布和匹配的时间戳叠回视频，复用原音轨；无音轨作品保持静音。FFmpeg 可用 concat demuxer 加载透明轨并以 overlay 合成，或让现有编辑器读取 manifest。按底片时长收尾，检查最后一帧与末尾音频。可变帧率素材先从原 PTS 映射到叠加时间轴。用户只要图层时直接交付 manifest 及其依赖。
5. 将整张成片缩至目标播放宽度，按正常速度看每组进场、中段、落点和退场。核对连接方向、参照对象、字线净距、停留时间及人物或板书遮挡。用实帧检查第一条因果边及最挤的一次替换，再通查其余各组。首尾与全片间距按新信息第一次可见的时刻复核。
