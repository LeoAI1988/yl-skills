# 长视频文案逻辑重构

先读完整原稿，再决定哪句话值得观众停下来、后文如何一层层兑现这句话。这个成员负责段落之间的顺序和取舍。原顺序已经成立时可以全部沿用。判断依据是论述有没有跨段依赖，以及用户是否需要重构，分钟数不能替代这个判断。

## 建立源稿

- 读取本轮原始录音或完整逐字稿、已认可的版本与需要保留的句子。按[个人配置约定](../yl-toolbox/references/profile.md)定位作者已有作品、复盘和表达资产。冻结了开头、正文或局部红线的，以本轮最新明确指令为准。
- 为每个源分配稳定标识。读到全文结尾，记录各段说话者、原句、它回答的问题、上文指代、观点变化和所依赖的画面。只给了文字时使用段号和原句首尾作为锚点即可交稿。要执行原声重剪时，须将锚点匹配到同版源媒体的绝对起止，核对重复出现的句子。
- 原始转写与校对分开保存。识别疑点回到原录音或画面。本人亲历、比喻、数字和结论按作者说法入稿；除用户明确要求核查外，不因外部争议软化原话、删掉传播支点或添加防御性限定。原话中的否定、归属、时间顺序、立场反转及有意义的重复须保全。

## 从开头推到结尾

1. **选开头。** 用户已选定的历史有效开头先锁定，保留实际原句、重音和所需上下文。有可用历史数据时，找同账号同类作品的实际成片开头和表现，优先用与本次目标相符的指标和原句。记清依据是用户已确认、已查到的数据，还是本次判断。缺少记录时从本片最有力量的原句入手，不能杜撰成绩。
2. **找出观众下一句最想听什么。** 从这个开头列出它留下的问题，沿原稿找能接住它的经历、利益、代价、对比、反问、转折或具体结果。给每一段写出“上一句提出什么，这一段增加什么”。连续两步把同一个利益推高时，要把二者之间的悬念与第二次兑现一起保留。递进看似重复时比较信息和情绪的增量。背景可以后移到读者正需要解释的位置。
3. **核对连接和收束。** 以作者的原话连续顺读。调序会改变“这、还有、后来、当时我以为”的所指时，可从源里带回必要前句或换一个剪点。删掉重复铺垫、跑题和已失去对象的指代；保留作者有意的回扣、想象力、口语力道和最后想落到的判断。不能靠字幕或新造连接词修补原声断裂。
4. **多条分别成线。** 单条也可独立重构。用户要多条时，先做全批分题，分配各条的问题、主要例证、开头与落点。相同证据的必要复用写清原因；批次差异、区间重叠和多轮交付由[多主题精剪](../yl-long-video-multi-topic-editor/SKILL.md)统筹。

## 交付到下一步

交付可读的原始全文、标出删除和调序的全文、按目标播放顺序拼接的完整逐字稿，以及精简的段落映射。已有同版原稿直接引用。映射至少含作品、播放顺序、稳定源位置、完整保留原话与段落作用；已知倍速只作为下游参数。文字稿阶段的时长预估和原声核实状态单独写明。重排后从映射重建顺读稿，检查逐字一致、每句话能回源、承诺得到兑现。可执行映射见[虚构交接示例](references/handoff.example.json)。

只要文案就交到这里。需要实际剪原声时，将批准顺读稿与段落映射交给[口播基础](../yl-remotion-talking-head-editor/SKILL.md)或本轮宿主。宿主保留真实源时间基，依据源 PTS 核实每处音节、气口和起止，再冻结唯一成片时间线。半自动在本轮约定处等稿件确认；用户已授权开始剪时直接执行。仅改字幕、标题、图解或声音时，沿用已定文案与时间线。

单独调用时无需视频编辑器。组合调用时先重构，再由宿主执行一次剪辑和倍速；现有切片、课程与访谈工程沿用各自工具和文件格式。
