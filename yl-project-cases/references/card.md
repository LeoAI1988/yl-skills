# 项目案例卡格式

位置为项目区 `案例/<分类>/<id>.md`。文件名与 ID 对应，分类与目录对应。卡片 frontmatter 每个字段独占一行，值用双引号字符串或 JSON 字符串数组，以保留 Obsidian 兼容性。以下是用于说明字段的示意数据。

```markdown
---
id: "sample-project"
title: "示例项目"
category: "示例分类"
tags: ["技术标签", "场景"]
uses: ["复用场景"]
status: "部分验证"
updated: "2026-01-01"
threads: []
sources: ["/path/to/project/record.md"]
---

# 示例项目

## 任务

任务目标、当时条件和验收标准。

## 过程与关键取舍

有实际影响的决定、失败点和回退方式。

## 结果与边界

已验证结果、核验方式和尚未验证的条件。

## 什么时候复用

标出触发场景、必要输入、可复用做法及例外。

## 证据与回源

关键结论各自的材料、定位提示和可见范围。
```

- `id` 是稳定英文小写 kebab-case 标识。标题、标签可以随实际用途修订。
- `threads` 保存已知的聊天 UUID。没有可追溯线程时可为空。
- `sources` 保存本地证据的绝对路径，使用正斜杠。只知道外部证据时正文保留 URL 和可见范围。证据不足时明确在正文与状态中记录。
- 核对笔记、截图、交付、检查结果各自确实支持的结论。可补正文双链或 Markdown 链接，脚本验证 `sources` 字段中的本地路径存在性。 
- `search` 每个空白分隔的搜索词都要命中标题、字段或正文，可配合 `--category` 限定。报告链接带绝对路径，读回正文后再引用。 `index` 从当前卡片生成 Markdown 并输出；需要发布到本机导航时可沿用用户指定的位置。
