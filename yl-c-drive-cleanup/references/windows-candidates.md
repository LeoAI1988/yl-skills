# C盘候选判定

所有目录从当前机器的环境变量、配置、扫描和实际应用安装位置取得。`%LOCALAPPDATA%`、`%APPDATA%`、`%TEMP%`、`%USERPROFILE%`是定位线索，不是整目录删除范围。

| 类别 | 可以清理的依据 | 必须保留或单独判断 |
|---|---|---|
| npm `_cacache` | 已确认为下载缓存，没有安装/下载任务 | npm配置、全局包、项目依赖及共享包仓库 |
| npm `_npx` | 逐分支确认无运行/预览/服务依赖的临时解包包 | 当前进程引用的分支，以及本轮明确排除的分支；清理会影响用绝对路径调用的工具，需查使用方式 |
| Remotion/Webpack缓存 | 对应渲染与预览结束，确认无其他任务共享此缓存 | `node_modules`、浏览器、字体、模型、活动工程和依赖 |
| 视频抽帧/代理/临时音轨 | 内容确实可从仍在的原视频重新生成，无后续任务使用 | 唯一原视频、正式音视频和逐字稿；不要把同目录所有媒体一并删掉 |
| PPT/网页渲染目录 | 确认是可再生预览，原稿、正式PPT/PDF及源资产已保留 | HTML、图片素材可能是唯一来源或可编辑成果；“render”目录名不构成证明 |
| 应用 `*-updater`/更新缓存 | 用户明确不要对应更新包，或已确认卸载的选中应用残留；枚举内容为安装包/更新元数据 | `pending`可能尚未安装，不能一律标为过期；仍需更新的应用不因同屏出现就一起清理；有后台更新占用先跳过 |
| 旧插件安装暂存/staging | 当前正式运行组件完整，暂存不再被安装或进程引用 | 当前插件运行组件、正在安装的暂存目录、凭据和配置 |
| `modify_backup`等修改备份 | 当前完整SHA-256证实与保留的正式文件一致，或本批成果已确认且原件齐全 | 目录名不是去重证据；未逐项核验的备份不整批删除，不创建新的保险备份 |
| 旧应用/旧运行时 | 用户指定且确认不再使用，核实无当前引用，分目录处理 | 同一旧目录下的data、配置、会话和用户文档；不把“旧程序”扩大为整目录可删 |
| Chrome/桌面应用缓存 | 精确识别Cache、Code Cache或GPUCache，应用不再使用该范围 | Cookie、IndexedDB、Local Storage、会话、浏览资料及登录状态；缓存可能自动重建 |
| Windows Temp/更新下载 | 只处理可访问、已确认不活动的具体内容 | 权限拒绝、占用和维护状态不明的项；不改权限、不清系统组件目录或自行调用系统维护工具 |

## 不按大小直接清理

- 分页/休眠文件、Windows组件、已安装应用组件与共享DLL。
- Codex或其他Agent的会话、历史SQLite、索引业务状态；它们不是普通缓存。
- 微信、企业微信、邮件、笔记数据、聊天附件与账户目录。
- Python/Node运行时、模型、字体及浏览器安装；`.cache`可能混有这些共享组件。
- 用户需要的正式源码、PPTX、母带、文稿、封面和说明，即使位于“工程”目录。

## 本次实践沉淀的判断

- 圈选四行只代表四行；列表其余软件和截图正文不构成扩大授权。
- 用户明确“已卸载，这些不要”后，不再拿旧注册表版本或旧pending信息阻挡已授权的更新包清理；仍检查真实文件和当前占用。
- 当前哈希匹配可以支持删除字节重复备份，但不是所有历史修改备份的通行证；已删除副本在后续报告中标为已清。
- 0.000 GiB可能是空目录，也可能是四舍五入、访问失败或链接；读取实际目录后分别报告，不将它算成大体积释放。
- 没有同口径前次快照时，只报告本次现存占用和真实清理结果，不把文件创建量称为净膨胀。
