# 视频号运营工作台

Node.js 22+、Python 3.10+；官方连接的凭据保护目前要求 Windows。安装完整 YL 集群后，将本目录的 `workbench-config.example.json` 复制到核心之外，填写 workspace（独立工作目录的绝对路径）、expectedAccount（必须核对的视频号名）、python（解释器）、products（商品显示名称）和 tags。不要把密钥写进此 JSON。

个人 profile 的 `publishing.channels.config_file` 指向这份配置，也可显式启动：

```text
node workbench/server.mjs --config /absolute/path/channels.json
```

打开 http://127.0.0.1:8713 。共享核心只存代码；工作目录保存清单、发布回执、采集证据及复盘产物。启动不提交发布或采集任务。

## 四个页面

- 发布工作台：按固定时间槽拖动整条视频，商品、标签及设置随视频移动；快速播放预览；起止小时 06–22、分钟 10 分钟步进。标签默认全选，可取消和添加。
- 选片后读取浏览器可识别的媒体时长，显示原创处理说明；不足 5 秒自动将本轮原创设置为不声明，并保留原请求与原因。时长读取失败不猜测，执行时以平台提示核对。修改默认原创选项会同步更新每条提示。
- 发布记录：保存每轮清单、逐条平台 ID 与实际核验时间。未知回执不能当作成功，不自动补发。
- 数据跟踪：本工作台发布和平台历史作品统一按平台字符串 ID 查看，含隐藏作品；每条显示真实采集时刻、空缺指标和历史快照，支持导出。
- 复盘大屏：复用 yl-channels-analytics 的排行和十四章大屏；日历包含全部已采集作品，效果榜使用公开且成熟作品。缺日期不补零，全店订单不分摊为视频归因。

## 默认流程：保存清单后在 WorkBuddy 启动

完成选片与设置后，点击“保存并交给 WorkBuddy”。工作台验证并保存本轮清单，弹出含准确文件路径和批次编号的启动指令；点击“复制启动指令”，粘贴到 WorkBuddy 新对话中发送。此流程使用 WorkBuddy 已有的视频号连接，不依赖开放平台应用审核或网页 OAuth。

在 WorkBuddy 中重新读取当前版 Skill，直接打开视频号助手查看已有登录态；需要时由用户扫码，然后核对账号。此流程不调用 `/api/publish`，也不以 `/api/runtime` 的授权字段为前置条件。网页 API 返回 503 只说明网页直连不能执行，不证明当前 WorkBuddy 的浏览器路径不可用。只有用户发送明确发布指令后才执行，单纯保存清单不自动发布。

每条的顺序、时间、商品和其他设置以保存的清单为准。执行前核对账号、实际模型和平台已有作品，避免重复发布；时间已过或素材缺失时停止，不自动改时间。保存后记录仍为待发布，必须取得实际平台回执才能标为成功。

## 可选流程：网页直连 WorkBuddy

在工作台连接设置填写已创建的开放平台应用信息并完成官方 OAuth。密钥通过 Windows DPAPI 加密保存在个人配置目录，不进入发行包或页面状态响应。默认回调为 `http://127.0.0.1:8713/auth/workbuddy/callback`，须与应用设置一致；是否允许回环地址、PKCE 及所需权限以官方应用实际验收为准。

“网页直连设置（可选）”保留配置与授权入口；只有连接、账号和模型核验全部通过后才显示“网页直连发布”。未授权不影响默认的清单交接流程；已有直连任务或正在提交时锁定主入口，避免重复发表。配置保存后输入框清空，提示已加密保存，无需重复填写。官方应用需先审核生效；审核状态以开放平台为准，不把授权错误单独当作审核状态证据，也不承诺审核通过就一定能连接。

WorkBuddy 桌面本地助理必须在线，并具有视频号连接。完成账号和实际模型检查后，网页才允许启动任务，不需要另发一轮对话。官方本地助理 API 当前未提供逐任务模型切换参数；顶部 Space Bunny（默认）、GLM 5.3 Flash、DeepSeek v4.1 Flash 是待核对的要求，必须与助理实际配置一致。思考强度要求极致、上下文模型默认，不声称 API 已设置。

按按钮开始只读采集或确认本批发布；15 秒轮询仅追踪已经提交的任务，不自动发起新采集。每次新采集按 [采集合同](../workbench/scripts/capture-contract.md) 入库。结果不明保持任务锁；先核对 WorkBuddy 实际情况，再明确解除锁，不因断网重发。

## 历史迁移及验收

历史数据格式各不相同；可在工作目录的 analytics-config.json 中配置外置 `importer` 脚本适配旧证据。默认导入器只接受符合采集合同的不可变批次，空安装显示未采集，不携带作者数据。迁入旧记录须保留来源、平台 ID、原采集时间；不能按标题相似度合并。

发布包已做离线行为验证；真实应用 OAuth、实际视频号采集和发布必须在安装者环境分别验收。没有有效后台 ID、对应商品/时间、核验时间和截图，不标为发布成功。界面显示的最近数据是最近成功采集时刻的数据，不承诺后台实时推送。

新版直连发布回执分别记录 `at`（计划时间）和 `actualAt`（目标作品列表实际日期时间），格式均为 `YYYY-MM-DD HH:mm`。新任务缺少实际时间或两者不一致时保持待处理与任务锁，不自动重发；旧任务按原版本保留历史事实。发布记录明细分别展示两种时间、实际原创状态与异常说明；缺失数据明确待核验。手动 WorkBuddy 对话的总结不会自动变成已核验回执，也不能把无平台 ID 的日志冒充实测数据。
