# 复盘大屏与验收

续作沿用用户认可的主题、章节和表格；数据、结论及证据状态必须随当前输入重新生成。没有上一版的新安装使用本包生成器，不依赖作者历史项目。

## 输入与生成

`scripts/dashboard.py --input /work/review.json --output /work/review.html` 用纯标准库生成独立 HTML 和统计 JSON；CSS、JS 随包提供。评分调用同级 `yl-media/scripts/ranking.py`，不复制算法。账号、路径、产品、标题、订单、模板偏好在外部输入；原始证据不变，输出新版本。

规范化 JSON 合同见 [dashboard-schema.md](dashboard-schema.md)。采集适配器负责来源字段、单位、账号与发布 ID 核验。生成器不联网，不把读取历史快照说成本次重采。

## 版式

默认保留 14 章：总览、三段对比、播放分布与涨粉效率、每日发布与播放、视频指标与漏斗、总播放排行、完播与三秒、选题库、开头库、标题库、分产品成交、小店成交与客户明细、结论与实验、数据范围与待补内容。沿用具体项目的历史小节编号仅是该项目显示设置，不作为其他安装者的硬规则。

深色主题沿用 `scripts/dashboard.css`。桌面六列 KPI，小屏折行；宽表横向滚动。浮层靠右、正文独立滚动，不加遮罩；当前标题高亮，Esc 和关闭按钮可关闭。所有标题用事件委托绑定。

## 统计规则

- 视频与图文分型。图文保留在总播放排行，视频完播、三秒、均观看、时长、涨粉效率、综合评分及其均值、百分位、漏斗的分子分母均不纳入图文；不适用值为空，不得填 0。
- 账号累计与区间样本各自标注范围。爆款阈值由输入设置，卡片、清单、结论采用同一值；不同门槛须明确另命名。
- 成熟度是最低观察门槛，不等于不同发布日的累计数据可直接证明趋势或因果。
- 日历轴生成区间内每个自然日，完整覆盖范围内的未发布日期补 0；采集缺口不得伪装为 0。按用户设定决定成熟期外作品是否展示，并明示。
- 零发布不能只在数据数组里补齐：逐日格明确显示 0，汇总有发布／零发布／采集缺口天数，附完整零发布日期与逐日明细。最后一个自然日仅观察至采集时刻，不提前判整天停更。
- 所有比率从同组分子分母计算。均观看、爆款份额、商品占比、金额、条数、结论中的数字不得写死。金额统一两位小数。
- 按 product_id 分产品统计已付订单、金额、已归因订单、金额、成交视频数、爆款贡献；优惠价不改变商品归组。未知商品归因单列，不用成交均价猜商品。
- 客单价不同的产品分别分析成交机制。订单数占比与金额占比同时说明；“已归因成交视频都是爆款”不能推广为“全店订单都来自爆款”。私域单列后只合计一次。
- 产品和来源汇总分别展示订单数占比与已付金额占比，分母均为同范围全部已付；无订单或金额为零时不伪造 100%。爆款产能与播放分布配比例条，关键数值有颜色强调并保留可读文字。
- 选题先阅读全文，按主要内容价值建立粒度一致、可复用的类别，如实操实践、工具认知与测评、行业动态、协作方法。具体工具或案例名不自动成为独立类别；缺全文暂列待归类，分类依据留内部。每条作品独立一行显示名次、标题、综合分、完播率、万播放涨粉和涨粉数，类内按综合分降序，分类数和条数动态计算。
- 需要验证成交窗口时，内部保存跨期对照及各核验路径的状态；大屏只展示业务对比与必要的归因缺口提示。点击增长、成交不变是观察证据，单独不能证明固定窗口；保留项目采用结论、官方口径和未知长度，不能把历史对照包装为新接口验证。

## 逐字稿与开头

- 显示链接和稿件字典都以 publication_id 为键；标题只作显示。多次发布共稿须有正文或用户确认证据，保留分别的发布 ID。
- 每个显示的标题均有 matched / missing / not_applicable 记录。未装载、未匹配、未找到媒体、图文不适用不能混写成“本来没有”。遍历全量标题验收，不能只处理几个榜单。
- 优先校订稿，同时保留原始 ASR；校订状态、来源文件、哈希和匹配证据只保留在内部，不放进大屏或全文卡片。清理 Markdown 标记不得删除引用或列表中的口播原句。
- 起始时间小于 5 秒的整段不等于精确前 5 秒。内部保留完整分段及起止；大屏只显示“约 N 秒”，无时间依据显示时长待确认，不编造秒数。开头库删除稿件状态，所有标题点击一律展示全文而非开头摘录。
- 缺口优先查发布 ID、资产侧车、正式原稿与合法媒体；有媒体可补转写，无媒体保留具体缺口，不编造文字。

## 客户信息

仅在用户需要客户级明细且已授权时纳入。展示字段由个人配置决定；联系方式在生成 HTML 前脱敏，完整值不得藏在页面脚本、属性或隐藏表格里。可另交付完整 Excel，标明内部用途。姓名、地址等按当次授权处理；默认只做汇总。完整订单原件留外部受限工作目录，不进入 Skill、公共包或通用索引。

内置生成器地址只展示规范化省、市，不嵌入详细地址；缺失显示未获取，不从电话或姓名推断。不同成交来源使用稳定的颜色标签，未知来源用中性色并保留文字；Excel 可按授权保留完整原始字段。

## 验收

1. 验证分型、样本边界、唯一 ID、缺失值、每章合计、两套订单表一致、商品组金额与总金额一致。
2. 用当前输入重算关键结论；检查阈值、分母、时间与数据源，排除旧文案数字。
3. 全量检查标题对应记录与来源路径；开头时间边界不得虚标精确。
4. 扫描 HTML 不含完整联系方式，核对 Excel 的完整值与原件一致；不得把公式起始的客户文本写成公式。
5. 在宿主允许的预览工具里检查桌面与窄屏、表格、弹窗切换、关闭与滚动。截图、结构检查、现场交互分别记录；渲染受阻时如实写未验证，不用旧截图冒充。

## 业务展示原则

- 每表按主题明确主指标，整列数值标红，包括阶段单条均播放、播放排行、完播排行、三秒排行及开头库。辅助指标保持次要层级。
- 产品身份使用稳定的不同颜色，产品名称和订单金额一致；优惠价沿用原商品颜色。此规则优先于金额一律标红。成交来源另用带文字的颜色标签，不混淆两个维度。
- 每日成交使用日期横轴、金额纵轴的三条折线：两个指定产品及全部成交总额。按真实付款日期统计；未取得付款日期时明确说明采用的替代时间。连续日期、真实无成交补零、缺失断线；总额包含其他产品时直接说明。不要用累计金额替代每日金额。
- 大屏不显示工程内容：接口、路径、发布 ID、哈希、匹配证据、商品对应证据、连接错误、脚本版本、测试和执行日志。内部原件及核验记录完整保留，不向全文卡片序列化这些字段。
- 视频归因表旁保留：后期部分成交未归因到对应视频，表内订单及金额只是已归因部分，不代表全部成交。不能把此业务限制随工程说明一起删除。
