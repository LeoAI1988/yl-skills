# 批注、版本与手改真源

## 先定位，再编辑

批注字段中的页脚数字可能是元素 ID，不能当页码。预览器 slide id 也未必等于 PPTX 的 OOXML ID。联合匹配：文件、页面标题、元素名称/ID、文本、坐标、图片内容；至少有充分证据落到唯一对象。无法唯一定位才询问，其他明确修改继续做。

维护简单改动表：批注标识／实际页序及稳定页标识／元素／原值／目标／版本范围／验收。具体要求逐字照做。删除形状后也检查相邻装饰是否悬空；删除一条说明不意味着删掉整组。

只改几个字、位置或颜色时优先直接修改当前 PPTX 的实际对象。不要因为旧工程方便而整套重建，也不要把小批注升级为全面改版。若导入导出会丢动画、母版或用户调整，先以副本验证；保留无法可靠迁移的功能并说明。

## 一份公共内容，显式版本差异

示例矩阵（仅是示例，不固定实际页码）：

| 页面键 | 普通授课版 | 含课程商品版 |
|---|---|---|
| 输入工具页 | 含工具商品图 | 含工具商品图 |
| 资产基建页 | 无课程商品图 | 含课程商品图 |
| 结束页 | 无课程商品图 | 含课程商品图 |

这样“无课程商品图”版仍可有工具商品图。命名表达真实差异，不能简称“无商品图”造成误解。用户后续取消某页双版本时更新矩阵，不能继续套最初规则。

公共文字、配色、图示关系保持一致。布局若为商品图留位而变化，应写进矩阵的允许差异。必要时生成两份完整演示稿；若用户只要两个备选单页，不擅自复制整套。

同一张商品图用文件哈希标识；不依赖容易漂移的媒体序号。检查两版所有图片有无误串、遗漏或额外营销文案。

## 用户手调后的交接

1. 读取文件时间、SHA-256、页面顺序、元素和媒体清单，建立新基线；历史生成输出只作比较。
2. 用户定稿后不修改它。用户随后要求改动时，从该基线复制新的版本，再做定向修改。
3. 可用 `scripts/pptx_inspect.py compare OLD NEW --out REPORT.json` 找到变化候选。原始 ZIP 差异可能仅来自软件重存，结构变化也不一定是可见变化；回看实际渲染。
4. 对未修改页做必要回归检查，不能只证明指定文本出现。共同母版或字体变化会波及更多页。
5. 最终成品和内部验收分开存放。保留可恢复版本，不擅自恢复用户已经删除的旧稿，不让工程文件重新堆满成品目录。
