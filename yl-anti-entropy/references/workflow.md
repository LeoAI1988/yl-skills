# 磁盘排查与清理流程

## 只读排查

1. 读取用户指定盘符/目录、外置个人配置和本项目适用规则。多盘可逐盘或在工具中传多个根；不要为扫描提权、改权限或关闭工作中的软件。
2. 先读总容量、已用、可用，再自顶向下统计。百万文件的大盘先使用 `scan --metadata-only` 目录元数据模式，候选范围再做完整身份清单；不为系统组件和所有依赖逐个取文件身份或生成大型全盘数据库。快扫逻辑字节可能重复计算硬链接，不给全盘独立实体/可释放量；候选必须另核。全盘扫描跳过重解析点并记录，不沿知识库别名/Junction重复遍历。输出放扫描范围外；确需放同盘时排除输出自身。记录异常与覆盖范围。
3. 先给一级目录分布，再钻取最大的业务目录；统计最大文件、主要扩展名、近7/30天创建/修改分布和明确缓存。`cache`、`工程`、`过程文件`只是线索，不是删除授权：里面可能有原片或正式源代码。
4. 对字节重复进行完整哈希核验，同时读取真实文件身份识别硬链接。可以先查大文件以尽快拿到结果，但要标注阈值，不声称已排尽小文件。
5. 按业务角色整理候选：明确可再生缓存、已完成发布副本、已定稿工程、确证重复实体，以及需继续保留/排查的文件。每项列准确路径、逻辑大小、保留位置与处理前提，不只给总数。

## 清理前核验

恢复当前已给出的授权，不让用户重复批准同一范围。仅排查时停在报告；用户要求“合理清理”时可处理范围内已确证的缓存、重复副本及已确认工程，未知/唯一文件留待核对。确认归档的专项任务把清场作为完成标准。

先生成小型清单并核验保留集，修正工程、说明、审查稿、网页及待办引用。重复实体可直接删除，分类入口则先建并回读快捷方式；不同内容不能仅因文件名相同就覆盖。跨卷正式归档确需移动时先复制并校验，再移除旧位置，转换期间的副本不能留成永久备份。

工程清理针对与确认成果对应的所有制作轮次，不局限最后一次运行。原始输入/最终成果仅在工程内时先转到正式目录；普通脚本、配置、增强中间件不是原始母带。不要将整个工程移到“工程归档”后声称已清理。

每个删除目标先验证解析后的绝对路径处于准确清单范围，拒绝磁盘根、越界路径、共享上级目录或与保留集重叠。检查目标和父级的重解析点，遍历不跟随 Junction/符号链接；范围内共享依赖链接仅可拆除链接本身。保存待删文件的完整 SHA-256、大小及保留集校验值，记录与执行工具放在待删范围之外。磁盘空间统计预先选定同卷、清理后仍存在的位置，避免删除工程根目录后回执生成失败。

## 执行与受阻处理

Windows 使用同一个 Shell 或运行时完成文件操作。优先按已核验的固定目录分组，在工具参数中明确 `workdir`，命令直接列出有限的字面文件名或绝对路径。以下仅示范清单表达方式，实际文件须来自本轮核验。

```powershell
Remove-Item -LiteralPath 'frame-0001.png','frame-0002.png' -ErrorAction Stop
```

每组执行前复核文件与清单一致，执行后检查实际剩余项。文件清完后，重新确认范围内剩余文件及重解析点为零，再从深到浅逐项删除已核验的空目录，使用不带 `-Recurse` 的 `Remove-Item -LiteralPath`。遇到新增文件即重新核对。避免把动态枚举结果直接传给批量删除，更不得跨 Shell 拼接破坏性命令。

根据真实错误处理，保留准确错误和发生阶段。

| 情况 | 后续处理 |
|---|---|
| 文件占用 | 查明持有者，仅结束本批自己启动且已完成用途的进程，核对后续做可处理项 |
| 操作系统权限错误 | 检查目标、属性与访问权限，按当前授权和宿主规则处理；需要额外权限时记录依赖 |
| 工具在启动前返回 `blocked by policy` | 该调用未执行。读取明确拒绝原因与适用规则；原因未提供时保留未知，不能推断策略升级或权限变化 |
| 文件或目录快照变化、部分删除 | 回读实际文件与回执，核对已完成项，为剩余范围刷新计划 |

单次批量调用受阻后，先判断是否仍有规则允许的、作用范围更精确的处理方式。仅在已有授权及宿主规则允许时，把已核验目标缩为明确文件组并经正常工具审批执行。明确禁止的动作必须停止，不能通过换语言、换工具、隐藏脚本、改权限或混淆命令规避。显式文件命令也须接受审批，不能承诺必然通过。

持续完成可处理部分。只有确认剩余项确需用户权限、操作或外部状态变化时才交接，说明具体路径、数量、字节、错误及所需动作；不能仅凭一次拒绝就断言只能手动清理。续做以实际现状为准，已归档或已删除项不重复处理。

## 收尾报告与自清理

复核保留集哈希、目标缺失或准确剩余项、快捷方式真实目标和正式引用。分别记录删除文件数、逻辑字节、实际磁盘可用变化及差值可能受其他运行任务影响。按专项要求复验知识交接与浏览入口。移动到同盘其他位置或回收站不计为释放。

恢复执行成功后，原位更新批次最终状态、清理回执及旧的“未清理／手动清理”说明，清除已解决的待办。保留必要失败经过供追溯，当前状态必须与文件事实一致；目录已删但回执报错时先复验结果再修复回执。

将必要依据合入现有说明或一份小型摘要；只保留继续判断所需的映射和清理结果。完整扫描数据库、重复列表和试验工件完成后可以按本次范围清掉，不永久生成新的日志/备份层。未完成的清理只保留足以续做的小型状态，真实原件与成果不在这一步删。
