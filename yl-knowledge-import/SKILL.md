# 本地资料接入

读同级 `yl-knowledge/references/contract.md` 和个人配置。只接收用户指定文件/目录，不全盘扫描。先清点文件、来源、格式和可读性，过程输出放系统资料。

原文件保留不变。Markdown/TXT 直接读；PDF、Office、图片使用宿主已安装对应工具；音视频优先已有转写工具，保存媒体哈希、raw ASR、时间戳、校订稿和未决片段。第二个模型结果不等于原音核验。工具缺失可继续其他文字材料，不谎称全完成。

登记文字源：`python -B ../yl-knowledge/scripts/knowledge.py --profile PROFILE register --file FILE --id SOURCE_ID --origin local --ownership unknown`。登记前先读原文；随后由归档成员确定本人/混合/外部归属。已知本人语料也须识别嵌入引句。

进入 `yl-knowledge-ingest`，再回总入口走完提炼、表达、关联及检查。去重不能丢掉不同稿本的鲜活措辞。外部大型项目默认原位映射，不整体复制代码、媒体和客户材料。

## 本地稿先做同源判定（2026-09-26 补）

收件箱里的“新稿”常常是某篇已发布文章的早期稿本。**先做句子级重合度比对**再决定处置：把稿子按句切开，逐句在候选作品正文里查逐字命中，命中率高的按“同一篇的不同稿本”处理——归档保留原稿、登记与各平台的版本关系，**不新造原子**，并在完成收据的 `dedup_reason` 里写明命中率与承载观点的既有原子 ID。
实测一例：本地稿 32 句中 29 句（90.6%）逐字出现在某公众号正文中，判为早期稿本。

## 写档案文件的工程红线（2026-09-26 补）

1. **`.asset.yml` 里的 Windows 路径不要用双引号包**。YAML 双引号串会把 `\0`、`\A` 之类当转义序列，扫描直接报 `found unknown escape character`。
   正确写法二选一：单引号且**只保留单个反斜杠**（`canonical_path: '<drive>:\...\x.md'`），或双引号且反斜杠双写（`"<drive>:\\...\\x.md"`）。
   ⚠️ 反例：把 `"<drive>:\\a\\b"` 机械改成 `'<drive>:\\a\\b'` 会得到字面双反斜杠，路径全废。
2. **批量改档案文件前先圈定白名单**。用正则扫整个目录会误伤既有文件（实测一次误改 35 个，含大量历史档案）。改完必须逐个 `os.path.exists()` 校验真实路径，不能只看脚本没报错。
3. **Windows 上处理中文文件名不要用 bash 的 `for` 循环 + `rm`**，会中途被 SIGTERM 打断且部分执行。统一改用 Python 的 `os.remove()` / `shutil` 显式清单操作。
4. 批量写入后立刻跑一次结构校验（`knowledge_atoms.py rebuild` 或对应仓的校验），把校验结果作为“写对了”的证据，而不是以“没报错”作为完成。
5. **`.asset.yml` 与其它自建 YAML 的键值若含 `：`（全角冒号）或中文键名**，`re.sub` 替换时回调串里的 Windows 路径会被当转义序列（报 `bad escape \P`）。**替换一律用 `lambda _: '...' + newpath`**，不要用 `'...%s' % newpath` 直接当 repl。

## 密级用「文件夹」表达，不要只记在表里（2026-09-27 教训）

**踩过的坑**：某批外部真源（87 篇手写笔记）的密级原来只存在登记表 CSV 的 `privacy_level` 列里，
磁盘上完全看不出哪篇是哪级；而且两侧方向相反——**登记表是脱敏路径**（`工作/[受限]/SNOTE-xxx.md`），
**磁盘是真名**（`keepn公号后台.md`）。结果任何工具（包括 Agent）直接翻目录都可能把高敏内容当普通资料读，
只能靠“记得去比对登记表”来兜。**这不是机制，是运气。**

**正确做法：让文件夹成为密级的唯一权威。**

```
真源根/
├── 公开/     ← 可调用、可蒸馏、可进索引
├── P2/       ← 受限，不公开
└── P3/       ← 高敏（账号/后台/凭据），禁止解码
```

- 索引/蒸馏脚本**只看路径**：命中 `公开/` 才收，命中 `P2/`、`P3/` **直接跳过且不解析内容**
  （是“不读”，不是“读了再丢”）。
- 好处：文件夹是物理事实，不会像 CSV 那样漂移；也不依赖“谁记得去比对”。
- 机器分级与人工复核的差异仍可记在覆盖表里，但**结论要落到文件夹上**。

### 改目录结构必须同步「四处」——缺一处就留断链

**任何一次移动/改名/合并目录，以下四处必须一起动**，这是硬清单：

1. **来源登记表**（如 `…源登记表.csv` 的 `source_relative_path`）
2. **来源指针**（如 `历史来源映射/SNOTE-*.md` 的 `source_path`，以及正文里的“原文路径：”行）
3. **索引/原句库**（重建，让路径刷新）
4. **迁移映射表**（记录旧→新，供回滚与追溯）

**我犯过的错**：把 `P0/`+`P1/` 合并成 `公开/` 后**只改了索引，忘了登记表、指针、映射表**，
直接导致 50 个来源指针集体断链、要再修一轮。**先列清单再动手，改完逐项打勾。**

### 修来源指针的两个反直觉点

- **不要按内容哈希反查路径**：指针里的 `source_sha256` 存的是**规范化后的哈希**，
  不是原文件字节哈希，用文件字节哈希去匹配会全军覆没（实测 46 个一个没中）。
  **按路径映射改**才对。
- **指针里的文件名可能是被截断的**（`结盟，设计经理…各个端口都要有自己` 少了结尾）。
  定位真实文件要**按前缀模糊匹配**，不能要求全名相等。
- 原文已被本人删除的指针，**不要删指针**，标 `原文状态: removed_by_user_YYYYMMDD`，保留历史。

### 删除前的一致性门槛
动完结构、要删备份之前，必须**逐字节核验**：文件数一致、哈希全对、无缺失、无多余。
核验通过才删；删除走**回收站**（Windows 用 ctypes 调 `SHFileOperationW` + `FOF_ALLOWUNDO`，
`send2trash` 对含中文的长路径会报 `FileNotFoundError`；**PowerShell 的 `Add-Type` 常被安全策略拦截**，不要走那条路）。
