# 本地小红书发布工作台

通用程序在 `scripts/workbench`，个人配置、媒体、SQLite、截图和任务日志外置。仅处理最终视频成片；图文笔记不在本版本范围。

## 运行与安装

Python 3.11 及以上，无第三方服务端依赖：

```sh
python -B scripts/workbench/server.py --config /absolute/path/xiaohongshu-config.json
```

| 字段 | 用途 |
|---|---|
| `platform` | 必填 `xiaohongshu`；数据库也须具备对应平台标记 |
| `data_dir` | 本机外置数据目录，不能指向其他平台数据 |
| `port` | 默认 18767，仅绑定 127.0.0.1 |
| `account` | 预期小红书账号；不能根据抖音账号自动推断 |
| `tag_pool` | 可选相关话题候选，不要求至少 10 个 |
| `collections` | 用户已确认存在的合集候选；默认空 |
| `codex` | 已安装并登录的 Codex CLI 位置，缺省查 PATH |
| `ffprobe` | 本机时长检查工具，可选；缺少时不猜测时长 |
| `schedule_lead_minutes` / `schedule_window_days` | 可调整的本地规划预检，默认 60 / 14，未认定为当前平台正式规则 |
| `initial_folders` | 可选的已授权本地素材目录 |
| `icon` | 可选外置个人图标；默认页面使用文字标识 |

既有台账仅可导入明确标为小红书的数据；不把抖音已发布或已定时记录搬成小红书成功历史。已有 SQLite 若无平台标记或属于别的平台，在任何数据写入前拒绝打开；不自动迁移未知数据库。

Windows 桌面入口可以使用外置 `launch.py` 与 `pythonw.exe -B`。启动器检查 `/api/health` 的 `app=yl-xiaohongshu-workbench`，后台隐藏启动后打开本地网页。安装仅添加该成员入口到同一核心；不复制另一个宿主核心，不改浏览器安全设置，不创建开机自动发布。

用户要求桌面图标时，将图标保存在个人工作台稳定目录并绑定快捷方式，不能只交付图片。圆角依赖图片自身的 RGBA 透明边角，Windows 不会自动把实心方图裁成圆角；ICO 包含 16、24、32、48、64、128、256 像素各档，逐档核对角落透明并查看小尺寸预览。替换前备份快捷方式，只改 IconLocation，回读确认启动路径、参数和工作目录未变，再温和刷新图标；不重启 Explorer 或清除全局缓存。图标和个人快捷方式不进入通用核心。

## 使用顺序

1. 确认预期账号，添加本地文件夹，选择最终成片。新增账号只影响本地预期值，实际准备前仍须浏览器核对。
2. 检查每篇标题、发布正文、已有封面、话题和 AI 参与情况。标题最多 20，正文连同话题最多 1000，话题最多 10；界面与服务端都检查。超限来源仍完整保留，手工改到合规后才能准备。AI 参与未知时可本地整理，不能启动上传填表。
3. 设置日期、每天篇数与首末时刻。默认每天 1 篇，10:00—20:00；单篇使用开始时刻，多篇在区间内按十分钟均分。支持 1—10 篇是本地规划功能，不表示小红书批准这个频率。按日期双列显示，可拖动调整，已锁定条目保持固定。
4. 每次只选一篇，查看确认明细后点“准备这一篇”。这一步授权该篇上传和填表；已在聊天中明确授权具体篇目准备时，无需再重复询问，可等价启动该篇准备。不点击平台提交或保存草稿；平台本身可能自动保存编辑内容。准备完成显示“等待人工提交”，到平台检查并提交。
5. 回工作台点“核对平台结果”。它只读后台，不上传、不重发、不改期。等待人工提交或结果不明时保留锁定，防止重复开新编辑流程。只有核验未提交且有证据的条目才可恢复。
6. 登录、验证码、频率和风险提示由用户正常处理；程序不循环重试或更换身份。不承诺“防封”“规避反 AI”或平台已批准网页辅助操作。

确认弹窗冻结当时的账号、素材、发布字段、排期和模型选择。其他窗口修改后，旧确认会被拒绝，需重新打开检查；不能自动换成新内容再提交。已核验审核中或定时待发的记录仍可继续只读核验后续状态。

定时能力必须在上传前根据当前后台确认。时间已过或平台不支持时停止本篇，不能改成立即发布。本地未来计划不意味着已保存到平台。

## 内容、状态与证据

- `body` 是来源正文，仅用于本地核对和匹配；`caption` 为人工确认的发布正文。执行队列不应传递整份内部审查稿。
- 标题和正文使用 UTF-16 单元数保守检查，中英文通常均计 1，常见 emoji 计 2；不声称这是官方精确算法。话题规范化、去重后按 0—10 个校验，不自动补满。
- 默认公开、不添加位置活动、不关联合集。实际平台不支持下载权限时记录未找到，不能冒充已设置。AI 参与选“待确认”“内容未使用 AI 创作”“含 AI 生成或辅助创作”，覆盖视频、图像和正文的生成、合成、润色及优化，后者按事实选择平台标识；需要正文说明时由用户提供并计入长度。
- 本机 Codex 执行器默认 GPT-Astra、高推理；可选 GPT-6.1 Sol 及中/高/极高。参数随任务冻结，核验沿用，不能静默换模型或修改全局配置。
- 每篇任务写外置 `jobs/<id>/queue.json`，执行器仅写该目录 `progress.json/result.json` 和证据，不直接写工作台数据库。
- 状态区分 `awaiting_manual`（等待本人提交）、`reviewing`（审核中）、`scheduled`（定时待发）、`published`（已发布）、`failed`、`unknown`。上传或填表完成不是平台提交成功。
- 平台已接收的结果（审核中、定时待发、已发布）需本次核验目录中的有效截图、匹配的指定时刻与真实平台 ID。准备交接 awaiting_manual 尚无平台 ID，以字段回读及截图证明，不能编造 ID。小红书 ID 可以包含字母，不能套抖音纯数字校验。未取得字段留空，不编造。
- 单篇门控及结果证据校验在本地实现；浏览器禁止点击最终提交仍依赖执行器遵守 Skill 和冻结任务，不宣称已在浏览器层屏蔽提交控件。
- 服务只绑定回环地址，修改请求检查 Host、Origin 和 CSRF；视频只读，按登记 ID 预览，提供 Range，用户修改素材路径需重新核验。

## 验证

```sh
python -B scripts/workbench/test_workbench.py -v
```

覆盖 20/21 字、emoji、正文与话题合计、10/11 话题、AI 参与未知、账号必填、单篇准备、等待人工提交锁定、并发排期版本、平台 ID、证据与时间校验。测试使用隔离数据，不启动真实上传或发布。

安装后通过本地页面检查账号栏、素材导入、标题/正文计数、话题上限、默认选项、单篇排期、预览和确认明细。真实后台连接、真实上传及平台提交必须分别记验收状态；没有登录或上传实测不能报“端到端发布通过”。
