# 本地小红书发布工作台

通用程序在 `scripts/workbench`，个人配置、媒体、SQLite、截图和任务日志外置。仅处理最终视频成片；图文笔记不在本版本范围。

## 运行与安装

Python 3.11 及以上，无第三方服务端依赖：

```sh
python -B scripts/workbench/server.py --config /absolute/path/xiaohongshu-config.json
```

| 字段 | 用途 |
|---|---|
| `platform` | 必填 `xiaohongshu`；数据库也须具备对应平台标记 |
| `data_dir` | 本机外置数据目录，不能指向其他平台数据 |
| `port` | 默认 18767，仅绑定 127.0.0.1 |
| `account` | 预期小红书账号；不能根据抖音账号自动推断 |
| `tag_pool` | 可选相关话题候选，不要求至少 10 个 |
| `collections` | 用户已确认存在的合集候选；默认空 |
| `codex` | 已安装并登录的 Codex CLI 位置；路径失效时查 PATH，再查 Windows 当前用户的 Codex 桌面版安装目录，适配自动升级 |
| `ffmpeg` | 本机抽帧和音频比对工具；优先显式路径，其次 PATH 和 ffprobe 同目录，失败时隔离未检查项 |
| `ffprobe` | 本机时长检查工具，可选；缺少时不猜测时长 |
| `schedule_lead_minutes` / `schedule_window_days` | 可调整的本地规划预检，默认 60 / 14，未认定为当前平台正式规则 |
| `initial_folders` | 可选的已授权本地素材目录 |
| `icon` | 可选外置个人图标；默认页面使用文字标识 |

既有台账仅可导入明确标为小红书的数据；不把抖音已发布或已定时记录搬成小红书成功历史。已有 SQLite 若无平台标记或属于别的平台，在任何数据写入前拒绝打开；不自动迁移未知数据库。

Windows 桌面入口可以使用外置 `launch.py` 与 `pythonw.exe -B`。启动器检查 `/api/health` 的 `app=yl-xiaohongshu-workbench`，后台隐藏启动后打开本地网页。安装仅添加该成员入口到同一核心；不复制另一个宿主核心，不改浏览器安全设置，不创建开机自动发布。

用户要求桌面图标时，将图标保存在个人工作台稳定目录并绑定快捷方式，不能只交付图片。圆角依赖图片自身的 RGBA 透明边角，Windows 不会自动把实心方图裁成圆角；ICO 包含 16、24、32、48、64、128、256 像素各档，逐档核对角落透明并查看小尺寸预览。替换前备份快捷方式，只改 IconLocation，回读确认启动路径、参数和工作目录未变，再温和刷新图标；不重启 Explorer 或清除全局缓存。图标和个人快捷方式不进入通用核心。

## 使用顺序

1. 确认预期账号，添加本地文件夹，选择最终成片。新增账号只影响本地预期值，实际准备前仍须浏览器核对。
2. 检查每篇标题、发布正文、已有封面、话题和 AI 参与情况。标题最多 20，正文连同话题最多 1000，话题最多 10；界面与服务端都检查。超限来源仍完整保留；非手工来源标题可在队列中选取逐字可核验的原题完整短句，上传前必须通过最终计数校验。已有手工字段超限时单篇留待处理，不静默改写。AI 声明保留逐篇已确认值，其次自动应用安装者明确授权的个人默认值；有默认值时不再弹窗询问。通用核心不指定个人默认值。
3. 设置日期、每天篇数与首末时刻。默认每天 1 篇，10:00—20:00；单篇使用开始时刻，多篇在区间内按十分钟均分。支持 1—10 篇是本地规划功能，不表示小红书批准这个频率。按日期双列显示，可拖动调整，已锁定条目保持固定。
4. 排期可逐条多选、每天“全选当天 / 取消全选”或“全选待发布”；每天按钮只影响当天待发布项，保留其他日期的选择。点“批量设置”同屏检查各篇标题、正文、话题及 AI 声明；可统一应用已核实的 AI 声明和可见范围，话题按各篇内容分别匹配。整批验证通过后一次保存，字段超限、作品锁定或内容版本变化时整批拒绝，不留下部分修改。选择在同一浏览器刷新后保留。时间窗口不符仍可选择并编辑本地内容，但准备前必须调整排期。
5. 多选后“确认发布 N 篇”展示整批明细，点击“确认并发布整批”授权固定内容按指定时间顺序上传、填写、最终提交和核验。每篇成功后自动继续；已核实重复跳过，上传前仍疑似重复的本篇隔离待核对，其他条目继续，无需用户逐条点击；不能并发打开多个编辑页。缺标题或封面时按确认页说明，在队列中自动匹配并显示进度；已配置个人 AI 声明默认值时自动应用。匹配失败只跳过本篇，不返回聊天补资料。旧版单篇准备任务不自动升级为发表授权。
6. 在“发布进度与结果”查看已确认提交数、已定时/审核中/已公开以及各篇当前阶段、耗时、最近响应和异常原因。用户停止、连接失败、风险提示或结果不明时停止批次，已成功记录保留。未开始和明确上传前中断的条目返回排期；已上传或可能提交但结果不明的条目只能只读核对，不能重传。“只核对结果”不会发布。
7. 登录、验证码、频率和风险提示由用户正常处理；程序不循环重试或更换身份。不承诺“防封”“规避反 AI”或平台已批准网页辅助操作。

确认弹窗冻结当时的账号、素材、发布字段、排期和模型选择。其他窗口修改后，旧确认会被拒绝，需重新打开检查；不能自动换成新内容再提交。已核验审核中或定时待发的记录仍可继续只读核验后续状态。

时间提前量使用服务端时钟，并在确认弹窗停留期间持续更新；点击最终确认前重新读取当前状态。排期失效时显示具体作品、原时间、当前时间与最早可选时刻，不启动上传。点击排期行的“修改时间”可以只调整这一篇，保留其他条目的时间和发布字段；保存时检查排期版本，避免覆盖其他窗口的修改。

定时控件若在上传后出现，可先上传获授权的这一篇，再在最终提交前核实定时能力和窗口；上传前看不到控件不能直接当成不支持。时间已过或平台不支持时停止本篇，不能改成立即发布。本地未来计划不意味着已保存到平台。

## 内容、状态与证据

- `body` 是来源正文，仅用于本地核对和匹配；`caption` 为人工确认的发布正文。执行队列不应传递整份内部审查稿。
- 导入标题只读取与视频同名或以其完整名称加分隔符命名的 Markdown，优先“发布标题 / 原始标题 / 成片标题 / 视频顶部标题”明确字段，避免将审查稿文档名称当标题。多个来源冲突时保留待确认；没有原稿时需核对成片，不能拿哈希文件名充数。手工修改保留原始出处。
- 标题和正文使用 UTF-16 单元数保守检查，中英文通常均计 1，常见 emoji 计 2；不声称这是官方精确算法。话题规范化、去重后按 0—10 个校验，不自动补满。
- 默认公开、不添加位置活动、不关联合集。实际平台不支持下载权限时记录未找到，不能冒充已设置。AI 参与选项覆盖视频、图像和正文的生成、合成、润色及优化；缺少单条记录时使用安装者已授权的个人默认值，已有单条声明优先，按实际制作情况可修改；含 AI 内容时按平台要求使用真实标识。
- 本机 Codex 执行器默认 GPT-Astra、高推理；可选 GPT-6（`gpt-6-sol`）、GPT-6.1 Sol 及中/高/极高。参数随任务冻结，核验沿用，不能静默换模型或修改全局配置。
- 每批任务写外置 `jobs/<id>/queue.json`，每篇使用独立 `attempts/<id>` 目录，执行器仅写该目录 `progress.json/result.json` 和证据，不直接写数据库。新批次使用 `mode=batch_publish`；旧 `prepare` 和只读 `verify` 权限分别保留。
- 状态区分 `not_started`（未开始）、`not_uploaded`（明确未上传）、`duplicate`（核实旧作，跳过）、`duplicate_pending`（完全未上传的疑似重复项，单独隔离，其余继续）、`awaiting_manual`（旧准备任务）、`reviewing`、`scheduled`、`published`、`unknown`。上传完成不是提交成功。进度按真实阶段展示，不伪造上传百分比。最近响应超过 45 秒显示等待提示；默认无响应 300 秒或单篇 1800 秒时停止，不自动重试。可通过 `executor_idle_timeout_seconds` / `executor_item_timeout_seconds` 调整本地超时。
- 平台已接收的结果（审核中、定时待发、已发布）需本次核验目录中的有效截图、匹配的指定时刻与真实平台 ID。准备交接 awaiting_manual 尚无平台 ID，以字段回读及截图证明，不能编造 ID。小红书 ID 可以包含字母，不能套抖音纯数字校验。未取得字段留空，不编造。
- 顺序编排、批次冻结、进度读取、超时及结果证据校验在本地实现；浏览器操作仍依赖执行器遵守冻结清单与权限，不宣称平台认可自动化。
- 服务只绑定回环地址，修改请求检查 Host、Origin 和 CSRF；视频只读，按登记 ID 预览，提供 Range，用户修改素材路径需重新核验。

## 验证

```sh
python -B scripts/workbench/test_workbench.py -v
python -B scripts/workbench/test_batch.py -v
```

覆盖字段限制、批量原子编辑、旧准备模式、整批确认、顺序推进、部分成功后停止、未上传与未知结果区分、无输出超时、重启恢复、历史成功凭证保留、平台 ID 与时间校验。测试使用隔离数据，不启动真实上传或发布。

安装后通过本地页面检查账号栏、素材导入、标题/正文计数、话题上限、默认选项、单篇排期、预览和确认明细。真实后台连接、真实上传及平台提交必须分别记验收状态；没有登录或上传实测不能报“端到端发布通过”。



单篇疑似重复继续条件：本次账号与候选截图、候选标题、`block_scope=item`、`reason_code=duplicate_unconfirmed`、`preflight_only=true`，且上传/提交标志均为 false。任一不符保持 unknown 并停止；登录、风控、连接与提交不明仍停整批。待核对项不计入发布成功，不再被全选自动带入新批次。

单篇故障隔离：文件选择窗口超时且未调用 setFiles，须有当前空白上传页截图和明确未上传/未提交标志，才记为 item_failed，恢复本地待发布并继续下一篇。登录、连接、风控、已调用 setFiles 后结果不明仍暂停整批。失败原始原因与校验原因同时保留。排期更换列表只显示本篇与尚未占用的素材，避免大量已排期选项重复渲染。

## 本地查重区

导入自动检查，也可“重新查重”。`duplicate_checking` 是未完成检查、`duplicate_review` 是本地疑似重复；两者都不能进入发布任务。候选按组显示路径和原因，可逐组或全部深度排查。单组深查只检查这一组，保留其他组与待发布列表；文件版本变化须回到全库重新查重。已提交/已排除单独折叠展示，不能选中。

先用 SHA-256 排除同文件，包括改名或跨文件夹复制；再按名称、标题与相近时长的三处画面寻找候选。深度比较 12 处画面；只有时长、动态画面与三段音频高度一致才自动排除转码副本，明显不同才返回待发布。相似布景、裁切、时间偏移、静态视频和声音证据不足可能继续待排查，不保证自动判定所有变体。候选连成一组只是展示方式，不把相似关系传递成重复结论。

历史记录优先保留；一组未发副本只保留一个，优先已排期条目。平台 `duplicate_pending` 仍须核对原平台记录，不从本地按钮直接解除。查重结果不替代上传前的必要平台核对。

本地抽帧最多并行处理 3 个文件，发布仍按顺序执行。数据库记录进度与原因；服务中断后未检查项保持隔离，重新查重可继续。指纹缓存按文件路径、大小、修改时间验证；深度结论按内容哈希失效。整个检查中禁止发布和修改库存，检查结果原子提交。缓存位于外置 `data_dir/dedup-cache`，不复制视频。

## 人工解除疑似与字段整理

查重卡片支持按单条或整组人工确认不重复；`POST /api/dedup/clear` 校验查重版本、文件版本和任务状态，原子保存结论与可选状态。解除的是当前候选之间的关系，不是永久白名单。已发、字节一致、平台疑似、缺失文件和解码错误不适用。

`POST /api/prepare-fields` 只做本地字段整理，不上传或改变排期。已有设置优先；已核对标题、对应原稿、描述性文件名依次回退，仍缺失时读取成片画面上的原文标题。图像模型调用在数据库锁外执行；提交前再检查版本，素材变化时停止。标签最多十个。AI 制作声明支持由安装者明确授权的个人 `ai_declaration_default`，已保存的逐篇声明优先；有有效个人默认值时不询问 AI 声明。没有可靠标题来源时显示具体条目，不能伪装为已完成。

## 发布队列内自动匹配

网页发布入口直接展示固定视频、账号、时间和自动匹配策略，最终确认请求带 `auto_prepare=true`。`BatchPublisher` 在线程内逐篇执行 `preparing`，尚未打开平台页面或上传；`field_resolver.py` 只匹配本篇字段，最终通过执行校验后才调用浏览器执行器。原始 `queue.json` 保持冻结，匹配结果及来源记在外置任务的 `prepared/<asset_id>.json`，浏览器尝试清单仅包含最终发布字段，不带内部原稿。

已有标题/封面和人工设置优先；主标题识读可检查首秒顶部、对应封面和多处完整画面；对应原稿回退仅接受逐字连续原话。封面匹配要求同视频名称绑定，无对应已有图时提取本片原帧至个人数据目录。单篇缺可靠来源、文件失效或抽帧失败返回 `item_failed` 且 `upload_started=false`，其他篇继续；`preparing` 阶段中断恢复为未上传。取消后即使本地模型随后返回也不开始浏览器上传。页面无需返回 Codex 补全。

每批首次 Codex `thread.started` 的会话ID保存到任务，后续单篇用同一会话 `exec resume`；保留冻结模型与推理强度，避免跨会话占用同一原页。`POST /api/resume` 仅用于新只读凭证已证明同一原上传完成且未提交的连接中断：核对账号/文件/新截图/原批次字段和排期，继续同一编辑页，不重传。无法证明或可能提交时拒绝。

## 服务更新后的页面连接

旧页面可能保留重启前的 CSRF 凭证。服务只在 Host 与 Origin 均匹配、且尚未进入业务处理时返回 `csrf_expired`；前端获取同源 `/api/session` 的新凭证，保留本次固定明细并仅重试一次。地址不符独立提示，不再用“请从本机工作台操作”混淆原因。保持无 CORS、禁缓存和 CSRF 校验；网络断开、响应不明、业务失败和平台提交不明不自动重试。更新前端脚本后须刷新原页面，不能把仅打开排队中的标签当成已加载新版。

执行器自动将成功浏览器工具调用输出的真实截图保存为本次尝试目录 `browser-shot-<hash>.jpg/png/webp`；无效图片或保存失败不影响已发生的提交状态，图片本身不自动升级成成功凭证。恢复阶段沿用已核对字段，避免重复开启可选智能章节或推荐窗口。原页已上传且明确未提交的连接异常，仅经新鲜原页凭证与冻结明细核对后恢复；已点击提交则只能核验。
