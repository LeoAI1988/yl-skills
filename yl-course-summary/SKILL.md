# 长视频总结

以实际视频和完整转录为依据，整理清晰、可回看的长视频总结。课程与演示突出判断、入口、动作、结果和容易卡住的地方；访谈、讲座与观点分享保留论述推进、论据、案例、分歧与适用边界，不强套操作教程。技术调用名 `yl-course-summary` 保留兼容。

先读 [个人配置约定](../yl-toolbox/references/profile.md)，只读取与本次任务相关的个人说明。讲者原话、完整思想推进、用户最新手改与已确认成品优先；不自动调用通用写作风格。来源视频、路径、头像、凭据和运行记录保留在核心之外。

整理用户本人课程时，正文沿用本人的第一视角，直接说观点和操作；不写“讲师认为”“课堂强调”“原话精简”“要点提炼”等旁观或制作标签。个人选择写“我用／我的”，学员操作直接写动作，不能仅把“讲师”批量替换成“我”就视为完成。必要条件与实际限制融入具体说明。内部仍区分逐字引用与压缩改写，压缩句不套逐字引号；外部访谈的各方身份与判断归属继续保留。

## 1. 确定视频、章节和真源

1. 从实际文件、链接或大纲建立来源清单：视频/章节编号、标题、成片、时长、字幕/逐字稿、版本、待补材料。课程沿用课时；访谈、讲座按实际话题分章，不机械按时长切段。用户说“前两章”时先核对对象；上下文已经明确就直接处理，不重复提问。
2. 以实际选定视频及匹配转录为主，讲者原稿辅助校对术语和思想。大纲、PPT、过程片和标题不能冒充视频全文。多段属于同一章节就合并整理，多个导出版本只选已确定的版本。
3. 复用已有完整字幕或转写，只补缺失和关键疑点。核对文本的开头、中段、结尾与视频时长/内容；不同剪辑、倍速或拼接版本的时间戳不能直接标成成片定位。
4. 缺少转录时，按 [来源与导出](references/source-and-export.md) 选用当前宿主可用能力。材料或工具不足时继续完成有依据的章节，逐项记录缺口；不靠常识补写未读内容。用户要求 YouTube 链接的深入总结时，可按需使用已有 `yl-youtube-deep-summary`。

## 2. 完整阅读，提取可用内容

- 完整阅读选定范围。操作内容梳理目标、前置条件、操作顺序、关键判断、演示分支、常见问题和结果；论述内容梳理问题、观点、论据、案例、反例、分歧与结论。明确出现的“几条原则/几个步骤”逐项覆盖，保持逻辑与依赖。
- 保留少量真正有力度的原话、比喻和判断。逐字引文回源；删虚词、压缩口语或重新概括的句子不套逐字引号，内部记录改写方式，不冒充逐字引用。
- 删除重复口语、无效等待、闲谈和反复试错。保留会影响操作的失败原因与处理办法，不把所有工具日志写给学员。
- 软件入口、按钮、接口格式、参数等关键细节对照实际画面。ASR 中的产品名、数字、快捷键先校正；不能凭模糊读音补出命令或精确参数。
- 区分各讲者判断、视频示例和已验证结果；访谈中的不同立场不能合并成一致结论。只展示检查方案的案例，不写成已经安装或部署成功；价格、套餐、型号、积分等用简短的录制时口径说明，不伪装成最新规则。

## 3. 按内容选择总结方式

参考 [分章模板](references/lesson-template.md)，按实际内容调整，不机械填满所有栏目。

- **开头先说明本章讨论什么或要做成什么。** 一两句话足够。
- **论述保留推进。** 访谈、讲座与分享写清观点怎样提出、靠什么支持、案例说明什么、有哪些分歧与边界。按原顺序或话题重组时保留因果、反驳和来源对应；不把推测写成讲者结论。
- **观点讲清理由与条件。** 理论内容提炼概念、判断和选择标准；只有视频实际提供方法、应用步骤或练习时才整理，不额外编造行动清单。
- **步骤讲清“在哪里做什么、做完看到什么”。** 默认按操作依赖组织；必要时拆成准备、配置、执行、验证。一个步骤一个主要动作，分支说明适用条件。
- **示例指令可以直接用。** 只在有帮助时提供一段依据课堂指令压缩的任务描述，变量用明确占位说明，不加入未讲授的新方案。
- **重点少而明确。** 关键动作、判断、条件适量加粗；少量金句增色，不复述每段。操作教程可用流程速记或完成检查，论述总结可用核心结论与未解问题收束。
- **保留原始材料。** 总结是派生产物，不能覆盖原逐字稿、字幕或用户手改。内部保留章节到来源段落/画面的映射；读者文件不堆本机路径、哈希、API 日志和制作经过。

已经授权整批制作就连续完成，不额外设置逐节批准。用户只要样稿或方案时，停在对应边界。

## 4. Markdown 与 PDF 交付

默认交付 Markdown 和同名 PDF。单条长视频可在一份正文内分章；系列课程或用户要求分节文件时，每节一份并提供阅读目录，按需补带目录、书签和连续页码的 PDF 合集。用户指定格式和组织方式时遵从，不强制拆文件。资料包按需提供，不包含原视频、私有逐字稿和工程记录。

**已有课时文件夹的系列课程，按 [课程手册归档](references/course-filing.md) 交付：** 每节 MD 与同名 PDF 放入对应课时文件夹，与该节视频、逐字稿和课件在一起；总入口用可持续扩充的“学员实操手册”，仅平铺汇总各节 PDF，ZIP 也只收录这些 PDF，不按章再建子目录，不夹带 MD、导航稿或工程文件。用户另有组织要求时优先遵从。此规则不强套到普通访谈、讲座或单条视频总结。

沿用用户已确认的版式和最新文件；新项目采用清晰、可打印的简洁版式。工程文件、转写、截图、预览和验收报告放在外部工作目录，成果目录只放读者需要的文件。

读取安装者外置的署名与品牌设置（如 profile.document_branding）：按要求在标题下写作者，文末右侧放署名、联系账号与真实二维码；Markdown 与 PDF 都要实际包含。二维码复用明确指定的原图，不重绘、不把商品码当个人码。具体姓名、账号、路径和图片不得写进通用核心。检查新增署名后的分页，避免联系方式单独占一张近空白页。

可使用当前宿主的 PDF 能力；若调用其 PDF Skill，先读取并遵循该宿主要求。需要重复批量导出时，可用本成员的 `scripts/export_handbook.py`。它只负责排版、目录、PDF 文字完整性检查和打包，不代替视频内容理解与视觉验收。依赖、清单格式和调用方式见 [来源与导出](references/source-and-export.md)。

## 5. 验收后再报完成

1. **小节覆盖：** 交付与选定视频/章节逐一对应，检查遗漏、错号、多段漏读和版本混用。
2. **内容回源：** 重要步骤、前置条件、成组观点、关键金句都能定位来源；未演示或未核实项有明确边界。
3. **适合内容：** 操作教程检查材料、入口、动作、预期结果及分支；论述总结检查问题、观点、论据、案例和分歧的对应，不混淆各讲者立场，不漏掉改变结论的条件。
4. **文件一致：** Markdown 和 PDF 正文、标题、强调句、条目与数量一致。检查目录链接、书签、页码、字符、字体和压缩包内容。课程归档逐项核对课时目录内的 MD/PDF、汇总 PDF 与 ZIP 成员；汇总副本必须与课时内 PDF 字节一致，ZIP 只含预期 PDF。
5. **真实渲染：** PDF 全页渲染后检查越界、遮挡、乱码、断表、标题孤行、跨页步骤及节末一两行单独占页；先压缩冗余和调整分组，不靠持续缩小字号。只修改一节时验证受影响页即可。

最终给出分节目录、文件和合集的可点击链接，简短说明视频/章节数量与实际检查范围。文件导出、转录覆盖、逐句听审、当前界面实测分别报告；部分完成不能写成整批完成。没有明确发布、云端写入或同步授权时保持本地交付。

用户确认成果并说“归档”时，按 [确认归档清场](../yl-video-archive/references/completion-cleanup.md#用户确认成果并说归档时) 核对正式初始文件、来源和最终总结/手册后，自动删除本批一次性工程、临时音频、转写副本、渲染预览及过程记录，不另建永久工程归档；原始材料与明确要求的交付继续保留。

## 防熵增收尾

保留正式原视频/逐字稿与确认的分节MD/PDF、用户需要的阅读入口及资料包；日常导出不备份。课程 PDF 汇总和 ZIP 是明确要求的交付，不能当作重复垃圾。验收通过且已授权归档/收尾后，清本批临时音频、转写副本、预览、导出工程与过程日志，不再长期堆工程归档。删除前核对正式文件、目录归属和引用，清理后再次核对保留集；不能只清最后一次运行而漏掉同批旧目录。

通用原则与独立磁盘排查汇总见 [yl-anti-entropy](../yl-anti-entropy/SKILL.md)；本成员上面的专项归档/清理步骤继续保留。
