# 长视频切片剪辑

目标是多条能各自观看、继续编辑的短片，不机械均分时长。直接调用时先按同级 `yl-media`、`yl-video` 做一次归属分流；已经分流就继续，不回跳。读取 [个人配置约定](../yl-toolbox/references/profile.md) 和相关个人说明，沿用已有工具选择、视觉标准、素材及授权。默认使用 Remotion；用户指定其他工具时保持内容方法，先核实该工具可用性。

## 1. 恢复任务与源片

检查原件、现有剪辑、源字幕、完整逐字稿、用户已批准版本和本轮修改。先检查实际文件，不把记忆或旧完成标记当当前成品。运行资料始终在核心外，保护原片及已批准输出。

恢复数量、时长、画幅、剪辑与包装范围。无明确数量/时长时可建议6至10条、每条30至120秒；这只是起点，内容不足应少出并说明，不填充凑数。保留原画幅、原声和正常速度，除非另有要求。分别确定：剪辑、标题、字幕、遮盖、配乐、增强、导出。用户要求先剪就先交付剪辑；已有字幕且说不加字幕时不重复叠加。二维码遮盖和替换文字按任务授权；不要把某次商品导流句变成通用默认。

探测源规格、帧率、旋转、像素比例、HDR和音轨。完整读稿并用源音/烧录字幕核对时间；没有可靠全文时先获得转写，不仅凭标题挑选。转写错误不等于说错。云转写/上传/收费模型需要相应授权，可用本地工具和现有资料先推进。

## 2. 从完整论述选片

阅读 [内容与遮盖规则](references/editorial.md)，逐条落实：

- 每片一个明确主题：问题或判断 → 解释/例证 → 独立收尾。补足指代、背景与推理条件。
- 开头前3至5秒给出具体矛盾、结果、代价、问题或源内强判断。可把后段高能句前置，再回到解释；不得改变原意、拼出新主张或无授权加配音。
- 保留必要限定、论证与说话者归属。可跨片重叠、源内重排；前置句可删除原位置的机械重复，必要的回扣可保留。
- 精确剪到完整语句和自然气口；不切半词、不硬凑两分钟、不把开头强度当成整体完整性。

建立候选表：ID、主题/标题、开头原句与源位置、吸引力理由、完整论证、结尾、段落顺序、预计长度、重复/上下文风险。记录每段完整原话与 `[source_start_frame, source_end_frame)`。全自动或已授权直接剪辑就继续；半自动或用户要求先审稿时，交付完整原文、切片顺读稿和明确删改/调序标记，等内容确认再执行。后续标题授权复用已批准时间轴，不重剪音轨。

## 3. 建立可编辑时间轴与包装

按照 [运行方法](references/runtime.md) 使用 `scripts/slicer.py`。示例输入见 [manifest.example.json](references/manifest.example.json)。它只保障计算约束，不会自动理解选题或检测二维码。

每条、每段在 Remotion 中生成独立 JSX 节点；用帧数和半开区间记录源/成片映射。烧录字幕随视频移动。额外字幕仅授权后添加，先核源文再按输出映射重排，不能沿用原片绝对时间覆盖错段。新增字幕或动态包装不走本静态层快路径，应按当前宿主 Remotion 字幕/渲染规范完成再验证。

二维码：实际看源帧，定位每个出现区间及变化位置；完全遮住码、边缘、原扫码文字。遮盖颜色为不透明实色，替换文案是明确参数。源帧坐标在裁切/缩放后须重新映射；默认不裁切。移动码用更细时间段或跟踪遮盖，无法确认时加大遮挡并检查影响。覆盖范围不能压人物口型或必要原字幕。多处二维码分别处理。

标题与字幕各自独立开关。标题文案来自本片主题，遵守个人视觉标准；字体文件、900等真实字重、行距、黄白强调、阴影、位置和显示时长从个人层/任务参数取得，不把具体字体/样例图打包。等字体加载完再渲染，实帧检查溢出和退场。后补标题保持批准的段落和原声音轨。

横版单独校准标题区域与实际字高，不能只按竖版参考的高度等比缩小。用户标注区域时在源画布上换算该区域，按要求放大并加半透明黑底；文字保持实色，底板单独控制透明度。具体区域和样式留在个人参数，不改变竖版既有标准。

先打开可编辑预览并展示一条有代表性的样片；检查开头、切点、结尾、遮盖和标题。需要修改时同步回源映射，不能只改 Studio 后让导出偷偷用旧JSON。源HEVC可另做等时长代理用于预览，最终编码读原片；代理不得改变时间轴。

## 4. 导出与逐条验收

已要求最终短视频/MP4即在授权内完成导出；仅要求预览时停在预览交付。静态标题/遮盖可用Remotion透明PNG → 原片精确trim/concat → overlay，一次视频有损编码。动态效果用正常Remotion渲染，不以静态截图冒充动画。

首次剪辑单独生成原声剪辑音轨并编码一次。仅改包装时，核对批准版本的时间轴指纹，视频编码后完整复制该AAC；帧数限制只用于视频，不用 `-shortest` 截断尾部声音。核对每个AAC包的哈希。源/字体/脚本/文字/时间轴变动都必须新绑定；失败输出保留，重试另建目录，不凭旧完成文件跳过。

每条检查：完整解码、视频帧数/规格、音频起止与长度、声画切点、静帧/黑帧、标题首帧/末帧/退场、遮盖出现/消失及每秒抽样。风险处加密，二维码动态轨迹须逐帧核查。技术报告与主观听审分别记录；必须实际听看每条开头、全部切点、结尾，尽可能完整听看，未做就明确写未做。脚本通过不证明观点完整、听感流畅或平台认可。

交付：独立MP4、可编辑工程、本地播放页、每片完整顺读稿/标题/时长、源到成片映射和核验记录；正文只包含源中实际保留的话，标题/说明单列。保留未核项目。只因剪辑完成不发布、云同步、创建定时任务或清理原片；已授权归档可在成片验收后交给 `yl-video-archive`。

## 来源与维护

验收与本轮预览结束后，默认按 [去重收尾](../yl-video-archive/references/completion-cleanup.md) 将本批临时副本、未采用导出和项目可再生缓存交给归档成员清理，包含 `node_modules/.cache/webpack`，不依赖个人约定或额外清理口令。保留课程真源、最终切片、用户要求的可编辑工程及未完成听审/回改材料，不扩展到历史批次或共享依赖。

本成员依据实际切片工作流独立编写，文档、参数工具与模板为MIT；不复制其他成员的受限工作流，不捆绑Remotion、FFmpeg、模型、字体或私人媒体。依赖许可和适用限制见 [来源说明](NOTICE.md)。新增通用方法只改唯一核心，个人参数与运行输出留核心外。

用户确认成果并说“归档”时，按 [确认归档清场](../yl-video-archive/references/completion-cleanup.md#用户确认成果并说归档时) 清除本批历轮工程与过程文件，只保留正式初始文件、最终成果及用户明确要求的交付；本成员一般性的工程/增强中间件保留条款不再构成额外保留理由。
