# yl 契诃夫深层写作

## 共同写作约束（每次必读）

起稿前读取并执行 [写作公共约束](references/writing-foundation.md) 及其完整规则；直接调用本 Skill 也必须执行写前、写后和交付检查。它约束所有框架与风格，保护用户原话和有效修辞。下文或旧参考中的绝对词句禁令与它冲突时，以公共规则的语义裁决为准；脚本命中不能替代审稿。


## 目标与边界

把契诃夫研究线中已经通过稳定验证的高层机制，用于用户自己的事实、人物与判断。迁移的是观察、转向、后果和节拍决策，不是作者身份、原句、人物、情节或固定“契诃夫腔”。

现实写作不编造事实、引语、现场、心理或用户经历。虚构写作可以创造，但要保持人物目标和因果一致。混合写作先分清事实区与创作区。

## 每次任务

1. 确定交付物、媒介、现实承诺、目标读者、长度、材料范围、必须保留和禁止项。
2. 先读 [workflow.md](references/workflow.md)，建立内容内核：具体事实或设定、两股张力、主判断、反例、边界和希望读者发生的变化。
3. 读 [mechanisms.md](references/mechanisms.md)。只选一个主机制，最多两个辅助机制；适用条件不齐或代价无法控制时不用。
4. 先写不依赖平台花活的母版。每个主要推进段必须增加事实、动作、场景、关系、因果、反例或后果。
5. 需要明显但克制的表达特征时读 [language-shell.md](references/language-shell.md)。最多启用两个外壳参数，用户已确认的表达优先。
6. 输出公众号、短视频或朋友圈时，只读 [media.md](references/media.md) 的对应部分。媒介转译不能新增事实或改变主判断。
7. 检查事实、因果、反例、机制适配、外壳密度、原创性和媒介格式。用户只要成稿时，不展示内部机制名。

使用者原稿、个人表达和已确认观点优先；本 Skill 的机制辅助材料推进，不能替换用户原有思想链。

可用的稳定运行参数保存在 `assets/runtime-profile.json`。需要机器读取时运行：

```powershell
python -X utf8 "<本 Skill 根目录>/scripts/load_runtime_profile.py"
```

## 原著与中文译本

用户要求核对原著、查找句段或追溯依据时，读 [corpus.md](references/corpus.md)，再运行：

```powershell
python -X utf8 "<本 Skill 根目录>/scripts/search_corpus.py" --list
python -X utf8 "<本 Skill 根目录>/scripts/search_corpus.py" --language ru --query "关键词"
```

引用必须给出作品、`work_id`、`source_id` 和行号。本 Skill 自带 12 部已分发许可覆盖的俄文 clean 全文、固定来源与哈希；不是契诃夫全集。中文出版译本只有在使用者自己合法导入后才可检索和引用；缺失时明确说“当前安装没有获授权的中文全文”，不得把自行翻译或内容概述冒充出版译文。

## 机制与外壳停用条件

- 材料只有抽象观点，没有可观察事实或允许创造的场景。
- 机制会把制度、医学或伦理伤害过度心理化。
- 短篇幅不足以保留关键反例与代价。
- 外壳开始替代推进，或出现原作人物、意象、情节次序、连续措辞与独特结构的近似复刻。
- 用户明确要普通、直接、技术性或无风格化表达。

这些条件只停用不适配的机制或语言外壳，不取消整个写作任务。材料只有抽象观点时，依照工作流缩小题目、补可靠来源或用普通中文梳理已有判断；不得虚构细节。作为写作入口的常用首选时，同样完成用户所需交付。
