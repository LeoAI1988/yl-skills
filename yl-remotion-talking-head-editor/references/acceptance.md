# 真人口播成片验收

技术检查与视觉/原声检查分别记录。先根据本次授权建立适用项：只剪错话/长气口时，仍执行三模块内容判断，但不执行范围外的结构调序、短停顿删减或额外包装；已批准的纯视觉修订按下文复用冻结记录。未启用字幕、标题、卡片或封面的项目标为不适用。脚本通过不等于文案逻辑、切词、字幕位置和主观画质已经通过。按 [入口模式选择与执行清单](../SKILL.md) 逐项核销；全自动由执行者完成审核，不能省略审核或伪称用户已确认。

## 两种模式的确认与交付

- 新剪辑任务未指定模式时，先问“全自动”还是“半自动”；本次任务已选模式跨轮沿用。“开始／剪一下”不构成全自动选择。仅改 Skill、回答问题或只读审查不需要选剪辑模式，也不启动剪辑。
- **全自动**：执行者内部完成 GATE-1 和 GATE-2，连续执行本次范围内的剪辑、开拍增强及五项验收，交付最终成品；不索要中间意见，不交待办或未完成版代替最终结果。
- **半自动 GATE-1**：先一并交付本次所有视频的完整原始逐字稿与调整标记稿，逐处标明删除线、调序来去处、ASR 识别文字修改；记录用户对方案的确认，未确认不进入成片剪辑。
- **半自动 GATE-2**：按已确认方案完成剪辑和适用项验收，交付明确标注“剪辑完成，未做开拍增强”的版本；所有停顿候选须已处置，前五秒和全片听审通过。此时开拍状态记录为“按半自动流程等待用户确认剪辑版”，不能记作增强通过，也不能提前提交 API。
- **半自动最终交付**：用户确认剪辑版后，最后调用开拍 API，检查增强画质、色彩及原声音轨，并交付最终成品。逐字稿确认不等于剪辑版确认；半自动两次用户确认不得由内部审核代替。
- 两模式沿用相同剪切精度与验收标准，明显无声空白必须自主剪除。用户审核状态与执行者验收状态分开记录，半自动等待约定确认是阶段完成状态，不能掩盖剪辑漏项。

## 五项独立结论与交付状态

完整剪辑每条必须分别记录：`contentReview`（三项内化分析与EDL落实）、`speechRhythmReview`（逐字逐词、前五秒及全片听审）、`layoutReview`（字幕稳定、卡片授权）、`imageQualityReview`（同源清晰度对照）、`technicalReview`（媒体技术）。每项用 PASS / FAIL / PENDING，并给证据位置；不可用一份technical JSON替代其他四项。

- 五项适用项全部PASS，才可报告“精剪验收完成”；有FAIL继续修复，有PENDING继续完成，不得交作最终成品。半自动在 GATE-2 按约定提供已经剪完、未做开拍增强的阶段输出，此时待用户确认不等于听审或停顿处理未完成，开拍在下一阶段验收。只有用户另行明确要阶段预览，或真实能力/素材缺失使剩余工作无法继续时，才可据实提供未完成的待审输出并明确缺项；全自动不能用“已标待审”代替仍可完成的工作。
- 主观听审必须来自实际听到并检查原声的审阅过程，记录审阅方式、全片范围、前五秒及风险切点结论。工具不能提供音频理解时记PENDING；ASR、波形、静音阈值、PCM哈希均不能替代实际听审。
- 内容原序保持也必须有三模块记录、候选比较和保持理由。未调用外部DBS不是缺项，未执行内化分析才是缺项。
- 用户明确只改样式等局部修订时，复用已通过且哈希冻结的内容/听审记录，不重新剪口播；用户明确要求不做某项时标NOT_APPLICABLE并说明授权范围。不得拿此例外给完整精剪漏项放行。

## 技术检查

- 预期宽高、fps、outputFrames 和时长来自本片 EDL/配置，不能沿用旧片的帧数或时长。仅用户提出最大时长时才设上限；默认180秒封顶不适用于所有口播。
- H.264 视频流一条、AAC 原声音轨一条，无意外数据流；检查 r_frame_rate 与 avg_frame_rate、实际解码帧数及精确视频时长。核对方向、宽高比、像素格式与本次色彩目标。
- 原片旋转后的有效尺寸是默认基线；未明确要求缩小交付尺寸时不得低于它。已旋正的输出rotation应为0或无矩阵，必须看实际帧，不能仅检查1080×1920标签。兼容SDR输出检查yuv420p和正确色彩范围。
- 完整解码音视频并扫描黑帧，保存退出码、错误日志、实际帧数。跳过解码不能确认无黑帧或帧数正确。
- 对默认 SDR 交付检查 BT.709；HLG 原片另核对已做正确转换，不是仅改标签。记录原片信息、滤镜、最终编码参数和画面编码次数；多个输出的命令逐输出核对，不只读第一个CRF。
- 开拍流程额外检查 API 输入、API 原始输出和最终文件：BT.709 原色/传递/矩阵及 limited 范围须在码流解码、抽取帧和 MP4 `colr` 中一致。只看 `ffprobe -show_streams` 或输出命令里的色彩参数不够。混杂输入不得提交，混杂输出保留待诊断，不盲贴标签放行。API 可重编码声音，最终应回接原剪辑 AAC 并验证 PCM，而非把 API 音轨当作原音轨。
- 按任务建立保护清单并比较前后 SHA-256：至少原片，局部修订另含已批准封面/旧成片，纯视觉修订还含EDL、字幕正文/时间。不要把本轮允许更新的视觉配置列为冻结项。
- 纯视觉修订复制已批准的AAC，比较参考音轨和输出的解码PCM；若声明“原AAC逐包复制”，还需比较包数、payload哈希和时间戳。PCM一致只证明解码声音相同，不能代替逐包证据。

## 脚本用法与边界

用 `scripts/validate-talking-head-video.ps1`，或跨平台直接用其 `validate-video.py`。先执行 `--help` 或读取 PowerShell 参数；FFmpeg/FFprobe可显式传路径，优先本地工具，不依赖当前工程的npx或自动下载。

示例中的值从当前工程读取：

```powershell
$editSpec = Get-Content -LiteralPath './work/EDL.json' -Raw | ConvertFrom-Json
& './scripts/validate-talking-head-video.ps1' -VideoPath './output/video_v2.mp4' -ExpectedWidth $editSpec.width -ExpectedHeight $editSpec.height -ExpectedFps $editSpec.fps -ExpectedFrames $editSpec.outputFrames -ExpectedDurationSec $editSpec.durationSec -ExpectBt709 -MaxSilenceSec 0.25 -SilenceThresholdDb -32 -FfmpegPath 'ffmpeg' -FfprobePath 'ffprobe' -ReferenceAudioPath './output/video_v1.mp4' -ProtectionManifest './work/protected.json' -ReportPath './work/validation_v2.json'
```

`0.25秒/-32dB`是新版紧凑档的技术候选检查，不是所有录音的通用静音真值。实际剪切按 [停顿策略](pause-policy.json)：从成片0.15s扫候选，普通无信息间隔≥0.20s收至总留约0.10s，词内和前五秒另查0.12–0.20s。根据底噪选择声学阈值；没有检测到静音不等于没有气口。大于0.25s的保留项逐处说明原因，有意义转折通常不超过0.30s。

保护清单可用对象 `{"files": {"source": {"path": "./input/source.mp4", "sha256": "实际预先记录的哈希"}}}`。哈希基线必须在修改前保存，不能拿修改后的文件自证未改变。

报告必须使用不存在的新路径。验收器在任何写入前核对报告与视频、参考音轨、保护清单及受保护文件的路径，拒绝输入别名和所有已有报告/媒体；最终报告以独占创建写入，日志使用本次独立目录。PowerShell 启动器本身不写报告，启动失败只输出错误 JSON，避免异常路径覆盖素材。复验时使用新的报告名，不覆盖原有证据。

输出的逐项状态包含 PASS、FAIL、SKIPPED、NOT_APPLICABLE；总体 PASS 只代表本次配置的技术检查。`-SkipDecode` / `-SkipSilenceCheck` 会成为 PARTIAL、`ok=false`，不能作为完整验收通过。失败退出非零；退出0仍需检查 status 与遗漏项。`-AllowLongSilence` 只是放行候选，仍须人工逐段说明是否为合理留白，不能默认为已听审。

### API 末包时长舍入的显式例外

默认仍严格核对平均帧率及预期时长。部分 API 的每帧 PTS 维持 30 fps，但只把显示末帧的包时长按封装边界舍入；这会使 `avg_frame_rate` 略偏离 30、总视频时长相差十余毫秒。遇到此类已留存的严格失败证据时，可直接用 Python 验收器增加 `--allow-end-packet-rounding`（PowerShell 启动器暂不转发此选项），不能直接增加通用时长容差。

该选项要求显式 `--fps`、`--frames`、`--duration` 彼此一致，禁止 `--skip-decode`。实际完整解码帧数、全部视频包数及预期帧数必须相等；逐包检查整数 PTS/DTS 与期望 CFR 网格、PTS 唯一性、原始解码顺序 DTS 单调性，以及全部非末包时长。只允许显示末帧包时长改变，差异须严格小于一帧；实际 `duration_ts × time_base` 必须由最后 PTS 加末包时长解释，平均帧率须等于帧数除以该实际时长。微秒级时间戳量化单独记录，不能掩盖内部 VFR、降帧、丢包或重复时间戳。报告中的 `end_packet_rounding_evidence` 给出全包证据，原始严格判定保存在对应检查的 `strictCheckPassed` 字段。

这项例外只认证时间排布，不认证每一帧画面都不同，也不豁免音轨 PCM、保护清单、色彩、黑帧或主观审核。严格失败报告及日志先另存，再用新报告名验证兼容结果。

JSON的 `technicalVerificationComplete` 只表示技术检查完成；兼容旧调用者保留的 `verificationComplete` 也是同一技术含义。`scope`/`verificationScope` 明确限制为技术，不能据这两个字段设置全片交付完成。

未传参考音轨/保护清单/色彩期待时，相应项不被认证；完整流程不能把 NOT_APPLICABLE 写成“声音一致、原片未变、色彩通过”。

## 原声与内容

- 开头是完整词语，前五秒与标题共同建立清楚的问题或判断；结尾保留完整句意。
- 最终交付前核对新档停顿处置表：所有候选均已完成决定及实际处置，待处理为零；≥0.20s无信息间隔已收紧，0.12–0.20s词内/前五秒已扫描；写明最终总留白与帧量化误差，不把每侧padding当总留白。前置hook也必须映射已修keep区间，不能重新带回内部停顿。
- 对最终MP4的全长音轨重新扫描空白并逐处核销，不能只验证输入候选表；声学静默超过0.25s的保留项须有本次实际复核证据，明确无信息的必须返回EDL修剪。核对候选总数=已剪并复核+有依据保留+误报，所有必剪区间在实现后的时间轴中确已移除（允许已记录的帧量化与发音保护余量）。状态字段变PASS但音轨仍有应剪空白，判FAIL。
- 前五秒逐字精修并单独听审，之后连看前十秒确认承接：没有确认的啰嗦、错误、重复、准备声和犹豫停顿，不能把整体1.1倍速当作已精剪。全片每个保留段都查词内两字间的异常停顿，不只查句间；保留自然浮动和必要发音，听感连续，不像逐字拼接。
- 在本次剪辑范围内不保留确认的口误、需剪气口、卡壳、残字或重复起句；“只剪长气口”不等于删掉所有自然呼吸。重点复听所有危险切点及重说区间；整段 ASR 可能合并重复句，要用独立短片段转写/波形辅助，不能只检查全文转写。
- 字幕逐字对应保留的原声，允许正常标点与书写规范；不增加原声没说的完整句。专名、数字、否定词重点核对。
- 复查完整成片稿中“来去、那个、重复问句、同义绕圈”等具体冗余候选，以实际功能决定；确认无信息的必须已删除。每条问题ID关联EDL和最终核对记录，字幕改字不能充当原声剪错。
- 没有错轨、双重旁白或回声；插入视频静音，配乐/音效只有用户要求才加入。检查切点爆音、噪声处理金属感、语速自然度和响度。

## 实际成片画面

检查预览后，仍从最终MP4抽查开头、已启用的标题退场边界/最长字幕/卡片时段、低头近景与恢复位置、所有风险切点及结尾。以下只检查本次启用的层，不能为了满足验收而添加用户未要求的包装。

- 标题为真实粗字重，首10秒左右可见，内容完整不裁切；字幕位置符合参考/截图，普通白字、重点黄字，字体family统一、静态出现。
- 逐页检查实际渲染字号、字重、字距、横向比例、描边/阴影均一致，不能只检查config；长句以一/两行或分页显示，数字及标点规则稳定。字号随句长改变即FAIL。
- 字幕容器有固定基准区和底部锚点，多数页面位置稳定；单双行不重算整体中心，字幕不压嘴。仅少量连续镜头避让，记录例外次数、持续范围及恢复点。多数页面偏离基准或逐句跳位即FAIL，重新布局；不能把历史避让秒数复制到新片。
- 卡片数量核对用户指令：未强调卡片必须0；明确加卡片必须整条1–3，语义时机正确且足以读完、不遮脸。顶部标题/独立封面不算卡片，无要求外的转场、特效或短音效。对照版只有约定层不同。
- 按EDL映射同一源时刻，在相同显示尺寸和色彩管线下比较正常观看与100%细节：眼镜、发丝、皮肤/衣纹、背景字、暗部和运动边缘不出现新增模糊、涂抹、色块或锐化白边。清晰度不得弱于原片，失败回原片重导出。记录对照位置和实际观察，分辨率/码率/CRF都不是清晰度证明。
- 开拍前后对照至少覆盖正常光、逆光/高光和运动处；肤色、白衣/灰物、背景、字幕分别检查，不能用整画面亮度均值替代人脸观察。字幕不得被修复模型改字、涂抹或变色；眼镜、发丝和脸型不得扭曲。API 返回成功与4K分辨率不等于美颜通过，需记录实际观看与用户审核状态。
- 封面按本次约定的版式检查；安装了 `yl-short-video-covers` 时读取对应模式指南；单独安装剪辑工具时按本次封面约定执行。批准后保持原文件及哈希。

保存EDL、字幕、视觉配置、导出命令/日志、保护基线、技术JSON、关键帧和联络表；说明本地文件完成及用户审核状态，不能等同于已发布。

## 成片文字稿归档

按 [成片文字稿归档](final-transcript-archive.md) 提供完整TXT/MD，校验与最终口播一致，并关联成片版本。用户明确授权同步并指定目标后，完成云端标题/全文去重、笔记回读与知识库归属核验，以及适用的本地仓库正式收录和派生更新。技术视频验收PASS不能代替归档成功；本地导出、云同步、本地入库分别记录状态。
