# 成片完整文字稿与同步入库

每条最终成片都导出完整文字稿。云端同步或本地内容库入库仅在用户明确授权并指定目标后执行；确认视频不自动授权写入其他系统。

## 生成可下载的完整稿

1. 从**最终版本、已核对原声的字幕/剪后逐字稿**按实际口播顺序还原完整正文。字幕不存在时转写最终成片并核对声音/EDL，不用未剪原片稿替代。
2. 仅补正常标点和可读段落；不做摘要、重新润色、增加原声没说的话，也不混入标题、封面文案、重点卡片、剪辑说明和本地路径。保留正确的重复强调、数字、否定词及个人措辞。
3. 与MP4同目录导出版本化 UTF-8 `片名_成片文字稿_vN.txt`（纯正文）和 `.md`（标题＋完整正文）。同时保存独立manifest：标题、版本、成片路径/哈希、字幕/EDL来源、正文哈希、字数、审核状态和后续入库ID。
4. 去除标点/排版后，逐字校验正文与最终字幕拼接一致；抽查原声中数字、专名、开头和尾句。不能用这一校验替代已有的字幕与音频核对。
5. 有卡/无卡或其他纯视觉版本共用同一份口播稿，在manifest关联全部版本；正文完全相同不创建两份内容资产或两条云笔记。若后来实际改了口播/字幕文字，则保留旧稿，生成新版本。

成片尚未通过时，可随待审视频提供本地稿并标记待审，不宣布入正式库。用户明确要求此稿入库并指定目标后执行下面流程；“不要同步/只留本地/仅更新Skill不补录本片”等本轮限制优先，不重复索要已经给过的授权。

## 可选笔记同步（需指定目标）

若用户选择 Get笔记且环境有对应工具，读取 save、knowledge、list 等所需 API 说明；选择其他服务时按该服务文档映射相同的去重与回读步骤。凭据从已有安全环境取得，不写进Skill、正文或日志。

- 每次实时分页解析**当前用户指定**的知识库名称，不要固定旧topic_id；同名歧义无法依据现有上下文解决时才询问。
- 按完整标题和全文去重。完全相同则复用；同作品的已确认plain_text旧稿可按版本规则更新；无法确认同一作品时另建带日期/版本标题，不覆盖其他资料。写入超时结果不明时，先重新查询去重再重试，避免重复创建。
- 同步内容只包含最终口播正文；标题用独立title字段。类型为 `plain_text`。不上传原始录音、未剪转写、视频、封面、manifest、字幕时码、证据或内部说明。
- 创建/更新后，将API返回的字符串note_id加入实时解析的topic_id。回读 `data.note`，核对标题、全文、类型，再分页验证知识库成员关系；有缺项就记录未完成，不把创建成功当成入库成功。
- 在本地同步manifest记录note_id、topic_id、正文哈希、回读/归属验证与时间。只提供本人笔记内链，不自动创建公开分享链接。

## 本地文案仓库

只使用当前用户指定的本地内容库，先读其适用规则（如 AGENTS.md、SOURCE_OF_TRUTH.md、README）再执行现有入库流程。目标未配置时只保存视频旁的文字稿，不自动搜索或写入其他私人目录。

- 符合目标内容库范围的已确认成片稿，去重后正式进入相应平台作品目录；保留完整正文，并建立稳定asset_id、来源、审核状态及平台版本关系。没有发布证据时仍为已确认未发布，不能伪造publication_id/数据。
- 中央正文是后续编辑真源；视频成品目录的TXT/MD为绑定对应成片版本的交付快照，manifest记录中央asset_id/路径。两份用途不同，不维护两套可随意改写的真源。
- 被目标内容库范围规则排除的内容不得强塞入库；使用当前任务已指定的对应项目库，目标不明时先保存本地成片稿并询问准确目标，不阻塞已授权的视频交付。
- 需要云镜像、正式提升、版本关联、知识原子、表达资产/金句/比喻/递进链及统一知识网络更新时，调用仓库已有流程完成当前新增稿的全链验收。只复制文件、只做云镜像或只加一条索引不能称“正式入库完成”。
- 本任务是当前成片稿的定向归档；不因此启动全部历史笔记/视频的全量同步、不重剪其他视频、不操作发布平台。若流程暴露无关历史待处理项，记录范围边界，不让它们冒充本条已处理或扩大本条授权。

## 交付与状态

分别报告：本地完整稿已导出、Get笔记已回读验证、本地中央库正式收录及所需派生更新。哪一项失败就准确列出该项，保留可继续的ID/版本，不说笼统“全都同步了”。交付时给完整TXT/MD链接，并关联已验证笔记内链或中央正文路径。
