# 从源片建立可执行剪辑方案

每条视频单独完成本流程。输入是已有录音、画面和本轮编辑要求，输出是能与源片及实际成片对账的编辑决定。共用包装设置的批次也逐条检查内容。

## 确认源片和批准状态

记录源文件哈希、源时长、时间原点、逐字稿版本和实际读听范围。原始 ASR 单独保留，校对稿另存。音频听不清、转写缺段、专名与数词不确定的位置保留时间锚点，按 [转写覆盖与成片复审](final-review.md) 补查。

沿用主 Skill 已确定的全自动或半自动模式。半自动的批准稿、本轮删词范围和用户已锁定的排序进入工作记录。局部修音、换字幕样式或归档的任务按各自授权操作。执行修订时同时使用 [回改约定](revision-contract.md)。

## 建立源片中的依赖关系

通读完整校对稿并对应画面，以自然语义段记录源起止时间、原话位置和必要上下文。判断一段能否独立使用时，检查它引用的人物、对象、条件、前文观点及画面指示。

例如合成源片先说“这个办法在有备份时才适用”，后面才说“可以恢复”。若只保留后一句，适用条件会丢失。另一个合成片段先展示接线位置，再说“这根先断开”，则画面和话语需要一起保留。验证样例只演示依赖关系。

把本片要表达的主要判断及支撑段落记清，保留原因、案例、反例、代价、条件和有效强调。素材本身只有短观点时按其实际内容处理。出现演示、白板或指物动作时，核对相应画面在输出中仍可见。

## 从问题形成一项操作

每个修改项至少登记原句或声音、源时间、具体原因、操作、保留边界和复查结果。

| 操作 | 可执行条件 | 执行后的核对 |
| --- | --- | --- |
| 选取一次完整表达 | 源片中存在重说或失败起句，已经确定可用版本 | 选中的版本含完整条件、词首和尾音 |
| 删除词或语义段 | 本轮允许删除，且删除范围已定位 | 前后原声能接续，主张、否定和数词保持正确 |
| 缩短无声间隔 | 已分辨思考停顿、气口、重音与环境声 | 按实际听感及停顿策略保留容差 |
| 移动完整片段 | 移位能解决具体理解问题，依赖的上下文可一并保全 | 原位置处理正确，新连接及画面成立 |
| 保留 | 该处承担论证、演示、情绪或表达作用 | 记录具体作用，仍检查段内口误和切点 |

转写错字先通过原声核实，再修转写。说话人真实说错时，从原片中寻找正确表达，或评估安全删除的最小范围。需要补录才能成立的地方登记内容缺口。字幕按真实保留的原声生成。

重复检查覆盖段落和字词。相同观点再次出现时核对有没有新增解释、程度或有效回扣。确认无作用的重复、残字、重说和失败起句要落到实际删除记录。原段需要保留时，继续检查其内部犹豫和词间停顿。

问题按实际影响安排处理顺序。改变立场、破坏因果或使承诺失据的操作先修正，用户点名的细小字词也应逐项处理。暂时无法修复的项目保留未解决状态。

## 选择播放顺序和起点

先把原始顺序作为可比较方案，随后检查本片是否有需要前置的真实片段。候选要带源时间、完整原话、依赖段落和声音边界。比较它们在当前任务中让观众多理解了什么，以及带来了哪些新连接。

记录最终选择及原因。维持原序时写明现有推进怎样成立。调整顺序时登记每次移动、原位置去向以及最终完整逐字稿。通常移动已存在的片段一次，是否重复播放由本片明确需求决定。

分别读听新起点及它接下来的内容。开篇对象应可辨认，判断有原片依据，后续保留内容能够展开它提出的问题。标题与封面文字从最终保留的内容提炼，数量、效果和限定与正文保持一致。必要术语随其已有解释保留，目标人群由本次用途决定。

在最终输出时间的前五秒逐词检查失败起句、重复、残字、犹豫、尾音和剪接边界，登记实际动作与复查。已有好开头仍完成这项检查。整体变速在结构和停顿处理之后按本次要求一次应用。

## 由记录落实到 EDL

源时间用于定位原片，输出时间用于检查结果，两者分别记录。每个已决定执行的删除或移动关联实际 EDL 条目。保留区间覆盖正确词句与音素保护范围。需要帧量化时双向核对量化前后边界，确认删除项和保留项都得到落实。

根据实际执行后的 EDL 重新生成顺读稿和时间映射，检查每个新连接。对照标题、字幕、插图和 B-roll，确认它们对应当前成片。字词级精剪按 [剪辑工作流](editing-workflow.md) 执行，B-roll 按 [插入工作流](broll-workflow.md) 执行。

内容记录至少包含以下信息，可用一个 Markdown 表或等价 JSON 保存。

| 字段 | 内容 |
| --- | --- |
| `source` | 文件与逐字稿版本、时间原点、核对方式、未辨认范围 |
| `core` | 本片主要判断、用途、重要限定和原话 |
| `paragraphs` | 语义段及源时间、原话定位、支撑关系和画面依赖 |
| `issues` | 具体问题、操作、保留边界、原因及未解决状态 |
| `opening` | 原始起点、实际候选、最终选择、前五秒逐词复查 |
| `orderDecision` | 原顺序与最终顺序、选择理由、新连接检查 |
| `execution` | 编辑决定关联的 EDL、源时间、输出位置和实际复查 |
| `claims` | 标题与开篇的事实性表述、保留段依据、适用条件 |

`content-analysis.md` 仍是可用的项目记录文件名。已有 JSON 的 `bodySupport` 和 `contentFiveDimensions` 字段继续留在历史记录中。续作时读其事实依据并补入当前操作记录，避免为升级格式丢弃旧审批或执行状态。

## 输出验收

核对源片的关键意思和必留句，确认每个应执行的修改都在最终文件中生效。语义完整、实际剪接、字幕、声音听感和技术检查各记证据。波形、ASR、解码成功分别只证明其检查范围。主观听审仍按 [验收规则](acceptance.md) 完成。

未完成项写明具体位置、影响和所需材料。已执行的修改与待确认项分别保存，后续续作从实际状态继续。清理过程文件前按归档约定保留自包含审查依据。
