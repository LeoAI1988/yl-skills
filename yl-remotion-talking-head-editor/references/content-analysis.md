# 每条必做：全文逻辑、开头与内容诊断

本文已经把 `dbs-script-flow`、`dbs-hook`、`dbs-content` 中适用于真人口播的诊断方法合并进本 Skill。**每一条视频都必须执行三个模块，并留下逐条证据和剪辑动作；无需另行调用这三个 Skill，也不以用户再次提及 DBS 为条件。** 批次共用风格配置不等于完成了每条内容分析，不能复制一份空泛结论作为六条视频的分析记录。

诊断的对象是整条已录制原片。用户的原声、措辞、观点、论证链和真实画面是编辑边界；本流程决定如何从已有录音中保留、删除、压紧和必要时调序，不把剪辑变成代写、补录或配音。需要字词级切点、停顿容错和声学检查时，继续执行 [剪辑工作流](editing-workflow.md)。

## 1. 输入与全文结构图

在决定开头和删除任何实质段落之前，先阅读完整逐字稿，并核对原片：

- 保存带源时间的原始 ASR，再另存经原声核对的逐字稿；专名、数词、否定词、量词、限定条件和含混区间必须有标记。字幕纠错不能算作剪掉原声口误。
- 按话题和论证功能划分自然段，记录段号、源起止时间、原话、主题和功能。功能包括开场、背景、定义、论证、案例、因果解释、转场、强调、结论和结尾行动。
- 写出该片的一句话核心观点、实际服务的受众/问题，以及“观点 → 依据/解释 → 例子 → 结论”的依赖关系。没有的环节不虚补；它可能是简短观点片，不能因篇幅短强凑结构。
- 看原画面判定表达形式：纯口播、白板、操作演示或含实际指物动作。与画面配套的“看这里”“这一点”不能仅因文字上像赘语就删；每个指代都要有保留画面或上文可指向。
- 分开记录“原片确实说错/重说”和“转写识别错误”。无法辨认的声音不凭上下文猜成确定原话；先局部复核，无法恢复时记录可用范围与影响。

## 2. 模块一：逐段逻辑延续、信息密度与口播流畅

本模块内化 `dbs-script-flow` 的全部三个诊断维度。必须覆盖全部段落与每一对相邻段落；选中调序方案后，再检查新的相邻关系。

### 2.1 相邻段落的逻辑衔接

逐对引用上一段末句和下一段首句，回答：

1. 听完上一段，观众能否理解为什么接下来讲这一段？二者是因果、递进、对比、举例还是转场？
2. 是否从 A 跳到 C，缺少 B；是否从个案突然升到宏观，从数据直接到观点，或前一话题尚未收束就转入新话题？
3. 缺失的具体信息是什么？原片哪一处已经说过，是否可以保留或移动这一真实原声来修复？
4. 删除后，代词、转折、时间顺序、否定范围与前提是否仍成立？

可执行修复依次考虑：保留被误判冗余的论证或解释；恢复必要上下文；移动原片中已有的承接/收束语；调整完整语义块顺序；删除确实无关且不影响主线的支线。**原片没有的过渡句不得现写后冒充原声，也不得靠字幕新增一句话掩盖音轨逻辑断裂。** 无法以已有素材接顺时保留更完整的原序，或记录无法靠剪辑解决的缺口。

### 2.2 段内信息密度

逐段回答：这段新增了什么；是否换三种说法重复同一个意思；是否已经足够说明却继续堆例子；是否用多句话绕圈；删掉后观众是否会失去关键依据、限定、反例、情绪转折或可理解的具体含义？

- 无信息重复、空转解释、口误后的失败版本、未完成起句和无功能赘语必须形成删除动作，只保留表达完整、准确且有力的一次。
- 合并冗余的意思是从已有原声里选取必要段落或句子，不是把几句话改写成一句未录制的话。
- 删段前必须回答：“没有它，观众能否理解前一个关键判断具体指什么、为什么成立？”不能回答时，先把它视为必要论证，不能按话题表面不同判跑题。
- 有功能的反复（递进、对照、结尾回扣、修辞强调）和用户的口语风格可以保留，但要记录它新增的作用；“尊重原话”不能成为保留无信息啰嗦的理由。

### 2.3 句、词、字层面的口播流畅

逐句扫描长句、书面绕句、嵌套定语、生造术语、术语解释缺位、连续自问自答、连续长句过闷或短句过碎。超过约 30 字的单句是复查线索，不是自动删除阈值。

在已经录制的语音里，以源内可实现的动作修复：删去不承载意思的套语/重复词，保留完整主干，恢复已有解释，移动完整解释段，压缩思考停顿，选择自然重说的正确版本。不能把所有自问自答、长句或有个人特点的表达机械判错。

**每一个保留段也必须检查内部的词、字级口误、残字、拖延和犹豫间隙。** “段落逻辑正常”“整段 ASR 读起来顺”不能替代原声精修。声学切法、容错区间和连续听感按 [剪辑工作流](editing-workflow.md) 执行，不只剪句间长空白。

### 2.4 风险等级与证据

每个问题至少保留问题 ID、源时间、原句、具体影响、风险级别和拟执行动作：

| 等级 | 使用条件 | 后续处理 |
|---|---|---|
| 高 | 逻辑断裂、主张/否定被剪反、未兑现开头、严重信息重复或明显说错 | 先解决，再锁定 EDL；无法解决就明示缺口，不能判内容验收通过 |
| 中 | 承接不顺、无信息赘述、连续绕句、干扰理解的词间犹豫 | 必须给具体动作并复查；确认无信息的重复或口误仍必须剪，不因等级为中而选做 |
| 低 | 可保留的修辞/措辞或细微节奏差异 | 写明保留或调整理由，不为制造改动强行剪碎 |

高风险优先，但低等级不能掩盖用户明确要求处理的错话、重复或冗余。不得仅写“建议可删”后仍原样导出。

## 3. 模块二：内容支持与前五秒开头诊断

本模块内化 `dbs-hook` 的内容检查、六维开头诊断与候选比较。先看整片能提供什么，再选择开头，不能用夸张标题或无关抓手包装支撑不足的正文。

### 3.1 正文价值与素材支持

先确认正文实际让观众获得的判断、解释、案例、做法、体验或感受。检查已有录音里的五类素材：数据/结果、前后转变或反差、可独立成立的有力原话、可追溯的经验/权威依据、与受众有关的具体痛点。

对每一类记“有/无、原话和源时间、可支持什么”，不能编造数字、经历、背书或素材。被说出的事实不等于已独立核实；实质可疑说法应单独标记，不能增强成更确定的承诺。五类只是寻找可用抓手的维度，不是必须集齐的清单；不足 200 字或没有大数字不构成停止剪辑的理由。

检查受众范围：哪些词过早缩窄了理解范围，领域外的人能否听懂，目标受众为何关心。优先清除原片里的无关门槛和含混指代；不得为了泛流量删掉视频必须服务的具体人群、条件或业务问题。

### 3.2 当前开头六维诊断

对原始开头及最终候选逐项判断，并引用源时间和原话：

| 维度 | 必答问题 |
|---|---|
| 独立性 | 不看标题和封面，能否知道在讲什么？是否以“这个”“所以”起句却缺少对象/前文？ |
| 抓手 | 前五秒是否出现值得继续听的结果、反差、问题、具体判断、场景或利益关联？有无铺垫、招呼、试音、失败起句占掉有效时间？ |
| 悬念/继续观看理由 | 是否留下需要正文解释的问题或因果缺口？即使直接给出核心结论，是否仍有足够强的证据、解释或执行价值让人继续看？ |
| 可信度 | 原片提供了什么经验、观察、具体细节或证据使这句话站得住？是否删掉了关键限定而变成夸大？ |
| 口播友好 | 是否能直接听懂，是否有抽象套语、拗口词、连续自问自答、犹豫、错字、重说或残字？ |
| 正文兑现 | 开头建立的问题和承诺，后面具体哪段回应？删减后是否留下了未兑现预告？ |

“留悬念”适配为必须检查继续观看的理由，不强行把所有结论改成问题。已录制的清晰、可信且正文有解释价值的直述开头可以保留，不编造问句，不强行套反转公式。

### 3.3 源内候选与选择

- 先保留原始开头为候选 A，再从原片寻找真正可用的替代：结果加反差、数据、变化、金句、具体经验/观点、痛点加问题。按内容匹配和声音完整性比较，不套固定优先级。
- 有有效替代时通常比较 1–3 个源内候选；没有可用替代时记录“已检索哪些段落、为何不能前置”，不为凑数制造 10–15 个未录制开头。
- 每个候选写源时间、原话、前五秒实际可说出的内容、六维判断、所依赖上下文、正文兑现位置及剪辑代价。
- 若前置后段，默认是移动真实语义块；检查原位置是否需要删除以免重复，必要衔接是否仍在，人物动作与指物是否合理。不要默认复制一段做固定三秒冷开场。
- 写明胜出理由。原开头已最好就保留，仍要执行前五秒逐字精修；内容选项不变不代表精修可以跳过。

前五秒是强制重点：根据最终输出时间，单独核查每个字、词、失败起句、重复、思考停顿和剪切边界。不得用 1.1 倍整体加速替代这一检查，也不得剪去必要辅音、词尾或表达重音以追求无声间隙为零。

## 4. 模块三：内容五维诊断在原片中的落实

本模块内化 `dbs-content` 的五维方法。每个维度必须写出证据、结论与本片动作；形式已由原片和用户任务确定，不另设“有产品/付款链接”前提，不扩展为平台运营任务。

| 维度 | 已录制真人口播的必查内容 | 可执行结果 |
|---|---|---|
| 文字洁净与可理解性 | 原话是否具体可理解；是否有空泛排比、晦涩套语、术语无解释、错误、重复、无信息套话；不要把“像 AI”当作删除用户表达的证据 | 定位到原句/词和源时间；删无功能部分，保留能说清的正确版本；原声无法修复的说法单列 |
| 封面/标题与内容匹配 | 平实表述是否已经显示内容价值；标题的核心情绪/信息是否来自正文；文字与画面层级是否帮助理解；是否承诺了成片没有的内容 | 从已保留原话和主旨提炼准确标题/封面文案；服从本轮包装范围，不为补救薄弱正文加夸大标题 |
| 表达效率 | 能否用一句话概括主张；每段是否在推进；是否花过多篇幅铺垫微小信息；是否服务本片受众和用户目标 | 对无信息冗余形成删除项；保留必要前提、论证、案例、商业限定和结尾，不能只按压缩比例决定好坏 |
| 认知落差与新增价值 | 观众原本可能知道什么，本片新给了什么解释、机制、反例、案例或判断；若有已提供的对标，具体差异在哪里 | 把原片已有的有效区别讲清并放在合适位置；没有对标证据就标“未比较”，不虚称优于同行、不为制造反常识扭转观点 |
| AI 辅助与实现边界 | 观点片是否保留自然语气；分析片是否保住证据和逻辑；工具片步骤是否完整；哪些问题可通过已有素材编辑解决，哪些只能靠补录/新增证据 | 将 AI 用于对齐、定位、候选比较、EDL和检查；不代造原话/案例，不擅自补录/配音/改写。把不可由剪辑解决的问题作为明确限制，继续完成可执行部分 |

另作一次形式承载检查：深度分析与长论证不能为了“短视频”强压成固定秒数；操作/清单必须保留可理解步骤；人与语气承担说服作用时避免碎切削弱表达。此判断用于决定保留长度和结构，不擅自把视频任务转为文章、直播或图文。

## 5. 明确决定是否调序，再将结论落实到 EDL

每条必须有 `orderDecision`，只能是“保持原序”或“调整顺序”，两者都需要依据：

1. 记录原始段号序列、核心依赖，以及三个模块发现的问题。
2. 考虑有实际价值的源内调序/前置候选；逐一比较开头独立性、论证完整性、信息推进、声音切点和画面可接性。不因流程要求而强行调序。
3. 选择最终段号序列。保持原序时说明原序为何最清楚、替代为何无收益或有损；调整时写明每个移动片段的源时间、理由与原位置处理。
4. 按最终顺序再读一次完整成片逐字稿，检查每一个新连接；必须保住否定、数词、限定、主语、指代、前提、因果、引用归属和时态。
5. 所有确定的错话、残字、重复、失败起句和无信息冗余必须有 EDL 删除/选取动作；仅写报告、改字幕或整体加速均不算落实。

优先保留正确而完整的一次表达。只有一个错词且原片没有可用正确说法时，先判断能否安全删词；不能时删到最小的完整语义单元并复查论证。不能为了完成“剪错字”而拼出说话人没说过的意思。若删掉会使核心论点无法成立且原片无恢复办法，明确记录该内容问题尚未解决，不能把它标成通过。

## 6. 每条最小分析记录与完成判据

每条工程留一份 `content-analysis.md` 或等价 JSON 即可，无需另建大量表单。必须包含下列字段/内容，允许用紧凑表格合并：

- `source`：视频 ID、源路径/哈希、逐字稿路径/版本、核对方式、未辨认范围。
- `core`：核心观点、受众/问题、实际表达形式、关键语义和论证依赖。
- `paragraphs`：段号、源起止时间、原话位置、主题、功能、新增信息；每对相邻段的承接判断。
- `issues`：ID、所属模块/维度、风险、原句/字词、源时间、依据、决定、预期 EDL 动作与复查状态。无问题时也要给覆盖范围，不能只有一个空清单。
- `bodySupport`：正文价值、五类素材的有无/源位置、开头兑现位置、不能夸大的限定。
- `opening`：原开头六维结果、源内候选及取舍、最终前五秒逐字精修记录。
- `contentFiveDimensions`：五维各自的证据、结论和动作；不适用的局部细项须说明原因，不能跳过整个模块。
- `orderDecision`：保持原序/调整顺序、原序/候选/最终序列、选择理由、依赖与新连接复查。
- `execution`：每条必剪项关联的 EDL 片段或删除 ID、源时间、输出位置；实际执行/未解决状态，以及原声听看复查结果。

**完成判据：** 三个模块全部覆盖该片；是否调序已作有证据的决定；必剪问题全部落入 EDL 并在最终输出复查；前五秒单独逐字精修；最终稿仍保持用户原意；未解决的问题如实留档。只有分析记录、只有转写校对或“技术验收通过”均不能算内容精剪完成。最终成片的主观听审与技术验收另按 [验收规则](acceptance.md) 完成，不能由 ASR 或波形检查冒充听审。

## 内化来源与适配说明

方法来源为 dontbesilent 的 `dbs-script-flow`、`dbs-hook`、`dbs-content`。这里保留归属及适用于已录制口播的内化方法，不依赖安装者另行调用来源 Skill；上游更新不会自动改变本文件。

| 来源 | 已内化的方法 |
|---|---|
| `dbs-script-flow`（v1.1） | 段落功能、相邻承接、密度、句级口播流畅、风险原句证据、白板语境、论证肉与冗余区分、保留原稿与修改记录 |
| `dbs-hook` | 内容先于开头、素材五类与受众范围、开头六维、素材提取/候选比较、明确推荐及正文兑现 |
| `dbs-content` | 形式承载检查、文字洁净、标题封面、表达效率、认知落差、AI辅助实现的五维诊断及具体动作 |

适配范围：把未拍摄稿阶段的“加过渡/补素材/改写”改为源内保留、选择、调序及缺口记录；把开头的大量生成改为真实可实现候选；把绝对悬念公式改为有证据的观看理由判断；把标记式改稿改为保留原稿与源时间/EDL可追溯的变更记录；把形式/AI工作流建议改为当前原片的承载与实现检查。未引入付款链接门槛、字数门槛、无关商业断言、平台迁移、导流、原 Skill 的单次调用触发条件或剪前重复确认。这些是已录制真人口播剪辑的适配，不是省略诊断。
