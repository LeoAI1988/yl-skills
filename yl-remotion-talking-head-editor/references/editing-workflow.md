# 原声、逻辑与紧凑节奏

## 执行纪律（2026-09-14，遵循入口首要约束）

按 [SKILL.md 模式选择与首要执行约束](../SKILL.md) 先确定本次工作模式，再建立逐片清单并实际核销。新剪辑任务未指定模式时先问用户选择“全自动”还是“半自动”，不能把“开始／剪一下”默认为全自动；本次任务已经选定的模式跨轮沿用，用户修改时才切换。仅修改 Skill、回答问题或只读审查不触发剪辑模式选择，也不启动视频处理。

- **全自动**：执行者自主完成结构、正字、删留、停顿与剪辑审核，然后完成本次范围内的开拍增强和最终验收；不索要中间意见，不交候选、待办或未完成的中间版代替最终结果。
- **半自动**：先一并提交本次所有视频的完整逐字稿修改方案；用户确认逐字稿后，完整执行剪辑并交付“已剪完、未开拍增强”的视频。用户确认剪辑版后，才调用开拍 API 增强并验收最终成品。
- **两模式都必须完成停顿处理**：停顿定位、声学复核和剪切由执行者自主完成，不把明显空白或可自行解决的切点留给用户决定。半自动的两次用户确认针对逐字稿方案和完成的剪辑版，不能作为停顿未剪的理由。未完成项须继续处理，主动说明未完成不能代替执行。

## 开拍链路的色彩检查

按 [开拍画质增强](kaipai-enhance.md) 检查原片、API 输入、原始输出和成片。HLG 原片若遗漏 tone map，可能在输入阶段就出现 HLG 传递函数与 BT.709 矩阵混杂；不能未经核实便把问题归因于 API 输出标签。

必须从原片按原 EDL 重新转换，再叠原字幕。不能给错误像素强贴 BT.709，也不能对已叠字的坏成片整帧 tone map。仅当转换记录、同帧像素和输入基准共同证明像素已是正确 SDR 时，才允许单纯元数据修复；修后同时核对码流、解码帧与 MP4 `colr`，不能只改 SPS 却留下冲突的容器标签。

## 渲染/导出假成功陷阱

- **已有文件不能证明本轮渲染成功**：历史调用曾在输出已存在时仍被外层判完成。不要只靠退出码或 `RENDER_COMPLETE`；使用新的版本化输出路径，核验实际文件和本轮 EDL。不得为了通过存在性检查删除旧成品。
- 假成功排查姿势：看输出文件的 **mtime**（不是结果 JSON）+ 抽帧内容验证。字幕与画面错位/内容是上一版时，第一怀疑对象就是输出没真的重渲染。
- 导出产物校验三件套：`nb_frames`/解码计帧 == EDL `outputFrames`、时长与 build_summary 一致、抽帧（首/中/尾）核对字幕内容。最终帧数/时长以 [验收规则](acceptance.md) 严格核验；API末包差须通过专门全包证据，不能用通用±0.15s放行。

## 结尾金句复制到开头（headHook）的正确做法

需求：把成片结尾的金句段**复制**一份到开头当 hook（结尾段仍保留）。要点：

1. **spec 层**：`spec_v2.json` 加 `"headHook": {"sourceStart": <s>, "sourceEnd": <e>}`（源时间区间）。build 端：先把全部删除与停顿落实到修后 keeps，再取这些 keeps 与 hook 源区间的交集（可有多个片段）按序插入 merged 最前，逐段标记 `hook: True`；禁止直接把未修的完整 `(sourceStart, sourceEnd)` 插回；`map_time` 加 `hook` 参数区分同一源区间的两次出现（hook 页只映射 hook keep，原块页跳过 hook keep）——**不加区分会把结尾段字幕错误映射到开头**；hook 块的页在开头再产出一份；文字稿 body 开头拼 hook 文本。
2. **export 层**：skill 的 `validate_edl` **明确拒绝乱序 keeps**（"reordered hooks need a trim/concat timeline renderer"）——hook 模式不能走 select 单路，需自行校验（帧数守恒 outputFrames ≈ Σkept/rate）+ **trim/concat 滤镜**：按输出序把 keeps 划分为若干「源升序段」（源区间回跳处断段），输入流 `split=N` 供各段 trim+select，段间 concat。同一源区间出现两次（hook 与原段同帧区间）是常态，段划分算法必须容忍。
3. **overlay**：captions/manifest 天然按输出时间线（hook 页 0 起），与重排后的视频轨自动对齐，无需改 Remotion 组件。
若使用按语义 block 构建的生成器，hook 输入应覆盖一个或多个完整语义 block；block 内已确认的停顿仍会被剪掉。若要截取 block 中半句，先按真实词界把 spec block 拆开并重算页文本，或使用支持该范围的重排渲染器，不能猜切字级时间或让画面有 hook 而字幕/文字稿漏掉。完整多 block 的 hook 字幕与文字稿都应按全部前置片段拼接，不能只取第一块。

4. **禁止渲染后二次拼接**：那会对已编码成片再做一次有损编码，违背一次编码原则；重排必须在导出时间线内一次完成。

## 审查稿规范（GATE-1 交付物，2026-09-14 双模式）

审查稿**只管文字与结构，不把停顿决定转交用户**。半自动必须在第一次确认前，一并提供本次所有视频的方案，每条均含以下两个完整部分，不能只交摘要、局部建议或擅自先剪其中一条；用户明确拆批确认或指定先做某条时按其范围继续。全自动也须完成同样分析并内部留档，审核后直接继续。两个部分，不做多余表格与时间戳：

1. **原始逐字稿**：转写结果如实全文呈现，包括所有语气词，一字不改、不概括。
2. **调整标记稿**：同一份全文上加标记——
   - **删掉的词/字/句**：直接 ~~画删除线~~；
   - **调整顺序的句子**：加粗并以 `[前移自第X句]` / `[后移至XX后]` 标注来去处；
   - **ASR 识别文字修改与字幕正字**：用行内 `[原识别“X”→改为“Y”；依据：…]` 标出所有修改，包括专名、数字、同音字及书写规范，不只列少量示例。文字纠正不动原声；真实说错需剪切时另标为删除，不以改字幕掩盖口误。

**纪律**：半自动由用户确认整批逐字稿方案中的顺序、删留和识别文字修改后进入剪辑；剪辑版须已完成停顿精修且未调用开拍 API，第二次用户确认剪辑无误后再增强。全自动由执行者内部审核后连续完成剪辑与本次范围内的增强。两模式均按下方紧凑策略自主完成停顿声学复核与剪切，停顿不增加用户确认环节。半自动指定的两次确认不得擅自改成内部审核。

## 词级虚词清扫清单（每篇必扫）

结构删除之外，逐字扫描以下虚词与垫词，能删则删、在标记稿中逐处画线：

1. **名词前的泛指垫词**「这个/一个」：删除后指代不悬空才删（「所有的这个高光时刻」「这么聪明的一个AI」「一个逐字稿」删；「这是一个巨大的鸿沟」「执行一个任务」等判断句/量词必需型保留）。
2. **系动词赘余**：「它是/他是/现在是+VP」的「是」（「现在是要拼命的」→「现在要拼命的」；删后不通则留，如「是有…的」强调框架）。
3. **强调性「就是」**：「它就是塑造了」→「它塑造了」（删）；连接性「就是+句子」（「就是你不用再去考虑」）保留。
4. **可省虚词**：「经过[了]+NP」的「了」；VP 连接处的「和」（「价值，和判断」→「价值，判断」；NP 并列如「经验和踩坑」的「和」保留）；「如何的+V」的「的」（「如何的使用」→「如何使用」）；「不断的+V」的「的」（「不断的沉淀」→「不断沉淀」）；「去X的去V」赘余（「帮我去自动的去记录」→「帮我去记录」）。
5. **同义单字堆叠**：「你的所有的经过，所有的经历」——「经过/经历」取一。
6. **句尾语气词按语气完整性判断**：删除后语气断裂的**保留**——通用语气示例：「无所谓的**呀**」的"呀"不许删，删了语气不完整；「我告诉你**啊**」的"啊"可删（删后"我告诉你"完整）。拿不准的由执行者局部复听并裁决，不停在待裁决清单。
7. **时效性检查（内容判断，与剪辑技巧无关）**：预告性/时效性内容（"马上会XX""接下来要XX"）若事件在成片时已经发生完毕，该段整体过时，整段删除并在审查稿注明"事件已发生"；先核实事件确已发生，不能仅凭日期推断。
8. **重复句判定总则（依据上下文功能判断）**：前后**递进关系**的句子一般**保留**（"喝水一样→呼吸一样""看着电脑→看着电脑屏幕""可以心算→完全心算"均保留）；前后**几乎一样只差一两个字**的句子，大概率是前面说的有问题、后面修饰了一下又重说——**删前面、保留后面**（"我想要什么→我想要什么结果"删前；"你只需要关注你想要什么/你的结果"删后句留前句语义完整版）。不相邻的远距呼应结构（开场抛出+转折后重申）保留。判断有分歧时继续核对上下文与原声，确认递进/呼应就写明作用后保留，确认无信息重说就剪除；不能仅以“判不准”批量保留或留作未决。
9. **长音词漏检扫描（ASR 漏记重复，每篇必扫）**：ASR 可能把重复说的词组合并/漏记成一个长音词。异常长词可能包含被转写遗漏的重复短语。**所有词时长 ≥0.8s 的词必须用 source_48k.wav 能量剖面复查**：词内呈明显双峰/两个相似音节结构即为漏记重复，剪除前一遍；切点以音频定位（不信 ASR 时间戳），字幕侧用 replace 把被误记的短词替换成实际说的完整词。

**正字铁律**：ASR 同音错需结合原声、局部转写、上下文、热词表及可见产品名/界面帧补证，**禁止凭发音猜**；相近发音不代表含义相同，必须结合证据确定。有充分依据的修改直接标注并注明证据。半自动把仍需用户裁决的正字集中列入本次整批标记稿，在 GATE-1 一次确认；全自动由执行者继续局部复核并自主裁决，不另增中间确认，也不把“待确认正字”当最终交付。真实素材缺失导致无法恢复的内容须如实说明，不能编造词义或伪称已完成。

## 停顿执行规则（紧凑档）

参数真源是 [pause-policy.json](pause-policy.json)，当前档 `compact-v5-20260914`。普通无信息停顿总留白默认 0.10s，常规自然浮动为 0.06–0.15s；必要句间通常 0.15–0.20s，有语义理由的提问或强调可到 0.24s。默认值是工作起点，不是所有句子的强制同长，不等到 0.6s 才处理。停顿不进审查稿，由执行者在既有授权内自主完成声学判断，不逐处询问用户。

**下列数值一律是最终成片秒数**。以 rate 倍播放时，源秒 = 成片秒 × rate；例如1.1倍下0.20s触发对应源0.22s，总留0.10s对应源总留0.11s。写入 EDL 后按实际帧网格回算，30fps下0.10s约3帧，不靠多写小数假装有更高精度。

| 用途 | 当前标准 |
| --- | --- |
| 全片候选扫描 | 间隔从0.15s起全部列候选；词内及最终前五秒另扫0.12–0.20s |
| 普通无信息停顿 | 声学确认后，≥0.20s原则上收紧；目标总留0.10s，常规自然浮动0.06–0.15s |
| 小于0.20s的间隔 | 不自动豁免。词内、思考卡顿、前五秒明显拖慢处逐项判断；确认无信息且连接自然时也可收紧。已经连续、完整的发音不切 |
| 句间必要停顿 | 一般保留0.15–0.20s；提问/强调处有语义理由可到0.24s，不是每到标点就额外加一段空白 |
| 章节/有意义转折 | 原则上不超过0.30s，每处记录具体语义理由，不为“自然”笼统放行 |
| 成片技术兜底 | 检测到超过0.25s的声学静默须复核处置/例外；固定dB仅作辅助，不能证明词内没有迟疑 |

“总留0.10s”包含前后两侧余量，不能每侧各留0.10s，再叠固定80ms保护边。先找真实词尾、词头及必要的弱音/气音；可在声学静默两侧各留约一半，也可根据音节不对称分配。边界不足时优先完整发音，记录实际保留量，不机械切碎每个字或吞辅音。

执行顺序：全时长音频扫描（VAD/自适应能量，结合 ASR/长词内部定位）→ 核对真实发声边界和左右完整短语 → 自主裁决并写同一 EDL → 复听所有新切点及前五秒 → 对最终成片再次全片查漏。扫描必须覆盖 ASR 词段之外的空档，不能只检查已有字幕间隙。ASR 的词尾可能包含停顿；字幕持续显示也不代表仍在说话。明显无信息的长空白定位边界后直接剪切；有底噪不等于有口播，固定dB失效时继续用局部声学与听审判断。

每处记录候选来源、源/成片时长、决定、总保留、例外理由和复核状态。候选最终必须归为“已剪并复核／有依据保留／误报”，删除动作须在 EDL 和导出音轨中生效。`PENDING` 是执行者的未完成工作，不是用户审批；未处理候选不为零不能报剪辑完成。复扫检出超过0.25s的空档逐处核销，属于无信息停顿就返回EDL收紧；未触发固定阈值也不能替代全片听审。

复用旧批次生成器时，纯 ASR gap 只能进入 `pauseCandidates`；执行者须在同轮完成声学定位与连接复核，再通过 `pauseReviews` 的 `acousticStart/acousticEnd`、`confirmedNoInformation=true`、`joinVerified=true` 写入真实静默区间，并核查实际输出 keeps 已排除该段。只填字段、未改变时间轴不算执行。短于0.20s或调整保留目标时补充理由。没有实际复核就继续复核，不伪造确认值，也不把待处理版充作最终结果。词内、句间、内容删减以及前置hook都使用同一修后时间线，不能把完整hook再插回而带回停顿。

与词级删除、句级删除同一条 EDL 一次落齐，一步剪到位。参考片中的内容删除和局部变速属于该片编辑选择，不能算成停顿长度，也不能用新旧总时长比设置统一倍速。

## 先读完整内容，再决定切法

完整转写并校正专名、数词，保留带源时间的原稿。梳理每段服务的论点、因果、递进、例子和结论。优先删说错后重说、无信息重复、绕圈解释和容易使人失去兴趣的赘述，保留支撑判断的关键语义及个人口语习惯。

每条必须先完成 [内容分析](content-analysis.md) 中已内化的三项诊断，不依赖另行调用 DBS 或用户再次点名。输出每段功能、相邻衔接、冗余原句、开头比较、内容判断和逐项剪辑决定。原声与措辞是主干，不默认调用 human-writing 或其他改写 Skill。文字诊断不能只给建议，确认要删的字词/段落必须映射到源时间并落实 EDL。

顺序本来通顺就不改。确需前置，记录原声出处、前置理由、是否删除后面的重复片段，并检查代词/转折是否还成立。不要自动复制后段做固定三秒冷开场。

## 参考视频决定节奏

听本次参考的字间和句间停顿，用若干完整句估计典型范围，不用某一次吸气作为统一阈值；没有参考时使用共享紧凑策略并按本片发音校准。记录测量是在原速还是成片约 1.1 倍速下，不能混用。比较音节间的无信息停顿，不把每个字的发声时长变成一样长。

### 字词内部精剪：每条必做

1. **建立可核查的字词时间线**：转写保留源秒数、词/字边界和不确定区间。自动识别、强制对齐、VAD和波形只提供候选；不能将词级时间等分成字级后就声称已经达到逐字准确。专名、数字、否定词、轻声、词头词尾单独核对。
2. **扫描到字与词**：不仅检查句末气口，还检查词内两字之间的迟疑、拖延、重复音节、填充音和改口。定位每处“前一个字/词、停顿、后一个字/词”，听左右完整短语，区分思考停顿、必要发音间隔、强调及有信息的停顿。
3. **设自然浮动区间**：分别记录词内/短语间/句间的参考节奏区间和容差。采用上方共享策略的总留白目标，并按本片噪声和连续语音校准；语义转折按理由保留必要留白。处于自然区间的间隔不切，确认超长且无信息的部分缩回自然衔接。禁止按单一静音阈值或每个字固定时长批量切。
4. **清理错话与赘述**：错字/重复字词只留下完整正确一次；无信息绕圈保留最有力的一次表达。不能把“字幕改正确”当作“原声口误剪除”。源片没有可用正确说法时，判断能否删除整个错误短语而不损坏句意；不能凭空拼音节改造观点或补配音。仍不能形成完整表达就标注该处待解决，其他可做内容继续。
5. **只剪有问题的边界**：合并相邻可连续保留的区间，不给每个字单独生成切片。优先切无声/低能量边界，保护辅音、词尾和连读；高噪声下需要局部波形/声谱与短段听审，不能据底噪未降至阈值就放过迟疑。
6. **用真实精度落地**：以秒/音频采样定位候选，画面受原片实际帧边界约束。记录最终落点与定位误差，音画共用实现后的切点，误差通常不超过一帧；若会吞音就向保留方向调整。禁止把毫秒小数多当作真实精度，或分别剪音画导致累计不同步。
7. **双重复核**：每个高风险切点听前后完整短语，确认无残字、吞字、断音、爆音及重复残留；再整片听看连贯性。识别到一处残字时回查本条所有同类边界。不能以字幕文字相同或音轨哈希一致替代听感判断。

逐字逐词审核记录至少包含：源时间范围、左右原字词、问题类型、原间隔/保留间隔、删改理由、EDL 对应项、边界复核结果。不必为每个正常字单独建一行，但必须扫描全片，所有确认的问题都要有处置，不能只覆盖几处长停顿。

**两个起点工具**（`scripts/`，只出候选、不自动切割）：

- `word-audit.py --transcript <asr_raw.json>`：按段输出词级别表；`--rate` 为实际成片倍速，`--min-gap` 按成片秒设定，源时间仍原样显示；标出 `LONG`（词时长偏长）、`GAP`（与前词的间隙）、`P`（识别置信度低）与段间空档。`P` 低只说明识别不可靠，不能据此认定是口误。
- `pause-probe.py --audio <16k_mono.wav> --ranges "a-b,c-d"`：按区间做 10ms 窗能量，用第 25 百分位自适应噪声底给出低能量候选，并在动态范围过窄时打印“底噪高，判据不可靠”的提示。

两者都只回答“哪里可能有停顿”，运行结束后仍须完成上述剪切流程。**要删哪一段，必须同时满足两条**：拟删区间不切入经声学核实的真实发声（不机械相信ASR词尾）；删除后左右短语仍能连读。底噪高时缩小范围复核真实字音边界，保护必要发音后剪除无信息间隔，不因固定阈值没检出就放过整段空白。音频低采样代理（`source_16k_mono.wav`）用于定位，剪切与最终音轨一律走 48kHz 无损源。

### 前五秒加严检查：每条必做

- 以最终时间线的前 0–5 秒为准；若前置了后段，同样检查新的开头，而不是只检查原片前五秒。
- 开头第一个字完整干净，不残留准备声、失败起句、空转铺垫、重复、自我修正。逐字核查每个字词间隔，确认的啰嗦、犹豫和无信息停顿必须剪掉；不能用“自然口语”豁免。
- 抓手与正文一致，不为凑满五秒加内容，不为速度吞掉音节，不把必要发音过渡切成零间隙。听感应连续、紧凑、自然。
- 独立检查前五秒，再连看前十秒确认接入正文顺畅；记录开头原句/最终原声、切点及实际复听结论。

- 删除停顿气口、明显卡壳、重复字与失败起句。
- 说错后重说，保留完整且自然的正确一次，不能把第一次错误和后面的正确重说都删掉。
- 声学静音只定位候选，户外底噪下固定 -42dB 可能漏检；按噪声底选择检测阈值。禁止按阈值直接批量切所有候选。
- 从真实词/句发声边界切割，把必要保护余量计入总留白；不再在每侧固定叠80ms。不能为了快吞掉词头或词尾。
- 对异常长词、重复起句、半句重说和 ASR 可疑区间，独立截取左右短片段复听，必要时分块转写和查看波形。整段 ASR 可能合并两个重复句，不能据“文稿正常”推断声音无残字。

## EDL 是共同事实源

记录源片路径/哈希、源时间区间、保留顺序、删除理由、速度、输出帧率和输出时段。画面、音频、字幕、标题和卡片全部从同一 EDL 映射，不分别手填互不关联的秒数。

一般使用实际 PTS 和时间区间；可变帧率/旋转/HDR 先检查。若采用 `sourceStartFrame/sourceEndFrame`，必须声明它们属于 `fps=frameGridFps:start_time=0` 归一化后的帧网格，不是未经核对的原片帧号。帧区间用左闭右开。导出器要求归一化网格与输出fps相同；源fps不同时必须显式写明 `frameGridFps=fps`，不能把原始60fps帧号按30fps解释。

`render-static-overlays.py` 支持这种归一化网格的升序、不重叠 keeps。需要重排/前置或复杂插入时，用按 EDL 顺序的 trim/concat 构建等效时间线，不能排序 keeps 来掩盖不支持的重排。

精剪完成后默认以约 1.1 倍速试听并记录实际值；用户另有要求则用其值，不能为对标牺牲可听性。整体加速不会消除间隔不均，不能替代字词精剪。字幕从源时间映射到输出时间；Composition 时长、总帧数与最终画面完全一致，上游任何切点变化都重新计算，不能只把所有事件机械平移一个常数。

## 原声音轨

本人口播是唯一连续叙事。按 EDL 剪音频后使用同一倍速，保持音高；必要时以约 3ms 边缘淡入淡出去除切点爆音，不重叠词语。

轻度降噪按录音质量决定，可用 70–80Hz 高通、轻度频谱降噪及响度调整，避免过度处理导致金属声。检查响度与峰值。已经处理好的修订音轨直接复用，不叠加第二次降噪或响度处理。

要从 PCM 导出新音轨时，编码一次 AAC（例如 48kHz、192kbps）；仅视觉修订则从已确认视频复制 AAC，进行一致性校验。插入视频默认静音，不添加音效、配乐或替代旁白。

## 检查与范围

先看开头/前五秒、所有风险切点两侧、标题退场、近景低头、卡片进入/结束及尾句；再整片听看。用户点名一个残字时，检查同类重说边界，不扩展到未点名的视频。

无法直接播放并理解原声的执行环境，只能完成定位、转写/波形辅助和待审输出，原声节奏验收记为未完成。不得在技术报告通过后把听审缺项隐藏起来，也不因为缺少听审就停止与之无关的工作。

保留源片和旧版本。仅更新指定片子的 EDL/字幕/工程/验收；不要为目录整洁移动或删除已交付版本。用户要求比较时报告剪切、重排和倍速各自造成的时长变化。

补充执行 [转写覆盖与成片复审](final-review.md)：ASR 漏覆盖先核实；成片重复、填充、静音及字幕冻结须逐项裁决。前五秒使用当前 pause-policy.json，旧 0.12 秒描述由 0.08 秒候选阈值替代。
