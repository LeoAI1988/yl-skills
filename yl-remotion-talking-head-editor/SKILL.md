# 真人口播 Remotion 剪辑

## 首要执行约束｜逐项完成的待办清单（2026-09-14）

**本 Skill 是必须严格执行、逐项核销的待办清单，不是可选参考。读过规则、生成候选、改好配置或导出文件，都不等于执行完成。** 开工即按本次范围建立逐条视频的执行清单，每项记录实际动作、证据和完成状态；适用的必做项必须全部完成，不凭印象跳步。不适用项须有用户范围或实际素材依据，不能为规避难项自行排除。

### 开工先确定模式：全自动或半自动

**每次新剪辑任务，用户没有说明模式时，先问：“这次用全自动还是半自动？”等回答后再进入剪辑流程，不自行默认。** 明确说“直接给最终结果，不用问我”可视为选择全自动；明确要求先审逐字稿、再审未增强剪辑版可视为半自动。仅说“剪一下／开始／按最新 Skill 剪”不算选定模式。同一任务已选定的模式跨轮沿用，不重复询问；用户明确改选时更新。仅修改 Skill、回答问题或审查执行记录，不触发剪辑模式提问。

| 模式 | 固定执行方式 |
| --- | --- |
| **全自动** | 执行者自行完成内容、调序、逐字删留、停顿、排版及画质判断，精剪并内部验收通过后，继续本次范围内的开拍 API 美颜/画质增强和最终验收，一次性交付最终成果。GATE-1/GATE-2 为内部审核节点，不中途征求意见、不把待办或待判断候选交给用户；清单与证据由执行者内部完成。 |
| **半自动** | ① 先一并输出本次**所有视频**的完整逐字稿修改方案：删除线、字词/整句删留、调序原位置与新位置、ASR 识别文字修改。② 用户确认逐字稿后，完成全部精剪并检查，交付**未接入开拍增强的剪辑版**。③ 用户确认剪辑版无误后，最后调用开拍 API 美颜/画质增强并验收，交付最终成果。GATE-1/GATE-2 都须用户确认。 |

半自动不能擅自只交部分视频的文稿就开始剪其余视频；用户明确分批确认或指定先做某条时按其范围继续。提交未增强剪辑版之前，逻辑、停顿、字词、字幕和剪点必须已完成内部检查，不留未处理候选让用户代做精剪。两种模式的质量要求相同，仅中间确认方式不同。

用户明确“先给审查稿／等我确认／先不要开拍”时遵守指定节点；全自动也不扩展到未点名视频、云端入库或平台发布。实际素材、凭证或能力缺失时如实说明并继续可做部分，不伪造完成；不能把常规剪辑判断当成缺失信息。

### 两种模式共同的执行要求

- **按最严格的紧凑标准落实剪切**：沿用 [停顿阈值](references/pause-policy.json)，明确无信息的长空白由执行者声学定位后直接剪除并检查衔接；不因字幕仍显示、ASR未单独标出或“尚待判断”就保留。短停顿、词内犹豫、错话、复述和失败起句逐处自行裁决。严格针对冗余和空白，仍须保留完整字音、句意及必要的自然浮动，不能逐字切碎。
- **候选必须转成已执行的决定**：候选只是内部待办；逐处落为“已剪并复核／有具体理由保留／证据表明误报”，关联本次 EDL。检测脚本只出候选时，执行者负责完成剩余定位、判断和剪切；不得把改状态字段当成已剪。没有真实依据不能伪造确认，须继续局部复核。
- **检查脚本是否真正落实规则**：复用旧生成器前，核对它是否读取当前停顿参数、消费已完成的判定并改变保留区间、保留已确定的开头和调序。只写候选、忽略判定、恢复旧时间轴或遇旧成品直接跳过时，先修正或换用可落实规则的流程；不能因为脚本运行结束就放行。
- **从最终导出反查，不以生成成功代替验收**：全片重新扫描长空白，检查字词内部与前五秒，并完成原声听审及五项验收；检出的漏项返回同一 EDL 修复再验。待处理候选不为零、必剪项未落实、五项仍有 FAIL/PENDING，均不得作为最终成品交付。用户要求最终结果时，不能仅靠标“待审”就结束仍能继续完成的工作；只有真实能力/素材缺失导致无法继续时如实报告具体缺项，不冒称完成。
- **交付链接必须绑定本轮结果**：新版本名、EDL、字幕、音轨、开拍输入/回片、最终 MP4 的哈希和时长须对应同一时间轴。发现旧文件同名或脚本因文件存在而跳过，改用新版本继续；不覆盖旧成品，不把旧回片或旧链接充当新成果。

每条视频的最小执行清单（本次范围内逐项完成并附证据）：

- [ ] 确定并记录全自动/半自动模式，锁定源片、用户要求、参考标准和旧版保护记录。
- [ ] 完成内化的三项内容分析、开头/调序判断及所有必剪清单。
- [ ] 全片检测停顿并自主裁决，字词删减、停顿收紧及调序全部落实同一 EDL，待处理为零。
- [ ] 前五秒逐字精修；全部新切点、全片原声与最终长空白复查通过。
- [ ] 本次启用的字幕、标题、卡片和封面完成；实际倍速、音画同步及固定字号/位置已验证。
- [ ] 色彩转换、源片画质对照及本次要求的开拍增强完成，回片与本轮输入匹配。
- [ ] 内容、节奏、排版、画质、技术五项验收通过，无未处置问题。
- [ ] 提供对应本轮的版本化视频链接、完整文字稿与工作文件；云端入库仅按相应授权执行。

以用户的真人原片、原声、措辞和完整思想推进为主干，完成内容判断、逐字逐词精剪、后期和封面。使用本次用户提供并认可的参考，分别校准视觉、停顿节奏和画质；没有参考时按本 Skill 通用参数起步。参考不提供下一条视频的文案、切点、固定时长或卡片授权。

## 固定执行要求

- **项目热词表**：使用当前用户提供或当前项目维护的专名、产品名和 ASR 误写修正表。查表后结合原声核对；没有表时由本次素材建立。新增修正记录在当前项目，不读写其他用户或其他工程的数据。

- **每条必做三项内容分析**：逐字稿逻辑与信息密度、开头与前五秒、内容表达与标题。DBS 三个相关 Skill 的方法已内化在本 Skill 的 [内容分析](references/content-analysis.md)，必须逐条读取并完成；不动态调用外部 DBS，不以用户未再点名为理由跳过。分析必须落到原句、源时间、决定与 EDL，不能只写“逻辑通顺”。
- **判断必做，调序按需要**：比较原顺序与可实现的剪辑方案。原序最好就保留并写清理由；需要调整才调整。确认的错话、无信息啰嗦、重复字词及失败起句必须剪净，不能用“保留个人口语”放行。
- **精度到字词内部**：逐字逐词定位与复核，既修句间，也修词内因思考、犹豫造成的过长间隔。用有浮动区间的自然节奏，不把每个字独立切碎；前五秒逐字重点精修。详见 [剪辑工作流](references/editing-workflow.md)。
- **字幕稳定**：整条先选固定字幕区；同一条字幕字号、字重、行距、描边与标点规则固定。长句分行或按语义分页，禁止逐句缩字号。只有个别连续镜头可以少量位置避让，不得逐句跳位。
- **卡片默认关闭**：用户没有强调卡片就为 0 张；明确说加卡片时自行选择全片 1–3 张，不逐分钟累计，不再追问数量。顶部标题与独立封面不算重点卡片。
- **清晰度不得降低**：从原片直接导出，默认保留有效分辨率，不为加快渲染擅自降尺寸、换低质编码或使用有损代理。最终必须与同一源时刻对照，达到无可见细节损失；可适度增强，不能用涂抹或锐化光晕换取“清晰”观感。
- **开拍前先校正色彩**：按真实源片识别 HLG/SDR，在字幕叠加前完成必要的 HDR→SDR 转换。开拍只接收经过核验的 SDR BT.709 剪辑版；自动检查输入、API 原始输出和交付文件的解码帧、码流与容器色彩标记。不把强贴 BT.709、全局提亮或减红加蓝当作色彩转换。
- **技术通过不等于精剪完成**：内容、原声节奏、字幕稳定性、主观画质和技术检查分别验收。无法实际听审时记录“原声听审未完成”，继续可做工作，但只能交待审版，不能宣称已完成精剪验收。

## 使用范围与入口

- **口播与课程的边界**：本 Skill 面向紧凑的口播短视频；无信息复述、填充词和迟疑必须处理，有功能的强调、递进及完整语气按上下文保留。课程录屏的操作等待和教学重复需要另一套判断，不能拿课程标准豁免口播精剪。
- 从当前工作区发现源片、参考视频、字幕、EDL、工程与已确认版本；模式未说明按入口先询问，其他可从本地推断的输入自行查明。
- 用户指定新参考或局部要求时，以本轮要求为准；要求按此前流程时沿用该用户已确认的样式。
- 用户只要剪口误气口或明确不要后期时，只做所要求的剪辑，不附加字幕、卡片、调色或封面。
- 使用 Remotion 编写、预览文字层或插入素材时参考官方文档；环境中已有 `remotion:remotion-best-practices` 时可读取对应指南，不依赖必须安装另一份 Skill。
- 不生成数字人，不调用 HeyGen，不把任务变成配音或文案重写。

## 两种模式的工作顺序（四阶段，2026-09-14 更新）

**先确定工作模式，再判断内容与结构、完成剪辑和验收，最后做开拍增强。** 半自动由用户确认 GATE-1/GATE-2；全自动由执行者完成内部审核并继续，不增加用户确认。无论哪种模式，停顿判断和剪切都由执行者自主完成。

### 阶段 1｜逐字稿审查稿（GATE-1：结构审核）

1. **锁定范围**：只处理用户点名的视频。记录源片、已批准封面及需保护的旧版哈希；输出新版本，不覆盖源片。
2. **分析参考和原片**：检查真实分辨率、旋转、帧率/PTS、HDR、声音及整段转写；抽查参考视频节奏、字幕和标题。
3. **生成逐字稿修改方案**（每条一份文档，格式见 [剪辑工作流·审查稿规范](references/editing-workflow.md)；半自动一并交付本次所有视频的方案，全自动内部留档后继续）：
   - **原始逐字稿**：转写如实全文，含全部语气词；
   - **调整标记稿**：同一全文加标记——删除的词/字/句直接 ~~画删除线~~，调整顺序的句子加粗并标注原位置与新位置；ASR 识别错误用“识别原文 → 修正文字”标出，注明为文字纠正或需剪原声口误，不混淆两者；
   - **只管文字与结构**（句子顺序、句子删留、字词删减），**停顿不进审查稿**——按 [紧凑停顿规则](references/editing-workflow.md#停顿执行规则紧凑档) 自主完成候选扫描、声学确认和剪切，不增加用户确认环节；常规无信息间隔从成片 0.20s 起处理，通常留总计 0.10s，词内/前五秒连 0.12–0.20s 也逐处查；
   - **通过结构审核再剪辑**：半自动须用户确认逐字稿修改方案；全自动由执行者完成三项分析与删留裁决并留档，然后进入阶段 2。停顿候选不构成等待用户的理由。

### 阶段 2｜一步剪到位（GATE-1 通过后，不提交开拍）

4. **一次性执行全部剪辑**：按确认清单把逻辑重排、整句删除、词级删除、停顿收紧**全部落进同一 EDL**，一次渲染到位——不留"下一轮再剪停顿"的尾巴。同时完成排版（固定字幕+双行标题，标准见 [视觉标准](references/visual-style.md)）与封面（需要时）。确认的错话、复述、口头禅必须剪净，不能用"保留个人口语"放行；字幕改字不等于剪原声。
5. **检查导出**：按 [渲染与画质](references/rendering.md) 一次有损编码合成，逐字复听前五秒及全部风险切点，对照审查稿清单逐项核销（检出 N 处/处置 M 处/漏检 0 处）。**此阶段产出完整“剪辑版”，明确标注未做开拍增强。** 半自动提交给用户审核；全自动作为内部中间产物，检查通过后继续，不以此结束交付。

### 阶段 3｜剪辑版确认（GATE-2：剪辑审核）

6. 半自动须用户确认未增强剪辑版，确认前不提交开拍；全自动由执行者完成画面、字幕、节奏、剪点及技术审核，确认适用项通过、待处理为零后，继续本次范围内的阶段 4。发现问题回到阶段 2 修，不能提前用开拍回片掩盖剪辑未完成。用户指定“先不要开拍”时按指令暂停该步骤。

### 阶段 4｜开拍增强（最后一步，GATE-2 通过后）

7. 按 [开拍画质增强](references/kaipai-enhance.md) 先检查剪辑版色彩，再执行 `hdvideoallinone`。默认不叠加提亮、冷色或饱和度滤镜；目标是明亮自然的肤色和保留细节，不能发灰、发青、过曝或塑料感。新素材/接入改动先用短样验证，再处理完整已确认时间轴；最终复用原剪辑音轨。免增强须有对照依据并记录。
8. **分项验收交付**：按 [验收规则](references/acceptance.md) 完成五项验收。提供版本化 MP4、EDL、字幕、审查稿及确认记录。
9. **文字稿与入库**：按 [成片文字稿归档](references/final-transcript-archive.md) 导出完整成片口播 TXT/MD，仅在用户明确授权并指定目标后同步笔记或本地内容库。

## 修订与版本边界

- 已明确授权的局部修订直接完成并验证，不重复索要视觉确认。只有依赖缺失且无法推断的信息才阻塞相应工作。
- 仅改字幕样式、标题、卡片或画质时，冻结 EDL、字幕正文/时间、语速和原声音轨；重新从原片合成画面，复制已确认 AAC，并核对声音一致性。用户要求改字幕错字或同步时，仅解冻所授权的正文/时间字段，不顺带重剪口播。
- 用户要求有卡片/无卡片对照时，输出两版，底层剪辑与声音相同。除此之外严格执行：未要求卡片为 0，明确加卡片为全片 1–3。历史样本带卡片不自动授权当前片加卡片。
- 保留旧视频及已通过封面，以 `_v2`、`_v3` 等新增文件交付。仅在用户明确要求替换当前版时，先保存可核验的备份再替换。
- 同一次只处理指定素材；已批准成片导出完整文字稿；另行授权的入库按上面的流程完成，但批准样片或更新 Skill 不等于授权立即批量剪其他视频、平台发布或全平台采集。
- 由安装者指定一份维护真源；更新分发副本时核对版本，避免多份规则漂移。分享包不包含本机 Junction 或符号链接。

安装与工具准备见 [环境与参考](references/approved-example.md)。示例工程不是运行依赖，不能向新视频复制旧标题、旧字幕、旧切点或旧人物画面。

## 2.1 同步补充：覆盖检查和成片复审

剪辑前、导出后必读 [转写覆盖与成片复审](references/final-review.md)。转写覆盖检查在删空白前执行；GATE-3 在 GATE-2 中完成，增强回片后复验。旧段落中前五秒只从 0.12 秒起检查的描述升级为 0.08 秒起候选，确认后目标约 0.05 秒，均为成片坐标；其他停顿范围不变。不得用转写空白直接当作无声。

覆盖区间可用 `scripts/check_asr_coverage.py --input /work/coverage.json` 只读检查，输入为 `{"coordinate":"source_seconds","vad":[[0,2]],"asr":[[0,1]]}`；两组须先对齐同一源时间轴。结果只生成听审候选，不自动删片。
