# 真实案例整理成文章

从作者已做过的事中恢复完整过程，让读者看懂遇到了什么问题、如何解决、结果如何，以及自己怎样使用。直接点名本成员时即可执行，已有分流无需回跳。先读同级 `yl-toolbox/references/profile.md` 的配置约定和任务相关个人说明，再读 [表达与来源复核](references/voice.md)。本成员独立维护表达方法。

## 恢复任务和材料

恢复当前聊天里的目标、读者、渠道、案例范围、已确认表述和授权。优先查已有项目文件、操作历史、原始录音或视频、完整逐字稿、定稿和平台记录；需要跨库查找时调用同级 `yl-knowledge-search`。助手参与过的项目，从操作记录恢复过程，已有信息直接复用。只追问影响成文的真实缺口。

根据材料选择起点，可在同篇文章中组合。

- 随口说、无稿口播或录音，以完整表达和原始素材为起点，恢复思想顺序、重复、停顿及最终保留内容。
- 已完成的开发、建模、知识工作台等项目，以实际任务、过程记录、迭代和成果为起点，直接整理成文。
- 已有成片、文章和传播数据，以同一作品的素材、处理记录、成品和后台证据为起点，分析体验与效果。

用户指定每个 Skill 一篇时，每篇围绕一个能独立解决的具体问题展开。口播短视频、长视频多条、口述变文章、项目记录变文章等各自明确输入、过程、结果和适用人群，篇目数量服从用户要求。

## 建立案例对应关系

回读完整原文与重要上下文，查看实际成果。用作品 ID、项目记录、时间范围、文件哈希或可核对正文确认原素材与成品的对应关系。相近标题只用于寻找候选。

在核心外的本次工作目录保留简明证据记录，包含案例、原始材料、关键步骤、成品、指标来源、采集时间、作者确认和仍缺材料。已有清单可直接补充。把作者亲历说明与助手实际核验分别记清，成文时只呈现读者需要的信息。

用户指定截图圈定范围、数量或排名指标时，严格按该集合选取，并保留筛选依据。未指定时，根据案例解释力与素材完整度选择并说明选择。平台复盘已有评分与用户本次按播放量选案例分别按其适用范围执行。

## 还原过程并写成文章

先从作者原话与完整材料中找出叙事主线，再用必要的连接语组织正文。文章应让读者能够回答以下问题，章节形式随材料安排。

1. 当时遇到的具体困难是什么，作者希望得到什么结果？
2. 实际提供了哪些输入，哪些内容由作者完成，哪些由工具完成？
3. 做了哪些关键操作、判断与修订，为什么这样做？
4. 原始输入与最终成果有什么可见变化？
5. 结果和数据说明了什么，读者在什么场景下可以采用？
6. 读者需要准备什么，怎样开始，能得到什么交付物？

无稿口播案例要讲清随口表达如何经过结构梳理、顺序重排和删减变成可看的成片，具体动作以真实剪辑记录为据。项目转文章要说明助手掌握哪些项目上下文，以及实际写稿、配图、排版、人工修改和发布环节。用户确认的“只改一句”等体验表述保留准确范围。

用实际发生的步骤和有代表性的片段解释过程。失败、改动和关键决策在有助于理解时写入。提供与实际能力相符的可复制任务提示词，必要依赖和操作入口写清。案例结果用于展示已有体验，流量与收益表述保留证据所支持的范围。

## 前后对照与数据

- 原素材与成品并排展示或紧邻排列，标明各自身份。节选须注明范围和时长，完整版本提供可用入口。网页适配副本保留来源关系及原始文件。
- 使用真实操作截图、成品和后台截图。截取或遮挡只处理与案例无关的信息，并保留标题、指标名、数值等理解证据所需内容。需要编辑图片时遵循当前可用工具规则。
- 播放、阅读、点赞、关注等保留平台、对应作品、统计窗口和采集日期。不同作品、账号、窗口分别呈现。Fork 表示仓库分叉，阅读与播放使用平台原指标含义。
- 数据陈旧时标明日期；后台受限时使用已有合法证据继续工作，并一次提出具体补图需求。缺失数据保留待核验状态，新增截图到账后同步正文、图注和证据记录。
- 引用公开展示所需素材，检查身份信息、私人路径、凭证及链接有效性。平台限制按当前工具规定处理。

## 按渠道交付

默认交付 UTF-8 Markdown 正文及用户要求的图片、对照媒体和链接。内部证据记录独立保留，正文连贯可读。

GitHub 介绍突出问题、成果、示例、用法和入口，首页保留精选案例并链接详情。公众号文章需独立交代背景、过程和作者体验，沿用本人语气与手改。封面、配图、排版和发布按本次授权与个人约定继续完成；已有授权跨步骤复用。

发布时仅处理授权范围内的文件与资源，保留仓库其他未提交工作。核验实际远端内容、匿名图片链接和视频播放；链接失效则修复可控资源并复查。报告实际完成阶段及仍待解决的具体项。

交稿前检查每个请求案例、数据、媒体对照、使用场景和用法是否落实，并执行表达复核。作者确认的定稿按配置交给 `yl-knowledge` 完成归档、去重、蒸馏与关联，保留原始材料及派生关系。云端写回遵循明确授权。

## 调用示例

> 把这个已完成项目整理成一篇公众号文章。查已有过程记录，讲清痛点、关键步骤、成果和使用方法，保留我的表达，附真实过程图。

> 从指定的无稿短视频中选播放量最高的三个，展示原素材与成片对照，核对数据截图，写成自动剪辑案例介绍。
