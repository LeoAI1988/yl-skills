# 技能更新与优化

围绕技能要解决的任务，维护一套清晰、完整、可执行的当前规则。将新经验放回对应决策和执行步骤，合并同义规则，清除已替代的活动指令，保留有效能力与必要细节。

## 确定范围和维护真源

先从用户要求、当前上下文和仓库说明确定目标技能、用途、输入、输出及成功标准。读取目标的完整 `SKILL.md`，跟进受影响的引用、脚本、模板、配置、调用方及安装映射。YL 环境同时读取 [个人配置约定](../yl-toolbox/references/profile.md) 的相关设置。

- 用户要求检查或评估时，完成只读诊断和可执行的修改建议。
- 用户要求更新、优化、精简或修复时，在已明确范围内完成修改和验证。既有授权覆盖的常规整理由执行者直接完成。
- 先确认维护真源与宿主入口的关系，记录当前版本、文件状态和已有未提交改动。改动限定在本次目标及必要的依赖、路由和登记。
- 一项技能应能用一句话说明目的。缺少会影响结果的关键需求时集中澄清，其余可逆选择依据现有任务自行决定并记录。

## 提炼经验并判断适用范围

每条拟加入的经验都回答以下问题，按复杂度留简短工作记录。

| 问题 | 需要得到的结论 |
| --- | --- |
| 解决什么问题 | 原行为、实际失败或用户新要求，以及期望结果 |
| 依据是什么 | 本轮明确要求、已确认成果、可复现问题或实际工具能力 |
| 适用于什么场景 | 触发条件、覆盖输入、已有例外与授权边界 |
| 应放在哪里 | 入口、现有流程、专项参考、参数配置、实现脚本或个人层 |
| 怎样证明生效 | 可观察的产物、正常调用行为、回归场景与完成条件 |

区分必需约束、默认策略和条件分支。必需约束应有用户指令、系统接口或正确性依据，默认策略允许随内容调整，例外与对应规则放在一起。单次样片的标题、时间码、倍速、账号和目录留在项目或个人层。可迁移的方法进入通用核心。

发现旧规则限制当前授权任务时，核实它的来源和实际适用条件。已过时或误用的要求在源头修正，并继续完成本次工作。仍有效的外部限制给出具体依据和影响。

## 按当前结构整合

先沿实际执行顺序梳理入口、判断、操作、验证和交付，再在原规则位置修改。必要时重排章节或重写一个完整小节，使后来执行者顺序读取即可得到一致的当前行为。

- **保留**仍有作用的方法、工具调用合同、输入兼容、来源归属及能影响决策的细节。
- **合并**表达相同要求的段落，将同一规则集中到一个维护位置，调用方只保留链接与何时读取。
- **改写**有歧义、互相覆盖、条件遗漏或无法执行的规则，统一术语、参数、坐标、状态和完成标准。
- **删除**已确认过时、错误、被替代或失去用途的活动内容，同步处理其链接、默认值和调用点。历史变更记录保留在既有版本记录中。
- **迁移**个人偏好、真实案例、私有路径和运行数据到核心外的对应位置。较长的条件性流程放入有明确读取时机的参考文件。

检查入口和引用中的“补充”“新版覆盖旧版”“暂按旧流程”等历史层叠，落实最终有效规则后清除被替代表述。重要步骤仍需有清楚顺序、所需输入、执行动作、失败处理和可验证结果。

压缩以语义完整为边界。解释性重复可以合并，原声保护、数据兼容、授权、失败恢复和实际验收等有效约束须保留。只有内容足以影响执行时才新增文件或抽象层。

## 同步实现与依赖

沿“用户请求 → 技能入口 → 参考/配置 → 工具或脚本 → 真实产物 → 验收”检查变更影响。

- 参数已有唯一配置时修改该配置，并核对消费者确实读取它。文档中的摘要与配置一致，校验器使用本轮要求和真实输出验证结果。
- 规则涉及脚本行为时检查正常调用入口、旧输入、重试和部分失败，修复会使新规则失效的实现。共享资源删除或移动前核查引用及实际调用者，按仍需支持的行为决定迁移方式。
- 入口描述准确覆盖用途，UI 提示、路由、引用和目录登记一致。保持现有来源、许可与有效接口。
- 按仓库已有维护规范更新实际变化成员的版本、审核和包清单。个人配置独立保留，跨宿主使用同一真源映射。

普通检查优化可直接维护现有结构。只有用户请求的能力确实具有独立入口时才新建技能。

## 从真实使用方式验证

先检查名称/frontmatter、相对引用、缺失依赖、参数一致性、重复与冲突。环境提供技能校验器时运行对应检查，脚本改动运行相关现有测试，并为明确回归补足必要用例。

再选与改动相称的真实请求走查。至少覆盖典型用法和本次修复的问题，涉及限制或旧数据时加入对应边界输入。用请求、最小原始材料和当前技能推演或执行，查看步骤和结果是否满足任务。静态结构检查、行为走查和真实运行分别记录。

重点核验以下结果。

- 新会话只加载当前入口和按需参考，仍能找到完整流程与真实成功条件。
- 同一输入沿不同入口得到一致规则，旧默认值或末尾补充不会把新行为覆盖。
- 典型任务保留必要功能，本次回归得到解决，限定范围的请求仍只执行该范围。
- 已授权任务能连续推进，实际外部限制和缺失信息有明确处理方式。
- 重复执行、失败重试或旧输入适用时，产物和状态保持一致。

纯文档改动可做场景走查，执行性改动按实际工具验证。需要付费或外部写入的验证沿用本次授权，受限部分记录具体未验项。

## 交付与收尾

交付当前有效技能、必要依赖和简短变更结果，说明合并或删除了什么、规则现在由哪里维护、验证了哪些行为及剩余缺口。明确本地文件、安装映射、宿主加载和外部发布的实际状态。

新增或改名后刷新宿主技能列表并核对可发现性。宿主无法热刷新时说明需重新打开技能列表或新建会话。将临时验证材料留在运行目录并按项目规则收尾，活动技能目录只保留执行所需文件。
