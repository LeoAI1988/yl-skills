# 本地抖音发布工作台

## 安装与运行

使用 Python 3.11 或以上版本，无第三方服务端依赖。页面用原生 HTML/CSS/JS，视频预览支持 Range。配置中的所有个人路径都由安装者填写，配置文件放核心之外。

```sh
python -B scripts/workbench/server.py --config /absolute/path/workbench-config.json
```

配置字段：

| 字段 | 用途 |
|---|---|
| `data_dir` | 外置 SQLite、批次清单、执行日志和截图目录 |
| `port` | 本机端口，默认 18765 |
| `account` | 预期抖音账号，执行前必须核对 |
| `tag_pool` | 至少 5 个不同标签，不带井号 |
| `collections` | 界面预置合集；执行时重新核对平台实际合集 |
| `codex` | 本机已安装并登录的 Codex CLI 绝对路径，可省略并从 PATH 查找 |
| `ffprobe` | 本机 ffprobe 绝对路径；缺失时显示未知时长 |
| `icon` | 可选个人 PNG 图标绝对路径 |
| `initial_folders` | 可选已授权的素材文件夹数组 |
| `import_plan` | 可选已核对的旧台账 JSON |

旧台账结构为 `rows` 数组，每项包含 `id/video/title/date/disposition`，可带 `cover/duration/tags/date_basis/title_source/dedup_status/dedup_evidence/platform_id/scheduled_at`。`scheduled` 导入为此前已提交，`excluded` 导入为排除，其余导入待发布。导入仅在第一次初始化执行。

Windows 桌面入口可用外置 `launch.py` 配合 `pythonw.exe -B`：先检查该端口的 `/api/health` 是否返回应用标识，未启动则以隐藏窗口启动服务，成功后打开本机网页。快捷方式指向该个人启动器，图标独立保存在个人目录。不得修改浏览器登录、扩展权限或全局 Codex 安全配置，也不默认创建开机启动。

## 使用与行为

1. 粘贴文件夹并扫描；可继续添加多个文件夹。移除来源入口保留已导入记录和原文件。
2. 勾选视频，选择开始日期、最早及最晚发布时间，再选每天 2—13 条。首末时间各有小时和分钟选项，小时仅显示 06—22，分钟按十分钟一档；默认 07:30—21:00，可自由更改，改变条数不改两端。预览把区间尽量均分，取最近的十分钟刻度，恰好半档时向后取整；两端固定、相邻间隔最多相差十分钟。结束必须晚于开始，区间至少为 `(条数 - 1) × 10` 分钟，否则提示并禁用生成。点击生成才保存 `preferences.start_time/end_time/count/start_date` 并重排；旧版本未保存首末时间时只读沿用其旧节奏作为初值，不改旧计划。排序依据是登记的素材日期；新扫描没有可靠拍摄日期时使用文件修改日期并标明。最后一天不足整日数量时使用所选节奏的前几个时段。
3. 排期按日期从左到右分两列，每天内部从上往下；窄屏自动改为单列。拖动每条左侧手柄，将视频插入目标前后，其余视频顺移，时刻不变；支持跨日期移动，已提交条目固定。手柄聚焦后可用 Alt + 上下方向键调整。下拉框可换为未排期的视频，已用视频显示原时刻并禁选。逐条的“视频”“封面”按钮分别预览，封面点击才加载，关闭后卸载；无封面时禁用。“设置”可修改标题、已有封面、五个标签、合集、可见范围、下载、原创、章节和相关热点。
4. 选择本次提交时段，查看明细并确认。仅执行本批，远期计划保留本地。界面采用提前 125 分钟与 14 天窗口做保守预检，执行时以当前平台规则为准，不能自动改成立即发布。
5. 观察任务逐条结果。中断或未知结果先点“核对平台结果”，该操作只读，不重新上传。只有完整核验未提交并有截图的条目才能恢复到待发布。

新扫描自动识别同路径或字节完全一致的副本；标题与文案相似不自动排除。重新编码、重剪或不同录制的判断交由发布前实际画面核验。封面无法按文件编号或前缀可靠对应时留空，不任取图片。标题留空时，执行器须按 Skill 的来源顺序读取成片；允许正文原句仍需来自该条视频。

生成、保存和执行批次均检查视频 ID、规范化文件路径和已知非空 SHA256，阻止相同文件重复占用时段。换片或拖动带 `plan_revision`，旧页面的调整会被拒绝并刷新；不覆盖其它页面刚保存的顺序。标题或文案相同不触发这项排重。

标签匹配使用关键词与别名相关度，同分随机；不是向量相似度模型。发布执行器根据实际成片再次检查相关性和平台话题节点。

## 执行与结果协议

每个批次写外置 `jobs/<id>/queue.json`，冻结素材与时刻。Codex 通过标准输入接收任务，在该目录执行，不修改工作台数据库。只使用宿主已提供的浏览器工具，不调抖音私有 API、不导出 Cookie、不创建额外登录配置。

工作台每次打开默认使用 Codex、GPT-Astra（`gpt-6-astra`）、高推理。面板可为本批选择 GPT-6.1 Sol（`gpt-6.1-sol`），两种模型均可选中（`medium`）、高（`high`）、极高（`xhigh`）；不提供静默模型回退。`queue.json` 与任务记录保存 `executor.driver/model/reasoning_effort`。CLI 通过 `--model` 和 `-c model_reasoning_effort="所选值"` 接收实际参数，核验任务沿用原批次模型和推理档位。全局 Codex 配置保持原样。

执行器逐条更新 `progress.json`，结束写 `result.json`：

```json
{"items":[{"asset_id":"V-example","state":"scheduled","at":"2030-01-02 07:30","platform_id":"","evidence":"/absolute/job/path/proof.png","note":"后台已确认定时发布中"}]}
```

可用状态：`uploading`、`scheduled`、`published`、`reviewing`、`failed`、`unknown`。真实成功或审核结果必须包含本批目录中的后台截图，时间必须与清单一致；未知条目保持锁定。`failed` 不自动解锁，只有只读核验确认未提交时可带 `verified_absent:true` 并提供截图，再由界面恢复。

服务仅绑定 `127.0.0.1`。修改接口检查 Host、Origin 和随机 CSRF token；媒体接口只按已登记素材 ID 返回文件。源视频始终只读。页面不展示内部日志和哈希；执行证据留在个人数据目录。

## 验证范围

```sh
python -B scripts/workbench/test_workbench.py -v
```

覆盖自定义首末时间、十分钟刻度均分与无碰撞、无效区间拒绝且原计划不变、节奏保存与条数独立、旧设置只读兼容、HTTP 预览与实际生成一致，以及跳过过期时段、旧到新顺序、跨日插入顺移、锁定条目固定、换片去重、旧版本拒绝、相同路径与哈希排重、三档推理、任务锁定、中断恢复和后台证据校验。模拟测试不证明真实上传成功。安装后另做真实浏览器只读连接测试，并通过界面检查时间选项、实时预览、拖动、媒体预览、设置、计划和导出；未经授权不新增真实发布来验收。
