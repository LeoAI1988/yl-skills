# 抖音视频排期与发布

把授权范围内的最终成片变成可核验的发布队列。账号、素材目录、标签池、节奏和状态保存在安装者个人配置或工作目录，不能放入本 Skill。读取个人 profile 中的 `publishing.douyin.config_file`（若已配置）及本次指令；本次指令优先。

## 本地工作台

要求可视化选片、多文件夹导入或桌面入口时，使用随附的 [工作台](references/workbench.md)。通用程序在 `scripts/workbench`，个人配置、媒体、图标、数据库和执行记录全部外置。不要另做一份宿主专用核心。

工作台支持每天 2—13 条，最早与最晚发布时间单独设置；小时与分钟分别选择，小时仅显示 06—22，分钟为 00、10、20、30、40、50。在两端之间尽量均分并取最近的十分钟刻度，首末时间固定，不能整除时相邻间隔最多相差十分钟。结束须晚于开始，至少容纳条数减一乘十分钟，避免重复时刻。条数改变不自动更改首末时间。设置先预览，点击生成才保存节奏并重排；旧计划不会因升级自动改变。这是工作台规则，不替代本次用户明确给定的其它节奏。只生成计划不会向抖音提交，点击并确认具体批次后才启动执行器。

发布执行器使用本机 Codex CLI 与当前可用浏览器工具。工作台打开时默认 GPT-Astra（`gpt-6-astra`）、高推理；面板可切换 GPT-6.1 Sol（`gpt-6.1-sol`），推理可选中（`medium`）、高（`high`）、极高（`xhigh`）。模型和推理参数随批次冻结，并显式传给 CLI，不修改全局 Codex 配置。首次安装要做只读连接测试。数据库记录与后台核验结果分开，截图缺失、指定时间不符或结果不明都不能当成成功。测试工作台时不要额外实发作品，除非用户明确授权测试批次。

排期按日期双列展示，拖动视频时插入目标位置、其余顺移，时刻不变；已提交条目保持锁定。视频和封面分别点击预览。已排期视频在其它时段的下拉框中禁选，保存与启动执行时再次检查 ID、规范化路径及已知文件哈希；不能把同稿不同次录制当作重复。修改排期带版本校验，旧页面不能覆盖新的顺序。

## 工作顺序

1. 核对当前抖音账号。区分本次要提交的批次与只要求规划的后续批次。明确“帮我发布”即授权对应范围，不重复确认；仅要求计划时不提交。
2. 建立成片清单：稳定 ID、文件路径、版本、时长、已有封面、标题来源、素材日期及依据。排除母带、素材原件和明确被替代版本。目录日期与文件修改日期不能冒充拍摄日期。
3. 读取平台已发和定时队列，并进行下述正文排重。文件夹“未发”标记与平台证据冲突时，以实际作品核对为准。保留来源文件，不因排重删除素材。
4. 对保留成片按用户指定的新旧顺序分配时刻，固定已提交条目的时刻。当天只用仍满足平台提前量的时段；平台窗口外的时段只列本地计划。
5. 逐条上传、填表、回读、提交，再回作品列表确认标题、时间与状态。断线或提交返回不明时先查询队列，不能直接重传重发。
6. 交付逐条计划表、排除清单、今日提交结果及证据。区分“本地计划”“已上传”“已提交审核”“定时发布中”“已公开发布”。定时提交不能写成已公开。

## 正文排重

- 标题、封面、时长和文件名只用于找候选，不构成重复结论。
- 对本地副本先用文件哈希识别字节一致，再用多个时间点的实际画面、字幕、口播或完整逐字稿核对重新编码、变速、改标题及局部裁切的版本。机器相似度只筛选候选。
- 对已发作品读取实际播放器，比较开头、中段、结尾的内容推进；记录平台作品 ID、匹配时间点和画面/字幕依据。同场景同题材可能是不同内容；短切片也可能已包含在长片中，应标明重合范围。
- 确认重复才排除。证据不足标为待核，不以“没发现相似标题”宣称完成排重，也不提交仍有重复疑点的条目。
- 区分同一成片、同源重剪、同稿重拍与同题材不同内容。同一文案的不同次录制不算重复，均可排期；不能仅因文案或模板相似而撤出队列或列为备选。只有用户另外明确要求内容层面的去重，才能按其范围筛选文案。
- 判断同一录制需要对应画面序列、人物动作、口型、镜头移动或屏幕操作等证据。同场景、同一句台词、相近时长都不足以单独确认。对改标题、变速、裁切和重剪的版本，应对齐实际画面再判断；无法确认时单列待核，不计入已确认重复数量。

## 字段规则

遵循本次要求及个人配置，不把某个账号的习惯当作平台通用默认值：

- 标题优先用明确的归档逐字稿标题，其次核对成片顶部标题。无可用标题就保留待核，不能凭封面或目录名改写。
- 用户允许使用正文原句时，直接截取相应成片的原句，并记录稿件段落或成片时间点；这不授权另行改写标题。
- 使用对应的已有封面。用户允许缺封面跳过时，不生成新图。核验上传预览，不能把自动截帧当成已上传自定义封面。
- 同一目录含多个视频时，按编号、前缀和内容逐条对应封面；不能任取目录中第一张图片。无法确认对应关系则留空并说明。
- 简介与标签按要求填写。标签数量以当前界面限制为准；相关性优先，在同等相关标签中可随机选择。逐个输入并确认成为真实话题节点，不能只看一串带井号的普通文本。
- 只选择现有且内容合适的合集；创建合集需另有授权。合集选择后再次检查保存权限，某些页面会恢复默认值。
- 原创、可见范围、保存权限、位置、活动、自主声明分别核对。要求的原创入口不存在时记录“不支持/未找到”，不能用另一种声明替代。
- 用户允许时为较长视频生成章节，生成结束后核对章节内容并保存。“生成中”不等于已添加。热点仅在真实相关时关联。
- 定时提前量、最长窗口、标题和标签数量限制以本次页面为准，不永久写死历史数值。

## 浏览器操作

使用宿主当前提供的浏览器工具，先读其规范。不包含私有接口、Cookie 提取或绕过界面脚本。具体易错项见 [浏览器核验要点](references/browser-checks.md)。选择器与坐标每次从当前页面观察，不把历史索引复用于新页面。

## 最小台账

每条至少记录 `id`、`video`、`date_basis`、`title_source`、`cover`、`dedup_status`、`dedup_evidence`、`scheduled_at`、`timezone`、`tags`、`collection`、`status`、`platform_id`、`verified_at`。无法获取的平台字段留空，勿猜测。排除条目单列表格，不能占用发布时间。

计划表中待核内容必须可见。若平台失败不影响本地排期，继续完成能做的工作并报告具体未完成项；不要制造成功状态。
