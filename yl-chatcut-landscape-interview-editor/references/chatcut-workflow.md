# ChatCut 执行与时间基

## 表面与工具

Desktop 本地 MCP 与 Hosted 插件是不同表面。Desktop 先 `get_active_project`；检查 active timeline，再读范围内项目、轨道和素材。实时 schema 决定参数，工具名相似不代表字段相同：Desktop 常用 `startFrame / durationFrames / sourceIn`（微秒），Hosted 可能用 `fromFrame / durationInFrames / sourceStartFromInSeconds`。禁止直接照搬另一表面的参数。

读取相关 ChatCut 官方 Skill：实际转写用 transcription，声音处理用 voice-isolation，Motion Graphic 修改用 create-motion-graphics，视觉验证用 visual-analysis；只读当前步骤需要的文档。缺工具先报告真实连接或能力错误，不查凭据、不猜接口、不编辑内部数据库、不使用 UI 聊天框绕过工具。

从 Web 迁入 Desktop 的项目可能引用压缩媒体；检查 `inspect_asset` 返回的真实本地文件、规格与源 hash，原片可用时使用支持的 relink/import 工具。Desktop 本地素材不自动成为 Web 可播放源，不能把云端不可用当作本地导入失败。

## 时间与音轨

对 MTS 等相机素材先探测视频首展示帧、音频 PTS、采样率、隔行和起始偏移；源时间、代理时间、转写时间、编辑帧与最终输出秒需有明确映射。非零 PTS 不直接当作统一修正值；实际测准后再用，换源就重校。

有独立音轨时，先验证视频内嵌音是否已静音，避免同一录音重复相加造成响度增大、梳状干涉和噪声。每段独立音频与视频应使用相同源区间、播放位置与倍率。拆音后不要基于第二份误识转写另剪一遍。

所有倍率、源区间和最终时长从同一份时间映射派生。用户指定 1.1 倍时，记录是否已有倍率，禁止再乘一次；倍速改变字幕和指定时间插图前，先确定这些时间属于最终成片。工具 readback 与最终导出都检查同步。

## 文本编辑事务

1. `read_script` 获取最新真实脚本；保存基稿与 occurrence 标识。不同表面可能返回内联字符串或工作区文件，按真实返回编辑。
2. 完成整篇语义判断，按用户范围标记删除和重排。不把 ASR 行当语义整句，不在 Script 凭空改原话。
3. 对已批准稿做一次预览，核对删除、重复、排序及范围；成功后执行，无需再次请求相同授权。
4. 应用后重读生成的干净稿，核对实际全文、字幕和独立音轨。若 stale，先重新读取、合并最新状态，不能覆盖用户新修改。
5. 需要机械停顿整理时，确认它不会删未授权的语气词。执行后必须重读再做下一批，不继续使用旧稿。

局部边界修正以原声为据并保持批准词序；工具不能提供需要的精度时说明具体缺项，不能静默以段级剪辑冒充精剪。保存可回退版本。

## 导出

用 Desktop `local_export`，按实时 schema 选择视频分辨率和帧率。返回 taskId/outputPath 仅证明入队；进度优先用支持的任务状态，若无状态接口，检查文件写完、稳定且可完整解码。CPU 增长仅表明进程活动，不能据此宣称“缓存正常”“即将结束”“没有失败”。不得高频轮询或重复提交；短而必要地汇报实际进展。

用唯一版本文件名避免覆盖旧成品。默认目录由工具确定；选 D 盘等路径时按实际能力处理。只有真正遇到原生保存确认才说明用户必须操作，不能伪造确认。不要为了规避额度而调用未授权付费生成/云端导出。常规本地视频导出与独立透明动效导出不是同一收费能力。

当前 local_export 的相对文件名保存到系统 Videos/ChatCut 下；传该目录外的绝对路径会触发原生保存确认。用户委托全程完成时，优先用唯一相对文件名正常导出，验证完成后用文件工具复制到用户指定交付目录并核对 hash，避免不必要的交互。当前支持 timelineId 时显式指定已核对的工作时间线，防止导出用户正在浏览的另一条时间线。
