# 流程复盘与行为验算

以下是从真实多轮工作抽象的方法；不携带当事人身份、视频、截图、项目 ID、路径或完整私稿。

| 曾出现的问题 | 正确做法 |
| --- | --- |
| 第一稿只删口误，用户多轮继续删重复功能、虚词、铺垫 | 全文主张与段落新增信息先审，第一轮就做有依据的语义减法；不能据后续偏好自动突破已批稿 |
| 用户说“只记录”，仍准备边收边改 | 收集状态仅归档/辨认；等本轮明确执行信号再提交 |
| 精确红线被泛化成自动清理规则 | 每条落到原文 occurrence 和字界，未划保留；截图外继承基稿 |
| 前移高能句后丢失反转或重复出现 | 连同立场限定审完整开头，默认移动一次，回读全部出现位置 |
| 为了听审门槛反复让用户批准同一步骤 | 一次批准持续有效；核验由 Agent 执行，缺能力诚实标注，授权不能充当质量证据 |
| 把音量设 0dB 就说“恢复原声、无失真” | 显式清除音效并回读；检查视频内嵌音和拆音是否叠加，0dB 不保证混音不溢出 |
| 输出峰值 0.0dB 被草率当作削波证明或健康证明 | 复查真峰值、样本截断、混音与听感；证据不足不归因 |
| 改增益没改善杂音，又直接断言来自环境 | 同内容等响度 A/B，分离源录音、混音、变速、效果和编码因素 |
| Desktop 人声隔离声称“可调弱一点” | 核查引擎合同；固定强度不能假调。先局部验证自然度，后应用全片 |
| 音效返回 applied，就声称声音干净 | 批量挂载、推理、导出、实际音质是四个状态，分别验证 |
| 黑底 alpha 小于 1 就称半透明 | 背景透明、文字不透明；看背景是否确实透出，勿只读参数 |
| 标题容器放大、加样式却没有可见阴影 | 检查实际字面、实例覆盖、代码版本；预览与成片双验证 |
| Hosted 云端额度不够，笼统声称本地全功能免费 | 区分普通 Desktop 本地视频导出与付费生成/透明动效能力；只查当前实际需要 |
| 每半分钟检查文件并重复宣称“正常、马上好” | 状态工具优先；无进度只报告未知。CPU 活跃不是成功证明，不能承诺 ETA |

## 维护时的场景验算

在不操作真实媒体的条件下走读这些场景，检查决定是否符合当前规则：

1. 半自动用户连续发几张图，说“还没发完”。应只登记，不 apply、不导出；新的“开始修改”才解除该轮冻结。
2. 红线只划掉一个虚词，旁边有明显叠词未划。应只删标定词，不能用 clean_script 偷删叠词。
3. 用户先批准全文，之后只说“标题加阴影”。应只改图形与验证，不能重跑全文剪辑或转写。
4. 原声回退后仍有杂音，V1 内嵌音和 A1 同源都发声。应先消除重复混音并 A/B，不直接叠新降噪。
5. 0dB 导出峰值仍为 0.0dB。应继续诊断，不能宣布“不会失真”；源峰值与输出混音不等同。
6. 半透明参数已写但画面仍黑。应以实际像素为准追查，不把 tool success 当视觉 PASS。
7. 本地导出返回路径但文件还没生成。状态是队列/运行未知，不可交付为完成，也不重复提交。
8. 用户说全自动并给 1.1 倍。应自行完成，保持指定速度只施加一次，不重新问模式、不依字速擅改倍率。

这是工作流行为检查，不证明真人成片的听感或视觉验收通过。
