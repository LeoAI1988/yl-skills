# 口述底稿公众号写作

## 共同写作约束（每次必读）

起稿前读取并执行 [写作公共约束](references/writing-foundation.md) 及其完整规则；直接调用本 Skill 也必须执行写前、写后和交付检查。它约束所有框架与风格，保护用户原话和有效修辞。下文或旧参考中的绝对词句禁令与它冲突时，以公共规则的语义裁决为准；脚本命中不能替代审稿。


原稿已经奠定约 80% 的基础。先在原稿上修，再在缺口处补。不能把原稿压成提纲、换一篇通用文章，再用几句原话装饰。

## 写作合同

- **底板**：当次本人原稿的核心判断、事实、完整思想推进、比喻、标志句、口语节奏与野心。最大程度保留具体措辞；保留有功能的重复。80% 是作者对创作基础的描述，不是相似度或字数达标线，尤其不能要求扩写后的 80% 字符来自短稿。
- **补充**：从本人知识原子、完整原文、逻辑链和表达资产中找缺失的解释、机制、案例、边界及桥接。材料必须服务原稿已有问题，不能因检索命中就另开主题。
- **修正**：纠正转写错误、病句、悬空指代、真正冗余和逻辑断裂。原话保留不等于保留事实错误；重要立场冲突或语义不确定点单列，不替用户静默换立场。
- **技术底座**：[DBS 内化编辑规则](references/dbs-editorial-foundation.md) 已包含标题、开头、结构、逻辑、理解难度、冗余与兴趣检查；运行时直接使用本地规则，不要求再安装或调用 DBS。
- **三层结构**：本 Skill 是**总框架**，管口述底稿变成文章的全过程——原稿保全、缺口检索、本人知识原子与表达资产的调用、编辑证据卡、交稿前复核、安装者可选结尾。写法挂在它下面，分两层：
  - **第二层，具体写作框架**：`chekhov`、`impact` 二选一，对应同级的两个 yl 风格成员；另可显式选择自带 `editorial` 编辑模式，不依赖外部风格。
  - **第三层，表层风格**：默认沿用所选框架。用户明确要求“契诃夫底层＋暴击表达”时，可在 `chekhov` 内启用 `impact` 的有限节奏辅助，不能叠两套全文模板。
- **换框架或换风格，都不改变总框架的要求**：必须检查本人知识与表达资产接口，已提供且可访问时实际检索回读，留下编辑证据卡并做交稿前复核。未配置/不可访问/无命中按知识接口记录，不伪称已调用；新增事实须有依据。引用协议见 [风格适配器](references/style-adapters.md)。

若规则冲突：本次用户明确要求与事实真实性 → 当次原稿意图及措辞 → 本人补充材料 → 所选写作框架的机制约束 → DBS 技术修正 → 所选表层风格。新口述与旧资产的立场冲突不能用“旧资产更多”压过新稿。

## 接收与路由

从用户现有消息提取输入、处理幅度、风格和篇幅；不要发一份问卷或要求再交已经给过的资料。

| 输入与要求 | 执行方式 |
|---|---|
| 语音输入文字、录音逐字稿，要求润色 | 局部修补，默认长度接近原稿，不为了“公众号”自动扩写 |
| 三四分钟或更长的视频逐字稿 | 作为本人原稿处理；去掉纯口播指示，保留叙事与论证功能。必要时补文字阅读缺失的上下文 |
| 三四百字短视频稿，要求 1500—2000 字公众号 | 沿原稿论点与顺序定向扩写，用本人材料增加论证深度，不凑同义段落 |
| 只给音视频文件或链接 | 先取得可用完整逐字稿；保留时间戳/来源映射。只有标题、摘要或局部字幕时不得宣称已有完整原稿 |
| 只有题目、知识原子或第三方文章 | 缺少本流程底板，说明需要本人原稿；可继续定位材料，不悄悄改成从零写作 |

用户指定具体写作框架或风格就直接执行。没指定且无已确认选择时，提供契诃夫（常用首选）／暴击观点两种选择；等待时继续原稿整理、缺口检索和证据装配。用户明确“你决定/直接写”时结合材料选一个并简述理由；用户只要原稿局部修补时可用自带 `editorial` 模式。仅指定契诃夫时不加载暴击依赖。调用本 Skill 即授权使用其已约定的引用链，无须逐个再问是否调用。

篇幅以当次要求为准，不能套用旧 Skill 的默认 1800 字或硬上限。没有篇幅要求就按处理幅度判断；扩写未给范围时简短说明预计长度即可，不必阻塞。纯润色不擅自压缩成熟稿。

## 执行流程

### 1. 冻结原稿，识别真正要保留的内容

完整阅读原稿。保留原始版本、路径和哈希；聊天输入首次落盘应为逐字记录，不做“清洗后原稿”。资料引用路径不等于允许复制录音大文件。

以原段落或时间段标为 S01、S02…，记录每段的论证作用与承接关系。摘出关键原话、金句、比喻、结尾、思想来路、有效重复和必须保留的商业语义，形成保留清单。先记录原话，再解释功能，不以摘要替代。

明显 ASR 错字可修正；听不清的专名、数字、否定词或指代若影响结论，回听或查已有来源。无法确定时留下具体待确认点，不猜。记录“这是用户主张”与“它已核实”两种状态。

### 2. 检查缺口，按缺口调用资产

**任何框架与风格都必须检查可用的本人材料接口。** 已提供知识库或表达资产时，围绕缺口实际检索并回读，记录路径、原话定位、对应缺口和新增事实覆盖情况。没有配置、不可访问、无相关命中是三种不同状态；如实记录后可基于现有原稿完成有依据的修补，不能伪称已经检索，也不能把未安装作者私人知识库当作永久阻塞。

阅读 [知识与原稿接口](references/knowledge-and-source-contract.md)。用原稿主张、具体痛点及缺失环节检索；重点回读原话、完整递进和上下文。相关 synthesis 先完整理解，再按节回读原对象。

建一份轻量内部 [编辑证据卡](references/edit-card.md)：保留清单、逐段处理、缺口、拟用原话与来源、增补去向。它在成文前完成，不需要用户批准，不输出成冗长前置报告。简单稿可以只记真正变动的段落。

每段新增内容必须回答：补原稿哪里、凭什么补、怎样接回原来的下一步。允许不引入新事实的逻辑桥接；Agent 新推导不能伪装成用户历史原话。新数字、亲历、对白、具体案例不得凭空补齐。

材料不够支撑目标字数时，先充分展开已有因果与解释。仍不足则如实交可支撑的稿件及一个具体素材缺口，不反复复述、硬贴无关案例或宣布已达标。

### 3. 就地修补或沿骨架扩写

先修转写/病句/指代，再修局部逻辑，再填证据卡确认的缺口，最后应用所选风格。已有顺畅原句不因“更像某作者”而改写。

默认保留原稿推进顺序。只有局部移位能解决明确问题时才移动，并在卡里写原因；若原稿主论证本身不成立，保留可用部分并指出矛盾，不先按通用模板重搭整篇。

扩写优先展开原稿压缩过的“为什么、怎么发生、实际意味着什么、适用条件”，调用合适的本人真实案例。不是把一个短视频观点复述五遍，也不是扩成一套新理论。概念足够时先减冗余、补连接，不增加概念负担。

写作框架通过外部引用装配（`chekhov`／`impact`，或自带 `editorial`），表层写法在选定框架内**互斥选一个**；框架机制不能改命题、不能接管骨架。不得照搬外部 skill 的固定文章五段式、作者语料或包装流程。

### 4. DBS 技术复核与原稿对照

按内化底座检查：标题承诺与正文兑现、首屏对象与继续阅读理由、各段新增信息/论证作用、前提与因果、术语及指代、跨段跳跃、同一观点两三次出现是否真正递进。

标题与开头优先取原稿最有力量且能兑现的表达。无需强制悬念、固定几秒、固定标题字数、给每段加钩子或制造普遍焦虑。正文成立后再定标题；默认交一个主标题，只有用户要备选或确有必要时补少量候选。

做一次原稿→成稿的逐段对照：每个关键判断、原话与推进是否仍有位置；删改是否必要；新增是否有来源或只是解释；是否削弱本人表达。有效复沓、动员句和结尾回扣不能按重复词计数删除。

按 [编辑证据卡](references/edit-card.md) 运行机械检查并做语义复核。机械通过只证明计数和所登记的原话检查通过，不能宣称“保真 80%”“风格质量已保证”。发现问题优先修有关段落，不重写一篇。

### 5. 交稿与回改

默认交“主标题 + 一份完整正文 Markdown”，附不超过几条关键改动及确实需要用户判断的问题；证据卡、风格运行材料、完整差异留在内部。用户只要正文时不要附审校报告。

公众号结尾使用安装者本次提供或已经确认的文字。没有配置则自然收束；不附来源作者的签名、促销、联系方式或赠品导流。可使用 `--cta-file` 核对自己的固定结尾，它接在原稿自身的情绪/判断结尾后。

用户回改时，以最新手改稿为当前底板，只改指出的问题及其必要连带处。局部满意的段落保持稳定；用户换用另一个写作框架或风格时，事实、证据、观点和已确认句子不重置。用户说“重写”时按从零处理：抛开上一版成稿，只依据原始材料重新规划与成文，不得在上一版句子上删改。

文件状态、定稿归档和后续授权按 [知识与原稿接口](references/knowledge-and-source-contract.md) 执行。写作本身不触发排版、配图、发布或云端写入；用户已给的明确授权不重复询问。
