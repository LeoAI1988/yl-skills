# 外部风格引用合同

本文件只规定如何引用现有风格方法。正文始终由本 Skill 的原稿保全、定点补全与复核流程管理，不把任务转交旧 Skill 重开一次创作流程。

## 1. 三层结构：总框架 → 具体写作框架 → 表层风格

优先级：用户本轮要求与锁定原话 → 原稿事实、立场、思想递进及本人补充资产 → 所选写作框架的机制约束 → 本 Skill 内化的 DBS 检查 → 所选表层风格。任何技巧均不能改换文章命题、掏空原稿、添加假经历或削平用户的判断与野心。

### 第 1 层：总框架（本 Skill，不可替换）

`yl-write-voice-led-wechat` 是口述底稿成文的总框架，管全过程：原稿保全与保留清单、缺口检索、**本人知识原子与表达资产的调用**、编辑证据卡、交稿前复核、安装者可选结尾。换任何具体写作框架都不改变这一层的要求；新增事实没有本人材料或可靠来源支撑时不得写成事实；未配置个人资产按知识接口记录。

### 第 2 层：具体写作框架（互斥选一个）

`writing_framework` 必须互斥取一个值；当前两个风格框架及一个自带编辑模式可选：

| 值 | 用户说法 | 使用的外部依赖 | 决定什么 |
|---|---|---|---|
| `chekhov` | 契诃夫、克制细腻 | `yl-chekhov-deep-writing` | 观察与解释顺序、细节承担判断、克制且有余味的节奏 |
| `impact` | 暴击、咪蒙式观点 | `yl-write-impact-wechat` | 真实冲突、证据承接与节奏 |
| `editorial` | DBS 编辑方法、只修原稿 | 自带 `dbs-editorial-foundation.md` | 结构、逻辑、理解难度、共鸣与传播机制；不加载外部 DBS |

框架可以继续增加，但新增的是写法，不是“要不要用本人材料”。

### 第 3 层：表层风格（互斥，可选）

在选定框架内部再选。`chekhov` 框架下可为契诃夫风或 `impact`（暴击风、咪蒙式）；`impact` 需额外引用 `yl-write-impact-wechat`，它只增加节奏落差、判断落锤和准确锋利的对照，并仍受契诃夫底层思维约束。`impact`、`editorial` 框架是否再分表层风格，按各自合同执行。

“咪蒙式”是用户用来选择节奏的名称，当前真实实现为 `yl-write-impact-wechat` 的安装者表达合同；不声称接入了一套未找到的咪蒙作者语料或专属 Skill。任何框架与风格都不逐句仿作，不搬作家情节、典型意象或原句。

用户指定框架或风格后，本 Skill 即按相应行执行引用，不重复索取使用旧 Skill 的授权。未指定时先做原稿识别、缺口定位、资产检索与纠错，框架选择按主流程处理；不得偷偷同时做两版或用混合写法顶替选择。

“原稿奠定 80%”表示它决定观点、案例、递进和主要表达，不是要求成稿字数有 80% 为复制片段。扩写后原文字符占比会下降，但核心命题与必留句应仍然可逐条回指。风格修改默认发生在缺口和病句处；原稿本来通顺的段落允许原样留下。

## 2. 依赖定位、版本与读取

依赖清单见 `style-dependencies.json`。只从本目录父目录中定位已选的固定 `yl-` 成员，检查必需文件是否存在且可读；不搜索作者私人目录，不自动安装或更新。记录实际路径与 SHA-256，路径只留在安装者的内部工作记录。完整集群的发行指纹可在 `cluster.json` 核对；单独安装则记录本次观察值，不冒称与发行包一致。

同一任务中指纹发生变化时，回读变化与兼容性，记录 `compatible_reread` 后继续。不能仅凭名称声明加载成功，也不能更新来源清单掩盖漂移。

首次引用或已发生变化时读取下列内容；同一任务内无变化不反复读取：

| 依赖 | 必读文件或部分 | 可用范围 |
|---|---|---|
| 契诃夫框架，必需 | `SKILL.md` 的目标边界；`references/workflow.md`；`references/mechanisms.md`；`references/media.md` 的公众号段与共同媒介约束；`assets/runtime-profile.json`；`scripts/load_runtime_profile.py` | 思维、适用条件、代价、事实与因果检查、中性参数 |
| 契诃夫框架，启用外壳时 | `references/language-shell.md` | 本文确有适用材料时至多两个参数；不能为凑参数重写原稿 |
| 暴击风格，仅 `impact` | `SKILL.md` 的核心合同、安装者表达校准、快速验收与红线；`references/style-contract.md`；`references/sourcing-and-claims.md` 的证据、归属与主张分类 | 原話保护、节奏、短句停顿、准确对照、判断与证据承接 |
| 自带编辑，仅 `editorial` | 本目录 `references/dbs-editorial-foundation.md` | 完整 CF-01—CF-08；无需外部依赖 |

不用旧 Skill 的整体任务入口替换本 Skill 流程。尤其不继承：从零新写母版、固定科技题材结构、1800 字默认硬限、重启选题、额外通用写作 Skill、仅因输入含 Get 字样就调用云端、强制分阶段审批、封面/HTML/平台发布和云端同步。篇幅、原稿存放、定稿与后续授权统一由本 Skill 主流程和本轮任务管理。固定公众号结尾采用安装者已经提供或确认的约定；不因风格包新增促销内容而自动变更。

## 3. 契诃夫运行参数的实际加载

在解析到的依赖根目录运行只读校验：

```text
python -B <已解析的yl-chekhov-deep-writing目录>/scripts/load_runtime_profile.py
```

读取退出码及 JSON，要求退出码 `0`、`status=available`、`runtime_payload.profile_status=stable`。这是每次实际运行后才能记录的状态，不能继承作者旧机器上的成功记录。

loader 返回的是完整 profile，仍含带作者标识的 `schema_version` 和来源哈希。协调层可以保留这些字段核对版本，但传给成文步骤或成文子代理时必须二次按白名单投影，只保留：

```json
{
  "mechanism_parameters": [],
  "shell_parameters": [],
  "constraints": {
    "forward_identity": false,
    "forward_source_text": false,
    "forward_research_cards": false,
    "max_primary_mechanisms": 1,
    "max_auxiliary_mechanisms": 2,
    "max_shell_parameters": 2
  }
}
```

数组只放本篇实际选定的中性参数对象，不照抄空数组；`constraints` 保留已加载 profile 中的完整约束，包括 `use_generic_fallback=false`。不要转发 `schema_version`、`source_manifest_sha256`、作者名、路径、研究卡、原著或中文译本。成文器另外接收本人的原稿、锁定句、已核补充片段和修补任务，不能把文学参数当成文章内容。

若 Python 暂不可用，可只读 `assets/runtime-profile.json` 并逐项执行 loader 当前公开的同等检查：schema、stable、3 个机制代码、每个适用与代价字段、角色列表、3 个外壳 mode、3 个禁止转发字段为 false、1/2/2 数量上限及去身份检查。记录 `validation_mode=manual_equivalent`；不能声称脚本已通过。未完成等价核验不得声明加载成功。

依赖缺失时继续完成原稿保全、来源检索和确定性纠错，把风格步骤标为未完成并说明具体缺失文件；不得用模型记忆中的泛化“契诃夫味”冒充引用成功。用户明确同意普通润色时才按该改动完成普通版本。

## 4. 两模式共享的底层思维（`chekhov` 框架；其他框架同受这些约束）

本节机制属 `chekhov` 框架。选用 `impact` 或 `editorial` 时，机制清单以各自 skill 为准，但本节的真实性、因果、观察、反例与后果约束同样适用，不得因换框架而放弃。

在既有原稿上寻找适用机制，最多一个主机制、两个辅助机制。没有适用材料时允许本篇不启用特定机制，并说明 `not_applicable`；仍执行真实、因果、观察、反例与后果约束，不为了“像文学”造现场。

| 中性代码 | 何时可选 | 对本稿做什么 | 何时不用 |
|---|---|---|---|
| `m_constrain_judgment_with_observation` | 本人原稿或补充资产确有能校准主张的动作、过程、结果 | 用现有细节接住抽象判断；补上观察与结论之间欠缺的一步 | 只有装饰性细节；细节不足以支持结论 |
| `m_reweight_ambiguous_fact` | 同一真实事实有多种可比较解释，且有前后变化与反证 | 修好解释之间的关系，让读者理解作者怎样形成判断 | 没有比较材料；会把制度或现实伤害心理化 |
| `m_extend_consequence_after_local_closure` | 本人材料已呈现一次决定或完成动作及其后续责任/状态 | 保留原稿确有的持续后果，减少最后一段重复说教 | 没有后续材料；需要编造开放结尾 |

保持作者对事实的判断力度，同时核对事实是否真的支持它。必要的反例和适用边界只补到帮助理解的位置，不把全篇改成免责声明或辩证套话。不强造“两股张力”，不为了机制另起题目，不把全稿推倒再写一遍“母版”。

## 5. 契诃夫表达模式

从已修补、已保全的原稿直接润色。重点是指代清楚、因果接得上、细节承担论证、长短句自然，保留作者本来有的锋芒。最多选择两个外壳参数：

- `clue_before_explanation_turn`：仅把现成的新线索放到需要解释的位置之前，不能凭空补线索。
- `accumulation_then_short_release`：若原稿已有多层递进，可把落点单独释放；不每段都套“长长短”。
- `voice_checked_by_consequence`：有可归属自述及真实行动/结果时才并置，不能补假对白或心理活动。

从 runtime profile 读取频率上限和 `max_consecutive`；这些是密度上限与警戒参数，不是必须完成的次数。不要把用户爽利的口述改成伤感散文，也不要添加俄国小说意象或故作含蓄的结尾。

## 6. 暴击表达模式

先通过第 4 节底层检查，再引用 `yl-write-impact-wechat` 做表达增强。整个正文仍是同一份修补稿。

1. **强化用户已有判断。** 优先保留原稿中最强的原句，去掉挡在它前面的套话；不要制造一个更极端的新结论。
2. **先成立再落锤。** 事实/动作/机制解释之后才用短句形成停顿。若短句只是重复上一段，合并或删除它。
3. **对照必须真实。** 从原稿的前后、投入结果、说法行动或旧新差异里提炼；不凭空制造敌人、阶层羞辱、恐慌或虚假的两难。
4. **保护完整递进。** 原有段落顺序能成立就不改。允许把最能说明主题的已说判断前置为开头，但需保留其条件，并立即交代具体对象；不得让标题/钩子倒逼文章换观点。
5. **控制密度。** 重要判断可以独立成段，其余仍用完整段落承接。不能把 1500—2000 字公众号切成 100 个口号；不强迫每段都有金句或比喻。
6. **保留个人语气。** 加强的是本人的动词、比喻和节拍，不是外部作者的习惯句。用户没有使用过且不自然的狠话不加；不机械使用“你以为……错了”或“不是……而是……”机关。

暴击模式中的节奏增强也占表达密度预算。若同时启用契诃夫外壳，仍以全篇最多两个显著参数、单段至多一个高显著信号控制，不叠加两套全量模板。DBS 的标题、首屏与共鸣修正完成后，再过一次第 4 节检查；承诺强于证据时回退该处措辞，不能补造证据。

## 7. 内部调用记录与验收

主流程内部审校记录至少保留：

```yaml
writing_framework: chekhov # chekhov | impact | editorial，必须单选
style_profile: chekhov # 框架内的表层风格；chekhov 框架下为 chekhov | impact
dependency_status: verified # 或 compatible_reread / unavailable
resolved_dependencies: [] # 路径、observed_sha256、读取时间，仅协调层保留
validation_mode: loader # 或 manual_equivalent
selected_mechanisms: [] # code、主/辅、原稿或补充片段ID、适用理由、已检查代价
selected_shells: [] # mode、实际作用段落、没有破坏原话的理由
asset_calls: [] # 总框架硬要求：实际查询范围、命中路径与原话行号、对应缺口，或未配置/不可访问/无命中状态
impact_adjustments: [] # 仅 impact：段落ID、改变了哪项节奏功能
not_applicable: []
```

验收看正文实际变化，不能用“已调用 Skill”代替结果：所有核心命题、必留句及重要比喻可回指；新增内容各有缺口和来源；没有改变不确定性的等级；删重复后保留有功能的递进；原稿已通顺处未被无谓换词。任何模式都不能承诺爆款、传播提升或作者会一次通过。外部依赖可读取、脚本可运行，只证明方法接入完成，审稿成本是否下降仍须真实稿件验收。

旧框架名 `dbs` 是 `editorial` 的兼容别名，进入本文件已有的内置编辑模式，不加载外部 Skill。别名映射见 [style-dependencies.json](style-dependencies.json)。
