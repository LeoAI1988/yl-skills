# 从原稿到可交付正文

本流程围绕本 Skill 的原稿、编辑证据卡、成稿和作者回改运行。使用本次明确的编辑幅度及篇幅，沿用已经选定的框架。起草前执行 [写作公共约束](writing-foundation.md)。

## 建立一次编辑的输入

保留可回查的原始全文，另建工作稿。给原段落或录音时间段分配稳定定位，记录作者、版本和完整性。修转写时保留原识别文字及核对依据。来源只有局部字幕时，先补齐本篇需要的范围，并说明已读范围。

在 [编辑证据卡](edit-card.md) 登记本次目标、必留原句、允许调整的部分和当前缺口。已有的录音、用户手改与历史作品分别标识。新稿所表达的当前立场以本次材料为准，历史语料用于补充可用的解释和经历。

直接把原稿的可用段落放进工作稿。保留其动词、比喻、语气、思想来路和从问题推到判断的过程。段号帮助复核，交付正文按正常文章阅读。

## 一处改动怎样成立

每项修改要能落到某一原段或新增位置，并回答下面的问题。

| 要确认的内容 | 证据卡中的记录 |
| --- | --- |
| 当前读起来有什么具体障碍 | 引用受影响的原句及相邻上下文 |
| 本次准备怎样改 | 纠错、补足、删去、移动或保留 |
| 改动后应发生什么变化 | 哪个对象清楚了、哪个因果补齐了、哪处重复减少了 |
| 依据从哪里来 | 当次原稿定位、已回读的本人材料、核实的外部来源或明确的编辑推导 |
| 原有内容怎样保住 | 必留措辞、适用条件、否定范围、叙述立场及结尾的实际去向 |

能修一个指代就先修指代。涉及事实的更正要回到证据，存在真实观点冲突时记录双方的时点和上下文。对已确认正文的排版任务，事实疑点单独交代，正文按授权范围处理。

例子仅用于验证编辑动作。合成原稿为“这套备份每周跑一次。断电那周没跑。所以我后来加了提示。”若删掉中间一句，后面的改变缺了原因。可以删重复解释，仍须保留断电与新增提示的关系。这个例子不提供实际产品事实。

## 把补充放到需要它的位置

先读到读者确实无法继续理解的位置，再检索。查询词取自原稿的对象、判断和缺失环节。本人知识库已经配置时，使用同级 `yl-knowledge-search` 回读完整原文，覆盖尚未形成原子的正文。索引不可用时记录实际降级方式。

找到材料后，记录它填补的位置、原话、上下文、时间和归属。与本篇无关的好句继续留在资产库。本篇已有充分解释时，维持其完整展开。多份来源对同一事物用词不同时，先核对是否同一对象，再决定术语。

可用的补充包括被口述压缩的推理、原有例子的关键动作、读者需要的背景、已提供的操作条件和实际后果。涉及新增数字、亲历、对白或产品能力时，先取得对应事实依据。编辑推导要与作者历史原话分别登记。

材料不足以支撑目标篇幅时，先展开已有解释。仍有缺口就交代具体缺少什么以及当前稿件的实际长度。每一新增段都应能回接到原稿后续内容。

## 通读工作稿时复核关系

把连续段落放在一起读。指代应有可辨认的对象，判断应带上必要条件，因果应有实际中间环节。时间变化、引用他人和作者立场变化都要让读者能够跟上。

同一判断再次出现时，检查这一处是否补了新的依据、修正、递进或情绪作用。记录保留功能，删去纯重复时再核对前后连接。有效反问、复沓和自然长句按其作用保留。

文章涉及产品操作时，核对前提、实际动作和可观察结果。人物与观点文章保留其叙述目的。具体读者需求决定需要解释到哪里。阅读后的实际反应可用评论、访谈或行为数据验证，编辑判断中注明尚未取得的反馈。

## 从完成的正文确定标题与开篇

在当前正文中定位最适合作为入口的原话，保留原稿的真实对象与表达力度。标题每个事实性词语、数量和结果都应在正文找到依据。作者已给定有效标题时沿用。

单独阅读开篇，再读紧接的正文，核对读者此时知道谁、发生了什么、接下来能读到什么。需要背景的原话应带上背景。前置某段时，复核其原位置及新的接续。可直接交代结论，也可沿原来的经历展开，由本篇材料决定。

内部比较确有差异的候选，按用户要求交一个主标题或少量备选。标题长度使用目标平台和本次任务的限制。标题引用、数字、时限和效果承诺与正文采用同一事实范围。

## 让最后一次修改可复核

对照原稿保留清单逐项找出成稿位置。核对重要原句、解释链、思想来路、语气及自然结尾。原文被替换的地方须有具体编辑原因。对模型新增句逐句检查其作用，无作用的前缀、过渡和审稿旁白移除。

执行 `check_article.py` 的原句、篇幅和可选结尾检查，以及 `check_writing.py` 的只读候选扫描。按上下文裁决每项候选，记录最终稿哈希和未解决问题。机械检查结果只覆盖相应指标，语义对照需要实际阅读全文。

交付遵循主 Skill 的 Markdown 格式。编辑记录留在项目中，用户要求时可查看。作者回改后更新基稿和版本，仅处理点名范围及必要关联。用户明确重写时重新回读原始材料并建立工作稿。需要长期保留的认可样稿和偏好依用户授权存入个人层。
