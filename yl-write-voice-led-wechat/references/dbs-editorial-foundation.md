# 已内化的 DBS 编辑底座

本文件是新 Skill 自带的可执行编辑规则。六个 DBS Skill 的有效技术已经摘编进来；运行时直接读本文件，不调用、不安装、不查找 DBS。来源快照、哈希、短摘录、改编与排除记录见同目录 `dbs-source-manifest.json`。

适用对象：用户自己的口述转写、长短视频逐字稿、短文和已有初稿，经修补、润色或扩写成为公众号文章。该底座负责清楚、连贯和吸引力；句子风格按主 Skill 已选定的写作成员执行。

## 0. 所有技术判断的上限

- 先识别用户已经说出的核心判断、完整推理、真实场景、标志性原句、比喻和情绪递进，再判断是否需要修补。口述稿是编辑底板，不能把它概括成主题后另写一篇。
- 原文保护约束技术优化：清晰但有野心的判断、鲜明立场、思想来源、排比、回环、长句、结尾可以原样保留。不能因为更平、更短、更像通行模板就替换它们。
- 原话保护不豁免明确事实错误、逻辑自相矛盾或转写错误。事实与推理先单独核实，局部修正并记录；无法核实的关键新增材料不得写成事实，无法判断的关键原话保留在内部问题清单，不能猜一个意思替换。
- 技巧是修复工具，不是任务来源。不能为了“有悬念”隐藏必要信息，为了“一个观点”删掉成立所需的复杂推理，为了“扩大人群”换掉用户原本服务的对象。
- 所有诊断必须引用原文位置；“不够丝滑”“缺少情绪”“不够爆”不构成改动依据。已经有效的文字列入保持不动项。
- 技术检查内部完成。用户已要求修补、扩写、润色，就直接执行；不继承 DBS 的诊断后再问一次是否改稿、要求付款链接、引导其他 Skill、生成聊天室等对话流程。

## 1. CF-01：先画原稿功能图，再处理整体结构

逐段登记 `原稿段号 → 原句/关键措辞 → 该段新增的判断 → 段落功能 → 服务哪条主线 → 与前段关系`。功能可选：开场、场景、问题、背景、判断、原因、论证、案例、反例、适用边界、转折、行动、情绪蓄积、回扣、结尾。功能允许重叠。

执行判断：

1. 用一句内部工作句表明这篇文章最终希望读者理解什么，并保留用户原本的主要用词。这句用于核对方向，不代替原稿和正文。
2. 列出全部子判断，确认各自是主线推进、成立条件、证据、解释、边界还是结果。主线可以包含完整的多级判断链；不要求正文只说一个简单结论。
3. 对看似跑题的段落做删段反事实检查：删掉后，读者还能理解前一个关键判断的具体含义、来由、适用范围和作者为什么在意吗？若不能，这段是必要论证，保留。
4. 先修补局部指代、句子顺序和相邻段承接。只有原顺序造成明确理解障碍、提前泄漏必要前提或真正重复时才移动段落；记录旧位置、新位置和原因。
5. 不把文章强制编成“痛点—反转—三个方法—升华”，不按模板增设小标题，不把长逻辑链压成金句清单。公众号能承载分析长度，应给原稿的推理留足篇幅。

扩写时依照原稿功能图填充已经存在的节点：具体动作、机制中间环节、本人真实案例、必要概念解释、反例与边界、同一问题的后果。先查询本人资产并回读上下文；不能拿一个新理论或第二套主张填篇幅。

## 2. CF-02：逐处找逻辑断裂，补出缺失关系

对每个相邻段落，放在一起读“上一段末尾 + 下一段开头”，依次回答：

- 前段留下的疑问是什么？本段为什么接在这里？
- 关系到底是因果、举例、具体化、对照、条件、时间推进、递进、回扣还是切换角度？
- 本段依赖的对象、事实、定义或前提，前文是否已经提供？
- 读者需要自己猜出的那一环能否用一句具体信息说清？

| 障碍 | 最小修复动作 | 不允许的替代 |
|---|---|---|
| A 后直接到 C，缺少 B | 补上“什么通过什么机制导致什么”的中间步骤；优先调用用户既有完整推理 | 只加“因此/所以/底层逻辑”来伪造推导 |
| 从一个个案推到整个群体 | 补充支持范围、其他本人案例或明确的推断条件；证据不足则把断言收回到原材料能支持的范围 | 把一个故事自动当成普遍规律 |
| 数据后直接给观点 | 说明数字的口径、比较对象以及数字为什么支持这项判断；只补读者理解必需的信息 | 在未经支持的数字后直接加“这说明” |
| 原因讲到一半换题 | 先用原有材料收住当前因果，再点出下一段要解决的余下问题 | 加“更可怕的是/真正的问题来了”但不给关系 |
| 时间、对象、视角突然变化 | 补一个时间锚点或清楚主语；必要时把已有背景前移 | 凭空编造发生时间或人物动作 |
| 类比被当成证据 | 保留比喻力量，说明它帮助理解的对应关系；结论依靠另行成立的证据/推理 | 因为比喻好看就宣称两件事事实等同 |
| 条件遗漏、范围偷换 | 恢复原稿已有条件；新增限定只覆盖实际缺口 | 用“可能、一定程度上”等词遍地稀释整篇立场 |
| 原话内部互相矛盾 | 对照完整录音/逐字稿及本人同主题原文，区分转写错、语境不同和真实观点变化 | 擅自选助手更喜欢的一边抹平冲突 |

修补顺序：查原稿漏掉的上下文 → 查用户本人相关资产 → 重排已有信息 → 补一条必要解释。需要新增事实而没有来源时，缩小补写范围并登记缺口，不造“真实案例”。

## 3. CF-03：诊断重复，不把修辞重复当冗余

把候选重复句放在一起，比较的是 `命题 + 新增信息 + 论证功能 + 语气/情绪功能`，不是同词出现次数。

**可删或可合并的重复**必须同时符合：核心命题相同；没有新事实、机制、条件、边界、例子或行动；不承担新的转折、递进、回扣、身份确认或节奏作用；删后仍能保持原稿的论证力量和说话口气。

**应保留的重复**包括：

- 先提出判断，再解释为什么，再用真实案例让它成立：同一观点出现三次，功能各不相同。
- 同一比喻从个人经验推进到组织或社会层面：对象/尺度变化提供了新信息时，不能当作复述。
- 递进排比每一项提高程度、补充对象或改变后果；连续追问逐层推进问题。
- 结尾回扣开头、带着已经完成的论证重说一句话，产生收束。
- 用户刻意的口头节奏、标志性金句和强调；只要承担明确作用，就不按次数删除。
- 两个案例分别说明机制与反例，或同一观点的不同边界。案例数本身不是冗余证据。

局部操作：

1. 对纯口误、起句失败、机械复读，保留承载完整意思的原句。
2. 对同义绕圈，优先保留用户最有力、最有节奏和最完整的版本；将其他句里独有的条件并回去。
3. 对重复例子，选最能证明当前节点且细节足够的一例，其余可压缩为一个有区别的信息；不能为短而删掉唯一可感的现场。
4. 对连用的“很重要/值得重视/不可忽视”，若没有递进信息，删空的强调，保留用户真正的具体判断。
5. 凡是删除整段、金句、标志比喻或思想递进节点，均需在内部改动表列明“删掉什么、功能为何已被覆盖、独有措辞是否保住”。无法说明就撤回删除。

## 4. CF-04：检查理解难度与句子可读性

检查具体障碍，而不是用字数判定坏句：

- **主谓关系**：一句话的行动者、动作和对象清楚吗？连续“这个、那个、它、他们”是否指向同一对象？能补主语就不换整句。
- **转写残留**：修正同音词、断句、缺词、成句失败；保留有效口头表达。视频稿里的“看这里/像刚才这个图”改成文字读者能理解的具体对象；没有图和原始证据时不能猜图内容。
- **前提负担**：一句话要同时记住多少未解释的新东西？必要术语保留，并在第一次需要时紧跟普通话解释或本人已有的比喻；已有读者可理解的专业词无需重复科普。
- **语法嵌套**：定语套定语、多层转折导致找不到主干时，优先拆掉一层或把条件前移；有完整节奏的长句不因超过 30 字而拆。
- **抽象堆叠**：几个抽象名词挤在一起时，换回用户已经说过的具体动作、对象、代价或结果；不能凭空增加现场、对话、心理活动。
- **节奏**：连续短句若把推理切碎，合并具有同一推进的两三句；连续长句若造成负担，在判断转折处落句。暴击模式也要保留足够的解释长度。
- **问句**：一问一答确实推进读者正在问的问题时可留；机械连续“你以为……其实……”而没有新信息时改成用户原来的直接判断。问句和书面词不在黑名单里。
- **认知验读**：模拟只知道前文的读者读到此处，能否复述“谁遇到什么，作者为什么这样判断”？不能时先补缺的信息，不立刻给句子加情绪。

## 5. CF-05：开头是正文的试用装

先检查正文有什么可兑现的价值，再处理开头。用三项工作框架核验：`话题（讲什么） + 抓手（为什么继续读） + 可信基础（这项判断/经历从哪里来）`。三项可以由首个完整阅读单元共同完成，不要求塞入同一句，也不强行晒成绩或权威。

具体执行：

1. 首段离开标题仍能建立必要语境；代词不悬空。标题可以与首段分工，不要求首段重复标题。
2. 按原稿素材找自然入口：真实场景中的不对劲、用户已经说出的锋利判断、真实前后变化、有口径的数字、有价值的比喻、读者当前处境。入口服务原主线，不按“结果+反转最高级”机械排序。
3. 读者看完开头，应该知道一个值得继续读的问题，或想看明确结论的理由、细节与后果。**结论先行合法**；不为了悬念把原稿好判断改成泛泛“为什么”。
4. 可信基础可以是可核实的本人经历、明确观察对象、具体过程、正文可展开的推理；不需要每篇自报成绩，也不能套用 DBS 原作者成绩和名人轶事。
5. 建立开头承诺清单：开头每个问题/承诺 → 正文兑现段号。正文回答 B 而开头许诺 A 时，优先把开头拉回正文的真实内容。
6. 没有开头问题就保留。需要修时，先用原稿内的已有一句调整；只有原稿素材不够才从已核验本人资产补一项。
7. 内部可比较两三个有实际区别的入口，最终交付数量遵循主 Skill 与用户请求，不向用户倾倒十几条待选开头。

不继承“前 5 秒”“正文少于 200 字不合格”“五类素材有三类才可写”“每篇必须留悬念”“必须放大到普世人群”等规则。这些不构成公众号阅读的已验证阈值。三四百字原稿可作为扩写种子，已有含金量的短稿不能因短被拒绝。

## 6. CF-06：标题从正文选择真实张力

先完成正文主线和主要修补，再定标题，防止正文追着标题跑。已经给定的标题先查承诺兑现与表达清楚程度；有效则可保留。

**选择程序**：

1. 圈出原稿及成稿中能独立成立的用户原句、核心反差、具体处境、真实结果和可兑现问题。
2. 判断读者为何要读：想弄懂一件事、纠正一次误判、理解自己处境、获得一项判断、看一段真实经验。只选与正文一致的动机。
3. 优先把用户最有力量的原句压到标题所需的密度。确有需要时，从下面已内化的句法中选一两种，避免把素材硬塞进公式。
4. 每个候选在内部记录 `标题 → 所用原句/素材 → 阅读动机 → 正文兑现位置 → 是否增添事实或承诺`。
5. 逐项验收：对象是否清楚；话题与正文是否一致；张力是否本来存在；数字/人群/时间/结果是否有来源；观点强度是否与证据相符；读者是否还有理由进入全文。
6. 数字只在正文确有对应条目、时间或事实时使用。文章有两条层层推进的判断，不硬拆成“三个真相”。标题字数按用户要求与实际平台限制核对，不套小红书 20 字。
7. 不把“至少两个张力元素”当门槛；一个准确而有力量的原句就可以成立。不给点击率、阅读量或爆款概率承诺。

**可直接调用的标题句法**（编号保留技术溯源，不要求向读者显示）：

| 适合的现有素材 | 可用句法 | 来源及公众号处理 |
|---|---|---|
| 本人作出与惯常行为不同的选择 | 为什么我不再／为什么我不…… | #3；只写本人真实选择，不制造“所有人都……” |
| 真实经历呈现反转 | 我原以为……，后来……／……之后，我反而…… | #6、#45；顺着经历，不把相关性写成因果 |
| 本文讲清一个动作的后果 | ……的后果／做了……，会发生什么 | #16；后果必须有支持，不添“最可怕/必然” |
| 面向明确共同处境 | 给正在……的人／当你…… | #23、#24、#56；处境优先于宽泛身份标签 |
| 正文确有可分步骤的方法 | ……的 N 个步骤 | #27；N 来自正文，不能为标题拆散论证 |
| 本人的可核验结果与过程 | 我如何……／我如何在……内…… | #35；有时间才写时间，无结果就不用这一型 |
| 经历带来一项具体教训 | 从……中，我学到…… | #42、#47；保留用户的实际认识，不强写逆袭 |
| 讨论一个真实争点 | ……是在浪费时间吗？／……已经过时了吗？ | #48、#51；正文须处理该判断，而非空抛问题 |
| 两个容易混淆的概念 | ……和……，怎么区分 | #52；只有原稿确在区分时采用 |
| 原稿有真实原话或现场冲突 | 当……说“……” | #58；引句必须真实并保留归属 |
| 原稿已有行动判断 | 为什么我开始／停止…… | #61、#65；不得新造对所有读者的命令 |
| 用户有明确原则 | 关于……，我的……原则 | #74；允许结论明示，不额外悬念化 |
| 原句本身就是好标题 | 直接使用用户的原句／金句／比喻 | 本任务对公式匹配的补充；不能强行套公式替换 |

被排除的套路：无证据的“专家不敢告诉你/他们不想让你知道”；保证收益、数字倍增、限定时间必成；为争议制造敌人；把个人经验扩大成人人适用。强烈且有根据的用户原话仍保留。

## 7. CF-07：兴趣与共鸣必须由具体文字承担

先用原文固定 `核心主线 + 读者具体处境 + 主要用途/动作`，再选一个最贴合的机制。只有另一机制解释新的问题、原文有触发证据、能带来一项必要修改时，才增加一个辅助机制。没有问题，不为每篇文章生成理论报告。

| 当前真正的问题 | 内部检查 | 可执行修复 |
|---|---|---|
| 读者不知是否在说自己（身份/处境） | “大家、普通人、创业者”背后是否有共同处境和实际利益 | 用原稿已有行动、限制或选择具体化对象，不凭空划敌我 |
| 结论有了，问题为何如此仍不清（框架） | 问题定义、原因、评价、处理方向之间缺哪环 | 补一条有据的因果或判断桥梁 |
| 只有“焦虑/愤怒/委屈”标签（情绪评价） | 哪个目标受阻、谁承担代价、什么难以控制？文字是否写出 | 从本人真实材料补具体处境与代价，不加音量，不编心理 |
| 看完不知道能干什么（用途） | 内容帮助理解、判断、表达、收藏还是行动？ | 强化原稿能提供的那个用途，不为每篇另造行动清单 |
| 需要传播但缺少可转述内容（分享倾向） | 有没有具体用处、独特观察、惊奇、值得转给谁的理由 | 保留并明确用户现成的有力判断、例子或比喻，不强行煽怒 |

上述检查分别来自社会认同/自我分类、框架理论、情绪评价、使用与满足、在线分享研究的编辑化用法。它们是选择修补方向的解释工具，不证明事实、立场正确、读者已经共鸣或平台一定推荐。

内部区分三层：**原文事实**（确实写了什么）、**机制推断**（这些文字可能产生什么理解/感受）、**待验证反应**（实际评论、访谈、行为才可确认）。情绪被激活、读者接受观点、读者愿意转发分别判断。文章主要用于理解或收藏时，不额外注入分享刺激。原作者案例中的数据表现不当成本 Skill 的实测成绩。

## 8. CF-08：一轮总检，修到能交付就停止

按以下顺序检查成稿，重大问题先于小修辞：

1. **原稿仍在**：重要原句、核心判断、完整递进、比喻、思想来源与结尾是否仍能一一找到？被删掉的原稿信息是否有必要理由？
2. **事实与逻辑成立**：新增每项事实都有来源；桥梁是具体关系而非连接词；没有偷换范围和因果。
3. **逐段有推进**：每一段提供信息、论证或修辞功能；每个跨段切换读者都跟得上。
4. **重复判断有功能依据**：没有同一观点机械讲两三次；有用回环、递进、案例和复唱没有误删。
5. **表达可理解**：主语、指代、术语和条件可跟踪；长短句服务原来的思路和选定节奏。
6. **标题与开头兑现**：所有引发阅读的承诺都在正文落地；保留原稿的真实张力。
7. **扩写确实补内容**：新增来自本人合格资产或必要解释，没有用理论介绍、空排比、同义复述凑字数。
8. **复核成本低**：正文可直接阅读；只把重要新增、整段移动/删除和未解决事实放入内部改动/证据记录，交付遵循主 Skill，不把满屏诊断混入文章。

内部问题表：`位置 | 原句 | 问题种类 | 缺失信息/功能 | 最小动作 | 改后句 | 来源 | 保留/修复/待确认`。

严重度只描述文本障碍：高＝事实/逻辑/主张保持错误；中＝理解或承接明显受阻；低＝可选节奏润色。不写“读者大概率划走”、不计算未经测量的留存概率。无具体问题就不改；同一处修复后复核其前后邻段，无新变化不循环重写全稿。
