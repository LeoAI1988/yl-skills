# 全文理解与多主题脚本

## 先把长素材读全

为源文件建立 ID、指纹、实际内容时长和媒体规格；记录录制中断、静音、问答、演示及换话题。分块转写保留 chunk 的绝对开始时间与边界重叠，词级时间统一回源。分块长度按工具能力和内存选择，不规定所有素材切成同样长度。

建立覆盖表：源 ID、源起止、转写/阅读/疑点核实状态。无可靠转写的空档继续处理，不把无字幕理解成无有效内容。逐个话题写出“提出问题—理由—例证—限定—落点”，保留说话者、指代与观点转折。

分块重叠有两种重复：同一原声被转写两次，以及作者本来就说了两遍。前者按绝对源位置去重；后者保留记录并在精剪时听辨。不得仅按相同词串静默去掉真实重复的第二遍。

## 做一张全批分线表

先列候选，再共同分配素材。每条至少记录：

| 项目 | 需要说明 |
| --- | --- |
| 观众与问题 | 观众处于什么情境，为什么需要这一条 |
| 核心判断 | 本片到底论证什么；标题/开头能否被正文兑现 |
| 推进顺序 | 判断、机制、例证、限定与收尾如何接上；不能只有几个金句 |
| 独有证据 | 哪个案例、经历或论据优先归给这一条 |
| 开头 | 源内完整原句、位置、为何能迅速进入主题 |
| 结尾 | 回答本片问题，去掉突然断掉的后半句和依赖下一条的悬空指代 |
| 与其他条的区别 | 问题、结论、因果链、例证及表达方式分别有什么不同 |
| 重复与缺口 | 必要复用、可替代证据、来源/逻辑不足及处理决定 |

例如，同一长访谈可以分别回答“为何迟迟无法行动”“经验怎样形成可复用工具”“能力怎样变成别人能用的产品”。这是不同问题与推理线的示意，不是固定选题、固定数量或本成员自带的作者观点。

源时间几乎不重叠，仍可能都在重复同一个观点；源内必要背景少量复用，也不必机械认定失败。两两检查：是否给出了相同开头、相同关键判断、相同论据顺序和相同收尾。主要贡献相同就合并候选或重分论据。

## 详细脚本交付

每条先给一句选题说明与预计成片时长，随后逐段列：

```text
段号｜本段作用｜源 ID 与绝对起止｜完整保留原话
放在本片的位置｜删留和调序说明｜本段倍速｜预计输出起止
```

“改成更紧凑”不能代替逐字稿。保留原本的思维推进、比喻、野心和口语力量，只做必要删冗、纠错和连接。字幕识别纠字、真正删除原声、源内调序、补录是不同操作；补录须有相应授权。

预计时长按每段保留原声时长除以实际倍速求和，包含前置句、必要气口与已要求的其他画面。首句速度独立时分开算，不把统一倍速套到整片。超过用户上限，先删次要旁支与重复，不加速到难以理解或牺牲完整论证。

方案确认针对内容和范围；剪辑后的声音、边界与画面还要验收。用户已授权直接执行时内部完成上述文件即可，不另造一个确认门槛。
