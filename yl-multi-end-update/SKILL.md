# 多端更新

以 [个人配置约定](../yl-toolbox/references/profile.md) 中的 `core_root` 定位维护真源，读取个人说明。适用于维护者已经登记的端点。普通用户安装发行包走 [整包安装](../yl-skill-sync/SKILL.md)。

## 确定本次发行

1. 从 profile 所在目录读取安装者维护的 `multi-end-update.json`，或通过参数指定。逐项核对项目、工作目录、适配器脚本、公开仓库和当前授权。周期任务沿用设定的端点、权限和模型额度。一次性只读核对执行 `check` 和 `verify`。
2. 比较核心、发行登记、既有 ZIP、真实远端分支及最新 Release。已有未提交改动逐文件与上个已审核版本比对；区分待发行的方法、远端独有改动、个人文件和运行缓存。保留来源许可。对有冲突的同一文件先合并语义和复核结果。若远端有更高版本先比对和合入其有效改动，禁止用过期的本地登记覆盖。
3. 有通用内容变化时按 [技能维护](../yl-skill-maintainer/SKILL.md) 完成语义审核、安全扫描、成员版本、目录和变更记录，再运行维护源的 `python -B build.py`、`python -B tools/audit.py --zip` 和 `python -B tools/verify.py`。已发行的同一版本须保持相同字节。无源文件变动时复用已核验的版本，继续检查每个端点，补齐上次缺失项。

## 同步与验收

在本成员目录执行。可用 `--profile` 或 `YL_PROFILE` 定位外置 profile，用 `--config` 指向其他受信任的本机端点配置。

```text
python -B scripts/run.py check
python -B scripts/run.py apply
python -B scripts/run.py verify
```

- 本机宿主由整包安装器更新，映射共享唯一核心。核对目录、清单、链接目标及文件摘要；新 Skill 是否被当前宿主发现按实际加载情况记录。
- 依赖同一适配器的工作台和独立客户端共用知识库、检索设置及 UI 真源。工作台核对源文件、安装插件和实际适配器；客户端核对有效配置、安装资源和离线回退。消费端只在自身有效内容改变时升级，已有会话、设置和用户数据按各应用的更新约定保留。
- GitHub 使用当前远端基线，仅同步已审核发行范围，保留独立维护的展示内容。用普通快进推送，按既有发行惯例提供整包与校验文件。复核分支、标签、Release 和下载字节。客户端发布、插件市场及知识内容上传各需独立授权。
- `check` 列出各端待办。`apply` 按配置顺序运行幂等适配器并立即验收，失败的端点单列，其他独立端可继续。修复失败原因后重跑，已对齐的端点复用原产物。最终给出各端版本、真实验证结果、是否需要重新加载以及失败项。执行回执保存在外置配置旁。

## 安装者配置

配置为 JSON 对象，`endpoints` 是有序列表。每端提供唯一 `name`、绝对 `cwd` 和 `check`、`apply`、`verify` 三组非空命令参数数组。首项为可执行程序，其后逐项传参。各端点相互独立，共同依赖的核心必须在运行前完成审核和构建。适配器负责自身预检、无变化跳过、版本保护、安装中断恢复及核验。`check` 成功表示可完成比对，差异由输出说明；`verify` 只在该端实际对齐后返回零。令牌由宿主凭证服务提供，命令和回执仅使用公开或本机非敏感摘要。
