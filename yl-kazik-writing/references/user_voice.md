# 安装者的语料与声音边界

本模板保留原版提取声音的方法，不携带维护者的笔记、知识库名称、身份、业务经历、个人判断或固定结尾。每次只使用本轮已授权材料。

## 1. 来源优先级

1. 安装者提供的录音原始逐字稿；Get笔记字段为 `data.note.audio.original`。
2. 安装者真实项目材料、当前对话与业务复盘。
3. 安装者既有原创文章。
4. 第三方访谈、课程或转载，只能显式归因。
5. 智能总结只用于定位，不能代替原文。

需要连接器时由安装者自行配置。没有连接器就接收本地导出。远程笔记 ID 始终保持字符串，读取详情后核对返回 ID；不得读取无关私人笔记或将语料拷入 Skill 本体。

## 2. 原话卡

每个关键片段在任务工作区建立一张卡：

| 字段 | 内容 |
|---|---|
| 来源与位置 | 安装者提供的文件、页码、段落或时间戳；远程 ID 不对外发布 |
| 原话 | 完整保留承担判断、比喻、进阶、口头节奏的原句 |
| 作者归属 | 本人 / 第三方 / 转述 / 无法确定 |
| 材料状态 | 原始录音 / 手写笔记 / 既有成稿 / AI 加工 |
| 判断与功能 | 在本篇承担事实、亲历、冲突、转折还是结尾 |
| 时效性 | 当时观点、仍适用的原则、需本轮核验的产品事实 |
| 可改范围 | 删口头重复、纠正确定的转写错误、补主语 |
| 禁止扩写 | 未提供的数字、收入、对话、心理、行动和结果 |

不要只摘一句金句就丢掉整条思路。先记录原话如何从经历推进到判断，再决定篇幅内保留哪些节点。

## 3. 既有成稿

成稿是作者加工后的表达，不能标成录音原话。记录版本、确认状态和本轮允许的复用范围。保留已经确认的主线、结尾和特色比喻，不把某篇的顺序机械套到所有文章。

同一主题有多版时，优先用户明确指定的版本；没有指定时展示具体版本差异再确定母版，不把最新文件日期直接当作最终批准。

## 4. 实践卡

个人经验用于第一人称前，检查：做过什么、用过什么、失败在哪一步、结果由什么证明、作者现在怎样理解。只有产品截图，不能补上注册、付款或成功交付。历史人数、营收、平台表现和工具能力应按本轮来源核验。

每篇只保留服务因果主线的真实实践，不把所有旧案例凑成个人履历。

## 5. 声音校准

用户交回手调稿时，与上一版逐处对照，学习修改的功能。区分稳定表达偏好、单篇词语和明显笔误。

- 优先沿用原话，少过度修饰。
- 允许强判断，以场景、动作或证据承接。
- 不伪造亲测、采访和先见之明。
- 不把第三方课程、访谈说成用户观点。
- 平台转换保留核心判断，调整进入事件的速度和解释密度。
- 技术解释讲清原理与差异即停；普通人能理解后回到真实后果。
- 历史与商业案例融在同一因果线上，不逐项对应，不替读者解释完隐喻。
- 少分节，信息类型或阅读任务改变时再使用小标题。
- 一篇文章只承载一条主要个人判断，不用固定口癖制造“活人感”。

## 6. 结尾与阶段门

不内置个人 CTA。安装者本轮提供或确认固定结尾时逐字使用，可将结尾保存到任务目录的 `CTA.txt`，给校验器追加 `--cta-file CTA.txt`；没有时自然收束，不塞入签名、赠品导流或联系方式。

默认先交正文 Markdown，确认文字后派生图片与 HTML。当前任务已经明确授权整体交付时，沿用该授权。任何外部发布或笔记写入仍须有对应范围的授权；只同步确认正文，去重后写入并回读，不能把未验证的调用称为同步成功。
