# X选题交付约定

## 可调整的Markdown结构

1. 账号、方向依据、固定窗口与时区、检索范围、采集时段。
2. 推荐表：优先级、选题、窗口内新进展、热度快照、推荐形式。
3. 各题详情：作者与链接、发帖时间、内容和关键背景、重要观点、少量有传播价值的原句、中文释义、建议标题、拍摄结构、事实限定、真实截图。
4. 低热度备选、待核线索和必要的旧热点排除说明。
5. 今天优先拍什么，说明理由与制作条件，不预测保证播放量。

规模随材料变化，不固定条数。没有证据的栏目宁可明确空缺。

## 每条证据卡（运行资料放在输出目录之外或其资料子目录，不放进Skill）

| 字段 | 内容 |
|---|---|
| topic_id | 本次报告的稳定编号 |
| author / handle / post_url | 作者身份、账号、永久原帖链接 |
| posted_at_utc / local | 统一时间与用户时区 |
| event_time / new_development | 已知事件时间，以及窗口内到底新在哪里 |
| captured_at | 正文和互动快照采集时刻 |
| metrics | 已确认点赞/转帖/回复/浏览量；未取得用空值 |
| source_type | 官方声明、当事人、新闻、评论或转述 |
| original_quote | 原语种准确摘句，省略或翻译单独标识 |
| screenshot_file / scope | 本地截图位置、局部或完整、被遮挡项 |
| uncertainty / recommendation | 尚待核实事项、为什么适合、制作所需材料 |

页面数据更新时保留快照差异，不偷偷将截图旧值改为正文新值。不必强制生成JSON，表格或工作笔记也可。

## 常见判断

- 原帖早于窗口，今日有高赞回应：围绕今日回应作为新讨论；旧帖仅作背景。
- 报道今日更新，官方发布早于窗口：未取得新讨论就不作为今日新发布。
- 搜索说热门，详情只有个位数赞：热度未获证实，可降为线索或备选。
- 只看到账号一条公开帖：说明方向推断依据少，不能声称看过全部历史。
- 原帖只有访谈标题：具体访谈观点另列逐字稿或视频来源，不能归为推文正文。
- 争议只有一方回应：尽量取得另一方；无法取得则注明，不能凭网友高赞作事实裁决。
- 仅取得文字、截图服务不支持：保存文字证据并找真实截图路线；仍失败就明确缺图。
- 同一作者连发几个相关观点：可以做储备切口，不能伪装成多个独立行业热点。
