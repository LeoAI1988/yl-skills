# 定稿文章转旁白图解视频

从作者已经认可的完整文章出发，做一条听得懂、看得明白的讲解视频。正文、图解和旁白都要服务原来的思想推进；不把文章压成只剩标题和金句的摘要。先按 [个人配置约定](../yl-toolbox/references/profile.md) 读取本次相关的外部配置和作者说明，再核对用户当次要求。

## 确定视频版真源

1. 找到作者确认的最新正文、标题和版本；标明文章固定页脚、平台引导语、编辑注释等非正文部分。现有批准的音色、样片、版式与回改记录直接继承，不重开已定选择。若源稿尚未定稿，先完成用户要求的文字确认；不能把生成视频时的自动改写冒充已批准原文。
2. 以段落或完整论述单元做“原文 → 视频旁白 → 画面 → 字幕”的映射，同时提取封面要传达的中心判断、准确标题、系列名及与正文有关的人物、书名和意象。正文尽量原句朗读；为口语可读性所做的删改、替换和新结尾单列差异，保留原文版本。用户要求“直接读稿”时不擅自概括、打乱推理或增添观点。专供公众号的结尾不默认进入视频；视频号等平台话术仅按用户指定或确认的版本使用。
3. 需要补背景、定义或证据时，先只读检索本人知识与原始材料，回到出处判断作者归属和事实边界。查询可用 [yl-knowledge-search](../yl-knowledge-search/SKILL.md)；新收到的本人原稿及制作中形成、经作者认可的新经验，再按 [yl-knowledge](../yl-knowledge/SKILL.md) 的完整采集、蒸馏、去重、入库、表达与验收链处理。检索和制作不自动授权云端写入或对外发布。

## 旁白先行

1. 根据用户选择的声音和真实可用的许可范围制作一小段中文试听，包含能检验音色、吐字、停顿和语气的连续原文。若用户已确认声音，就以该版本为基准逐段生成；跨段检查年龄感、共鸣、咬字、节奏、响度及尾音是否一致。不得把“风格相近”写成某真人亲自配音，也不以资源池存在为授权证明；记录音色来源与实际使用条件。
2. 用自然句界拆分旁白，优先减少生成次数。先确认服务是否支持所需时长、语速、费用及商用范围；有任务 ID 就续查，结果不明先核对，避免重复提交。生成音频后保留段号和文稿版本，实际听有无漏字、误读、异常停顿与声线突变；ASR 只帮助定位疑点。
3. 从同一批准的原始音频和原始时间坐标重建速度映射，变速保持音高。按用户指定的句界划定局部范围；音轨、字幕、场景时长和可编辑工程使用同一映射，不能在已加速的导出上再叠乘。语速以可懂度和完整字音验收，不用倍速数字代替听感判断。

## 图解分镜与制作

1. 把每一段的“观众要理解什么”写成一句可检验的画面目标，再选示意图、流程演示、具体物件、数据图或必要的实景素材。先画出对象、动作和因果，再加风格；抽象概念须有可辨认的对应物和标签。画面单独看也应能说明关系，动效只用于呈现变化，不为热闹制造无关元素。
2. 先做覆盖开头、核心推理和一处复杂比喻的短样片或关键帧，检查观众能否说出“谁、发生了什么、为什么”。用户已认可的色彩、字号、黑白关系和系列包装保持一致；当次具体配色、横竖屏、片长和倍速来自用户或项目配置，不写成本成员的通用常数。文字与背景、相邻图层必须有足够对比，字幕处于安全区域。
3. 旁白确定后，将段落映射为场景，将句级时间轴映射到字幕。制作可编辑工程，保留分层的旁白、画面、字幕和必要素材来源；导出前从工程预览关键转场、画面含义与结尾。无真人出镜不等于满屏文字：一屏只强调当前论述需要的一层关系，画面随讲解逐步显现。

## 封面贯穿同一制作流程

1. 分镜定下视觉主线时同步写封面简报：观众一眼应看懂的主题、封面原字、主副标题层级、系列标识、核心视觉对象和平台尺寸。封面文案从已确认的视频版与本人表达中提取，不写视频无法兑现的新承诺；书名、历史典故和人物身份逐字回源。
2. 用户明确的视觉方向、已认可的系列样式优先；否则读取个人配置与已有封面，选适合本片内容的构图。科技大字或半透明原帧等既有模式可调用 [封面成员](../yl-short-video-covers/SKILL.md)；稿件有更贴切的独有意象时，可按本简报直接设计，不强迫套固定模板。历史人物或风格化形象只在与正文有关时使用，不暗示其参与、推荐或为视频背书；尚未出版的书稿不画成真实已出版版本。
3. 在视频样片阶段给出封面方向或初稿；标题与画面定稿后输出一张正式封面。检查中文文字是否准确、主题是否与旁白一致、人物和道具是否可辨，原尺寸及平台缩略图下标题、系列名、书名仍能读清；检查前景与背景对比、边缘裁切和平台安全区域。图像生成、排字、脚本尺寸校验各有盲区，须目视看最终文件。用户指出问题时只改封面所需部分，内容确有变化才回改视频。
4. 除用户明确不要封面外，封面与视频、字幕、视频版文稿一起交付；最终只留一张确认采用的封面，记录尺寸、来源与验收边界。归档时交给 [视频归档](../yl-video-archive/SKILL.md) 核验封面和成片的对应关系、文件哈希及自包含审查稿；清理未采用封面、临时缩略图和生成过程文件。

## 反馈、验收和交付

- 对用户点名的问题先记录位置、原要求和修改目标；若用户说“先记录不修改”，只入待办。开始改时沿用最新认可版本，对同类问题检查全片及封面，但只重做必要的音频段、场景、时间轴或封面。明确的局部倍速与视频结尾改动不得波及未点名段落。
- 导出后核对：视频版旁白逐句覆盖、专名和末句、音画与字幕同步、速度分界、文字对比、画面可理解性、分辨率、帧率、音轨和完整解码。逐段自动检查、关键帧观看、整片连续听审及用户确认分别记录；缺哪项就标明未完成，不把 ASR 或技术解码写成听审通过。
- 交付可播放成片、正式封面、视频版文稿、必要字幕、可编辑工程及一份简短的来源/改动/验收记录；用户明确不要封面时记录该选择。定稿归档按 [视频归档](../yl-video-archive/SKILL.md) 处理媒体、封面与最终文稿的知识回流。本成员只制作本地成果，平台发布走独立分支。
