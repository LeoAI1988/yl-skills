# 数据驱动口播文案

用真实作品表现选取值得复用的表达，用本人完整论述构成新稿。成功标准是稿件可直接口播、观点与口气属于作者、写法有可追溯的样本依据、这一篇给观众提供了新内容。传播与成交效果由发布后的同口径数据检验。

## 启动

1. 读取本次要求、个人 profile 和任务相关个人规则。配置定位遵循 `--profile`、环境变量 `YL_PROFILE`、`~/.config/yl-toolbox/profile.json` 的顺序。个人接入文件由 `writing.data_driven.config_file` 指向，缺省尝试 profile 同目录 `writing/data-driven.json`。接入与命令见 [数据接入](references/data.md)。
2. 每次写作运行 `scripts/evidence.py prepare --profile PROFILE`，核对数据时点、账号覆盖、正文关联状态、历史生成记录。读取最新可用源文件及哈希。用户更新本地数据后，本次调用即重新装配。尚未更新的平台数据沿用其真实采集时间。
3. 用户没有提供新材料时采用模式一。有新灵感、新闻、文章、链接、截图或口述时采用模式二。允许直接指定。默认交一篇完整口播稿，长度和节奏从所选母稿及本次用途确定。批量数量由用户指定。
4. 默认以成交目标选母稿，同时检查传播表现。用户点名涨粉、播放、商品、账号或受众时按其目标选。账号未指定且两边均可用时，从适配母稿的账号进入，并在内部记录所选账号。

个人原话、原稿与完整思想推进是写作底板。这里独立完成选稿、装配和审稿，所需方法均在本入口及其引用内。知识查找使用 [知识检索](../yl-knowledge-search/SKILL.md)，命中后回读原文及前后文。写作引用范围包括完整原文、知识原子、表达资产和已授权内化观点。检索内容保留作者归属和时点。

## 从数据选择母稿

读取 [样本分析与两种模式](references/method.md)。先看成交证据对应的具体内容和商品，再看开头、承诺兑现过程、论述链及行动入口。每种写法保留支撑样本和可比的弱表现样本，标明各自的全文关联证据。

- 作品主键使用账号与发布 ID。原稿版本、重发作品、剪辑版本分别留关联。标题近似、同封面和日期接近作为候选线索，须回读正文核对后才能用于结构分析。
- 最新播放快照与历史成交截图分别保留时间窗口。账号级订单帮助判断商品需求和客单价，视频级成交证据帮助选择母稿。缺失成交数据记为未知。
- 传播排名采用完播率百分位 × 50% ＋ 单作品涨粉原始数量 × 30% ＋ 三秒百分位 × 20%。沿用集群 `yl-media/scripts/ranking.py` 的 `3.0-raw-follows` 显式规则。分数可超过 100。账号内按可比发布周期、时长和成熟度核对，说明分母与组别。缺指标的作品仍可阅读全文和已知成交证据。
- 稳定 ID、确认过的发布记录或用户确认可直接作为对应依据。已有人工核对结论具有可追溯依据时继续使用。发现具体冲突才复核该条。脚本输出的候选状态由当前 Agent 根据证据升级，记录在个人关联文件中。
- 商品价格、课程权益、工具功能和“限时免费”等时效信息按本次可用事实核对。历史强判断用于理解作者论证，涉及当下事实的句子按当前材料处理。

初次调用建立个人 `patterns.md`。记录主论点、观众欲望或阻碍、首句作用、后续兑现、真实证明、购买理由、适用题材、支持与反例路径、解释局限、最近数据哈希。完整读过几篇就记录几篇。更新时补充、修正或淘汰被新数据削弱的判断。原句与 Agent 的效果解释分别标明。

## 模式一 · 成交母稿续写

用户无需另交素材。先从可用成交稿中确定一个主要购买动机与一条完整论述链，再检索能推进这条论述的本人资产。

1. 选一个主母稿。写清本篇保留的有效逻辑与新增内容。按需加入其他本人稿件的完整语义段，保留前提、转折、代词指向和思想来路。
2. 将开头、论证、例子和商品承接接成同一条因果或行动链。主母稿的购买动机贯穿到结尾。原句适合就沿用，只为本篇语境修正衔接、赘语和过期事实。
3. 新意来自新的问题、场景、解释、真实案例、观点关系或操作任务。只换词、换标题、调整段落顺序的稿件回炉处理。保留标志表达，同时给观众增加实质信息。
4. 连续生成先查历史。优先选择近期少用、证据可用且与当前目标相合的母稿组合。随机请求只在这些合格组合中选择，并记录 seed 或本次选择理由。样本不足时深挖本人完整原文，扩大场景和论述，诚实记录仍待观察的部分。

## 模式二 · 新素材融合

先写出新素材提供了什么信息、它与观众有什么关系，再选能解释它的本人框架与历史有效结构。

- 灵感或口述保留用户这次新表达的推进。知识库材料补足论证缺口。
- 新闻读取原始报道或发布方说明，保存 URL、日期与可核实事实。明确观点与事实，变化中的消息沿用其实际确定程度。
- 外部文章拆解选题、开头与信息递进，保留引用归属。作者的经历、客户故事、成果数字属于原作者。新稿的判断、经历和比喻从本人资产取得。
- 新材料必须改变本篇的问题或论证，至少贡献一个可定位的实质段落。抽掉新闻名、公司名后仍可套回旧稿的版本，继续重写。
- 商品与新素材通过具体问题和解决方式相连。若当前资料支持观点表达，就先把观点讲完整，转化入口采用与内容相符的动作。

## 写稿与复核

写前保存一张简短的内部选稿记录，至少含模式、目标、账号、主母稿、保留逻辑、新增信息、来源路径。拼装时按完整意思使用本人段落，记录每一段来自哪里、哪些句子由 Agent 新写。口头反问、有效重复、长短句、比喻和有来路的野心都属于作者声音。

完成后按 [表达与来源复核](references/voice.md) 逐段检查，再运行 `novelty` 查看与母稿和近期新稿的重合处。工具给出重复线索，当前 Agent 判断是否只是表面改写。事实核对与数据分析写入内部选稿记录，正文只保留观众理解和行动需要的信息。

交稿前必须能回答以下问题。

- 首句让哪类观众因为什么继续看，正文是否兑现了它。
- 段落之间的理由是否接得上，改写是否偷换了作者的判断、范围或经历。
- 新稿究竟增加了什么，和近期同题稿相比观众会得到什么。
- 采用的商品、权益和行动入口是否有当前依据。
- 哪些句子已有本人的原话，哪些是新增连接，是否能删除空泛退让和解释前缀。

## 交付与回流

默认交付 Markdown 标题和完整口播正文。正文后用简短说明交代用了哪些母稿、这篇新增了什么及重要待核事实。用户要求“只要正文”时，证据保存在本地内部文件。

个人输出目录每篇保存 `正文.md` 与 `依据.json`。依据记录 `mode`、`account`、`objective`、`parent_sources`、`retained_logic`、`new_information`、`source_spans`、`product`、`cta`、`snapshot_fingerprint`。段落来源包含路径、哈希、原段位置、采用原句与新写连接。生成稿保持草稿身份。

使用 `register` 登记稿件，内容哈希去重并保留版本与生成选择。发布后通过 `feedback` 绑定账号、发布 ID、发布稿哈希和核实依据。后续 prepare 按该绑定找新表现，显示原假设、已知播放和成交证据。新数据更新模式库时，先比较观察窗口、商品、价格、受众、视频画面、发布时间与投流情况，再修改判断。单条成败作为新证据，长期规律保留跨作品支持和反例。

后续验证记录同账号可比作品的达标比例、播放中位数、完播、涨粉和有归因证据的成交表现。每轮保留实际样本量、观察窗及更新日期。文案评分仅用于编辑选择，发布结果用于检验成效。
