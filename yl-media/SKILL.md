# 自媒体板块

先读取同级 `yl-toolbox/references/profile.md` 及本次相关个人说明，恢复已有材料、目标和授权。自媒体是对外统一入口，写作与视频属于内部子板块；不要求用户先记住子入口名称。

## 按任务分流

| 任务 | 内部调用 |
|---|---|
| 写文章、口述转公众号、改稿、指定写作风格 | `yl-writing`，再按已指定风格或实际稿件需要调用成员 |
| 课程及演示长视频、长视频切片、真人口播、横屏访谈、剪辑、封面或成片母带归档 | `yl-video`，再进入相应剪辑、封面或归档成员 |
| 视频号采集、复盘或相关小店分析 | `yl-channels-analytics` |
| 视频号运营工作台、发布记录、数据跟踪大屏、批量定时发稿、挂商品、改已定时未发作品 | `yl-channels-publisher` |
| 抖音发布、定时排期、多文件夹选片与本地发布工作台 | `yl-douyin-publisher` |
| 小红书视频笔记选片、排期、字段校验与逐篇发布准备 | `yl-xiaohongshu-publisher`；用户在平台完成最终提交 |
| 公众号采集与复盘 | `yl-official-account-analytics` |
| X近期热点、短视频选题、原帖截图 | `yl-x-topic-research` |
| YouTube访谈/播客详细总结、观点与原话金句 | `yl-youtube-deep-summary` |
| 跨平台复盘 | 按下方采集与复盘流程执行 |

完整读取对应子入口或成员；只加载当前任务所需分支。写作和视频调用链为 `yl-toolbox → yl-media → yl-writing/yl-video → 具体成员`。直接点名写作或视频成员时，也先在这里确认所属分支，再保留用户选择进入执行；同一任务已分流则不重复回跳、不递归调用本入口。

本人原稿与表达资产优先。未明确要求写作风格时，不能仅因进入自媒体入口就自动启用通用风格；遵守个人配置和当前用户限制。已有的素材、模式和授权跨分支复用，不重复询问。只要写作或剪辑时，不启动后台采集、要求平台登录或补做复盘；跨环节任务才依赖顺序串联。

PPT 属于办公板块，交由 `yl-ppt`，不并入自媒体。平台发布、云端写入和定时运行仍须有相应授权，路由不扩权。发布是独立分支：抖音进入 `yl-douyin-publisher`，视频号进入 `yl-channels-publisher`，明确指定的小红书发布准备进入 `yl-xiaohongshu-publisher` 并保留人工最终提交；不因为采集复盘分支已登录就顺带发表。仅要求本地工作台或排期表时不提交；平台未说明且上下文不能确定时先澄清，不能默认为视频号。

X选题与YouTube总结属于外部资料研究，直接交给对应成员；不启动写作风格、账号后台复盘或本人知识蒸馏。外部作者观点保留归属，研究报告默认本地交付。本文下方“采集与复盘”指视频号/公众号后台，不能用其取数规则替代X公开研究或YouTube转录核验。

## 采集与复盘

仅采集/复盘分支恢复账号、窗口与平台范围。全平台默认视频号＋公众号，点名单平台只处理该平台；不自动访问小红书。不擅自创建定时采集或发布内容。

- 视频号→`yl-channels-analytics`，小店成交仅在相关任务中纳入。
- 公众号→`yl-official-account-analytics`。
- 跨平台→分别完成同一 collection_id 和窗口的采集，再按 [交接与复盘](references/handoff.md) 比较共同 work_id。
- 排名统一读 [评分方法](references/ranking.md)，只用 `scripts/ranking.py`，不各自复制算法。

采集与复盘属于一次工作；新增本人原稿/逐字稿自动交给 `yl-knowledge` 完整蒸馏，指标和结论交给 `yl-knowledge-review-sync`。Agent 写的分析结论不是本人原话，不自动提炼成本人观点。没有新正文只更新数据，不重复蒸馏。

完整报告必须覆盖请求的日期、页码、每条适用作品的详情和数据层。只读列表不算完成。详情不可达、登录失效或未翻页标 partial，不伪装成平台不提供。

## 发布

发布是独立分支，不属于采集与复盘。用户明确要求发布、给出发布时刻表，或要求修正已定时未发表的作品时，按平台选择成员。抖音使用 `yl-douyin-publisher`，由其处理实际画面排重、已有封面、标签、合集、定时与工作台；同稿不同次录制可以分别发布。小红书使用 `yl-xiaohongshu-publisher`，按 20 字标题、1000 字正文和最多 10 个话题预检，逐篇准备、由用户最终提交，不提供规避风控或无人值守代发。视频号使用 `yl-channels-publisher`，以下是视频号分支的补充规则：

- 只发布已完成且已归档的成片；未成片的条目不进入发布流程。
- **发布前先确认成片目录里有哪些做好的封面**。封面 PNG 就在成片同目录，不用它就是漏做。用户没提封面不等于不要封面。
- **位置一律不显示**。平台默认带城市名，不清掉会随作品发出。用户明确要求带定位时才保留。
- 平台发布、云端写入和定时运行须有相应授权，路由到发布分支不自动获得授权；无授权时只说明需要什么，不代替用户点发表。
- 编辑与归档在 `yl-video` 侧完成，工作台可呈现 `yl-channels-analytics` 的后续复盘；发布与只读采集分别由用户发起，不因入口整合而自动执行。

## 开工检查清单（采集前必过，2026-09-26 补）

历次失败的共同原因是**开工前没确认工具链，中途换工具重试**。按顺序过一遍再动手：

1. **确认浏览器能力**：使用当前宿主已经授权、可调用的浏览器，先读其规范。工具偏好和宿主配置位置从外部个人配置读取；不替用户启用被禁用的工具，不绕过浏览器限制。
2. **验证会话持续性**：跨步骤保留登录态；不能仅凭工具名断言 CLI 必然丢会话或 MCP 必然可用。连接失败时采用允许的官方导出或离线输入，明确未重采的范围。
3. **登录与回调**：需要扫码时展示真实登录页，等待手机确认和后台成功状态；oauth 回调期间不导航或刷新。登录完成后按页面正常导航，只在工具明确支持时使用观察到的同源只读接口。
4. **接力口径先算清**：读上次采集时刻与最新一条发布时间，明确“新增窗口”，历史条目只刷新累计值不重抓。把这两个值写进报告。
5. **取数遵守宿主能力**：优先官方导出和可见页面。仅在当前工具明确允许时观察网络及调用已观察到的同源只读接口；不以本 Skill 的代码例子替代宿主授权，不凭记忆构造参数。
6. **正文/逐字稿按平台特性取**：不同 `item_show_type` / `share_type` 的正文位置不同，兜底选择器有顺序，**不要退到 `body`**（会拿到整页脚本）。抓完按长度抽查，异常大的标 partial 重取。
7. **收尾三件套**：跑结构校验 → 与开工前基线对比队列（新增发现的缺口如实登记，不为缩短队列而隐瞒）→ 在报告里如实列出未完成项与原因。
