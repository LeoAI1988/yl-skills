# 自媒体板块

先读取同级 `yl-toolbox/references/profile.md`，从任务恢复账号、窗口、平台范围。全平台默认视频号＋公众号，点名单平台只处理该平台；不自动访问小红书。不要创建定时采集或发布内容。

- 视频号→`yl-channels-analytics`，小店成交仅在相关任务中纳入。
- 公众号→`yl-official-account-analytics`。
- 跨平台→分别完成同一 collection_id 和窗口的采集，再按 [交接与复盘](references/handoff.md) 比较共同 work_id。
- 排名统一读 [评分方法](references/ranking.md)，只用 `scripts/ranking.py`，不各自复制算法。

采集与复盘属于一次工作；新增本人原稿/逐字稿自动交给 `yl-knowledge` 完整蒸馏，指标和结论交给 `yl-knowledge-review-sync`。Agent 写的分析结论不是本人原话，不自动提炼成本人观点。没有新正文只更新数据，不重复蒸馏。

完整报告必须覆盖请求的日期、页码、每条适用作品的详情和数据层。只读列表不算完成。详情不可达、登录失效或未翻页标 partial，不伪装成平台不提供。

## 开工检查清单（采集前必过，2026-09-26 补）

历次失败的共同原因是**开工前没确认工具链，中途换工具重试**。按顺序过一遍再动手：

1. **确认浏览器能力**：使用当前宿主已经授权、可调用的浏览器，先读其规范。工具偏好和宿主配置位置从外部个人配置读取；不替用户启用被禁用的工具，不绕过浏览器限制。
2. **验证会话持续性**：跨步骤保留登录态；不能仅凭工具名断言 CLI 必然丢会话或 MCP 必然可用。连接失败时采用允许的官方导出或离线输入，明确未重采的范围。
3. **登录与回调**：需要扫码时展示真实登录页，等待手机确认和后台成功状态；oauth 回调期间不导航或刷新。登录完成后按页面正常导航，只在工具明确支持时使用观察到的同源只读接口。
4. **接力口径先算清**：读上次采集时刻与最新一条发布时间，明确“新增窗口”，历史条目只刷新累计值不重抓。把这两个值写进报告。
5. **取数遵守宿主能力**：优先官方导出和可见页面。仅在当前工具明确允许时观察网络及调用已观察到的同源只读接口；不以本 Skill 的代码例子替代宿主授权，不凭记忆构造参数。
6. **正文/逐字稿按平台特性取**：不同 `item_show_type` / `share_type` 的正文位置不同，兜底选择器有顺序，**不要退到 `body`**（会拿到整页脚本）。抓完按长度抽查，异常大的标 partial 重取。
7. **收尾三件套**：跑结构校验 → 与开工前基线对比队列（新增发现的缺口如实登记，不为缩短队列而隐瞒）→ 在报告里如实列出未完成项与原因。
