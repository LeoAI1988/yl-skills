# 采集、分析与知识库交接

直接调用采集成员时也先读取 [个人配置约定](../../yl-toolbox/references/profile.md) 和已配置的个人说明，确认账号范围、工作目录和可用工具；不从旧作者案例猜个人设置。

## 稳定身份与证据

asset_id 是一个正文/平台版本；work_id 是共同内容核心；publication_id 是一次真实发布；capture_id 是一次观察；collection_id 是本次采集。标题不是主键，重发是新发布，跨平台关系要读正文核对。

原始快照追加保存，规范化表可重建。记录实际采集时间、发布时间、平台、账号范围、窗口、成熟度、原始字段、单位、证据路径。未知留空，真实0保留。比例原始台账0至1，排名输入百分制须明确转换。累计快照不求和，同一身份同时间冲突保留，不默默覆盖。

分开维护：发布、作品表现、留存、账号窗口、受众分布、业务转化、采集覆盖。账号受众不能代替单篇受众；阅读不等于播放；推荐、转发、收藏不是跨平台同义指标。

## 完整采集门槛

覆盖表字段：collection_id、platform、published_from/to、layer、expected_count、checked_count、available_count、status、evidence_path、reason。

共同层：账号总量、请求的增长窗口、账号受众、发布列表、逐篇详情、内容来源分类。视频补留存、流量来源、相关业务转化；公众号补通知/分发、文章消费。按任务适用范围列 required_layers，不为未请求的业务范围扩大采集。

完整指应查条目均实际检查，所需日期两端和分页覆盖。到达页面但平台没给指标可记 not_available；未打开或访问失败只能 partial。直播切片/原创/未知分开，未知不进正式原创比较。禁止把未提供正文当成已蒸馏。

## 诊断与阶段复盘

按分发→点击/播放→开头→中段→完播→关注→业务行动逐级判断。没有分母不造率，没有留存不猜哪秒掉人。逐句/段/时间点对照标题、封面、原文和 CTA。结论分观察、假设、实验，并列样本数、成熟度、窗口、缺失、反例。

跨平台只比较共享 work_id 的版本，区分先后、标题、开头、长度、结构、受众和成交路径。单个爆款不是规律。周/月复盘同时看题材构成、发布频率、中位数、重复胜率、之前建议是否实际测试。经验进入外部分析/方法证据时保留样本、反例、时点、置信度，不当本人原话。

业务区分内容获客来源与实际支付渠道。平台可核、本人确认、时间相关分别列示，全渠道总计不与平台/私域分项再相加。退款、重复订单、时间口径先核；销售单价×点击不能估算为收入。

## 本地交接

新增本人正文的路径、source_id、哈希、work_id、publication_id、归属/转写状态交给知识总入口；读取全部正文再蒸馏。元数据同步不能完成正文环节。数据快照和复盘结果交 `yl-knowledge-review-sync`，自动更新选题与作品历史，但不把 Agent 推理当本人知识原子。

已有库可用个人配置的 `platform_validate` 和 `platform_report` 本地引擎维护原表，不迁走历史证据；新库按上面分表规范建立数据。原始语料、账号和媒体不写入 Skill 核心。
