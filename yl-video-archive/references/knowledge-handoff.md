# 最终文稿随视频归档进入本地知识库

归档指令表示用户认可本批最终作品。归档完成包含媒体落位和最终文稿的完整知识处理；只读审计不触发写入，明确仅归档媒体的例外需记录。不推导云端写入、发布或定时任务授权。

1. **先绑定当前版本。** 根据用户确认、交付记录与实际视频确定成片，记录稳定来源 ID、视频路径及 SHA-256、最终文字来源章节/行号、正文 SHA-256。多轮审查稿先找与当前视频绑定的字幕或完整顺读稿，不能机械选最后一个标题或最高版本号。只有旧方案时从实际成片恢复文字并保留未核疑点，不把旧提案叫定稿。
2. **登记全部条目。** 清单以本批成片逐条枚举，不能只扫描已有入库记录。原始长课、重拍、混剪、平台发布版与最终成片分别建立来源/版本关系；同一正文的多个媒体包装共用文字实体，语义相似的稿件检查增删及新表达。

   **先对照已同步的发布稿。** 对最终正文与已有平台全文、已审转写逐篇比对；先排除标点、空白、全半角等格式差异，再人工检查近似稿的词句和段落差异。完全相同正文复用既有正式实体，只增加来源别名、媒体及独立发布记录。纯转写错字或空口语词差别可作为同稿异文保留差异证据，不另占一份正式正文；实际措辞、段落或论证变化保留版本并说明差异。不能凭标题、相似分数或发布时间直接合并。原始平台快照继续留证，默认检索与阅读指向唯一正文。知识原子先查既有对象，同一原子补来源，不因渠道或视频版本另建卡。回执记录跨来源比对范围、决定、差异证据及唯一正文路径。
3. **交给知识总入口。** 读取 `yl-knowledge` 及它要求的成员，沿用既有库、稳定 ID、台账和正文格式。完整阅读、归属与版本判断、先查旧原子再提炼、表达变体、作品与思想关系、全文和本地语义索引、完成验收一并完成。课程切片复用课程真源；AI剧情中作者提供的句子、改编连接句和生成角色提问分别标注。
4. **保留最终文字主源。** 已有正式正文则引用；新最终稿进入配置指定的作品位置。审查稿作为版本证据留存，不能把历史删除段、机器 JSON、字幕时间数字或 Agent 的剪辑说明摄入本人原句。原音未听、文本已审、用户确认作品分别记录，不能互相替代。
5. **逐条闭环。** 在知识库系统资料中保存来源版本的语义回执（覆盖、归属、去重理由、原子/表达/关系产物及检索验收）；成果审查稿引用对应来源与回执。已处理哈希不变则复用原结果；新哈希重新进入待处理，旧回执保留。中断后从未完成项续接，不重复建卡。
6. **最后清理。** 最终文字、回源定位和回执不依赖将删除的工程；未完成时保护其必要依赖。媒体归档、知识完成、人工听审与清理分别报告。

## 可计算的完成检查

`verify_knowledge_handoff.py` 只检查逐条绑定、产物存在和版本一致性，不执行或证明语义蒸馏。清单格式：

```json
{
  "items": [{
    "source_id": "stable-source-id",
    "video_path": "/absolute/final.mp4",
    "video_sha256": "sha256",
    "text_path": "/absolute/canonical.md",
    "text_sha256": "sha256",
    "receipt_path": "/absolute/receipt.json"
  }]
}
```

回执可为单个对象或 `sources` 数组；对应项包含同一 `source_id`、`source_sha256`、`full_source_read: true`、`ownership`、`dedup_reason`、`expression_reason`、`organization_reason`、`disposition`（`distilled`、`merged_into_existing`、`no_new_atoms`、`external_reference` 或 `excluded`）、`artifacts`（实际产物绝对路径数组）、`retrieval_verified: true`、`unresolved: []`。无需新原子也应给出具体依据并完成全文检索。明确外部/排除仍保留处置与可回读记录；不能仅填完成字段替代真实工作。媒体专档例外使用 `knowledge_exception` 记录用户当次明确指令，并保留媒体绑定。

另须填写 `cross_source_dedup_checked: true` 与 `cross_source_dedup_receipt`（实际比对记录的绝对路径）；无匹配或没有已同步来源也要记清实际检索范围，不能省略这一步。
